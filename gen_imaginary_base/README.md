# Gen Imaginary Base — 虚数进制分形

二次整数环上的**进制展开**，画成自仿射点集。

一个**数系**由底数 `b` 与数字集 `D` 决定，整数 `n` 写成 `n = Σ dₖ·bᵏ`。取遍 `|D|^N` 个
地址（`|D|` 为基的 `N` 位混合进制编号），把每个整数画在它自己的位置上，就得到那片
自相似的点集 —— 底数是负的、纯虚的、带 `ω` 的，形状都跟着变。

移植自 TheGrayCuber 的网页项目 **imaginary_bases**（见 [来源与许可](#来源与许可)），
插件形态、HUD 交互与代码分层沿用了 `fractal_family` —— 那是与工作空间目录并列的
**独立仓库**（`C:\git\fractal_family`，自己一套 git 与商店发布流程），不是本仓库的子目录(只有 junction 链接)。

## 与 Fractal Family 的关系

两者共用同一对环，但算的不是同一种对象 —— 这对关系值得先说清楚，否则很容易误以为
是把同一个算法换了个皮：

| | Fractal Family | Gen Imaginary Base（本插件） |
|---|---|---|
| 环 | Z[i]、Z[ω]，ω² = −1 或 −1−ω | 同（切换 `i` / `ω` 就是它的 G / E） |
| 参数 | 基因：段 eᵢ（复整数）+ R/M 标记 | 底数 b + 数字集 D |
| 规则 | 每段替换成整条上一级曲线的缩放副本 | $n = \sum d_k \cdot b^k$，对 $\lvert D \rvert^N$ 个整数求值 |
| 收缩比 | $\lvert e_i \rvert / \lvert T \rvert$，逐段不同（可变比） | $1 / \lvert b \rvert$，全体统一（自仿射） |
| 产物 | 折线**曲线** | 自仿射**瓦片的点集** |
| 编辑 | 拖格点节点、切 R/M、滚轮改等级 | 拖数字与底数、增减数字、滚轮改位数 |

所以"孪生"成立在：**同一对环、同一套格点吸附、同一个「有限地址集 → 点」的机制**；
不成立在公式上：它的每段是"终点"，这里的每个数字是"加数"；地址权重一边是连乘
`∏(eᵢ/T)`，一边是幂 `bᵏ`。经典例子里这两者正好是"瓦片"与"瓦片边界"的关系
（`base −1+i` 配数字 `{0,1}` 是 twindragon，而它的边界就是龙形曲线）。

## 数学

**环。** `I` 域 ω = i（ω² = −1，高斯整数，方点阵）；`W` 域 $ω = ζ = e^{2πi/3}$
（ω² = −1−ω，艾森斯坦整数，三角点阵）。乘法靠把二次项折回去：

```text
(a + bω)(c + dω) = ac + (ad + bc)ω + bd·ω²
ω² = d0 + d1·ω   →   (ac + d0·bd,  ad + bc + d1·bd)
```

**有效数系判据。** 参考项目允许随便拖数字，但从不判断"这个数系是否有意义"。这里判了，
两条都是可判定的：

1. `|D| = N(b)`（位数等于底数的范数）；
2. `D` 在 `Z[ω]/(b)` 里两两不同余，即 `D` 是模 `b` 的**完全剩余系**。

满足这两条，地址 → 整数的映射就是双射（Knuth 对高斯整数，Kátai–Kovács 对一般二次环），
面板与 HUD 会显示"有效数系"；不满足则给出具体原因（位数不对 / 两个数字同余）。

**为什么点数是指数。** `|D|^N`：4 个数字 16 位就是 43 亿。所以位数永远先被**点数预算**
夹一次（`ring.max_places`），改数字集时也会自动往下夹 —— 否则把 4 个数字换成 40 个数字
会瞬间炸掉视口。

**点集是预计算成表的。** 每个数字乘 `bᵏ` 的结果只有 `N × |D|` 项，与点数无关；算点集时
用 numpy 的 fancy indexing 一次性求和，循环只发生在小表上。见 `ring.point_set`。

## 界面

侧栏 `View3D > Sidebar > Fractal`，自上而下：**Editing（HUD / Preview 两个开关并排）**
→ 数系（预设 / 域 / 底数 / 有效性指示灯）→ 数字集 → 位数与上色 → 输出（形态 / 生成 /
删除 / 取景 / 预算 / 半径或格缝）→ 动画（生成 / 每相位帧数 / 每级停留）→ 状态。

视口预览（`POST_VIEW` 立即模式，不建任何数据块）**把每个整数铺成一整格**：Gaussian 铺
方格、Eisenstein 铺六边形（形状与缝隙都取 `ring.cell_polygon(domain, cell_gap)`，也就是
「实心格」输出用的那一套），外面再套一圈**取景框**，框的形状跟着环走 —— `Z[i]` 方形、
`Z[ω]` 六边形（六边形就是三角格的胞腔形状）。HUD 的地图区同样按这个形状画。

> 早先版本画的是屏幕像素大小的 `POINTS`，远远看过去只是一层灰；铺满格子之后形状才读得出来，
> 而且格子跟着几何缩放，不是固定像素。

**HUD**（模态）在视口里直接改数系：

| 操作 | 效果 |
|---|---|
| 拖数字圆点 / 底数菱形 | 改数字或底数，总是吸附到整数格点（底数不能为 0） |
| 滚轮 | 改位数 |
| Shift + 滚轮 | 缩放地图 |
| `F` / `Shift+F` | 取景：只框数字 / 连点集一起框（也可点 `Fit` 在两个档之间切） |
| `Tab` | 切换环（i ↔ ω） |
| `A` / `X` | 加一个数字 / 删最后一个 |
| `Esc` / 右键 / `×` | 关闭 HUD（指针在面板上时） |

**HUD 不抢视口。** 只有指针落在面板矩形里（或正在拖标记）时才接管事件，其余一律
`PASS_THROUGH` —— 面板开着也能照常转视角、选中物体、用别的高频操作。早期版本把所有事件
都吃掉，一开 HUD 视口就锁死。正在拖动时例外：不管指针跑到哪都归 HUD，否则松手事件会被
别处吃掉、标记卡在拖拽状态。

面板与 HUD 改的是同一套参数，两边实时同步。

**两个取景档是有必要的**：点数一多，点集会跨几十个格距，而数字都挤在原点附近两格内 ——
按点集取景，数字就变成一团墨点；按数字取景，才拖得动。所以默认框数字，`Shift+F` 看整体。

## 输出

一个 GP 对象 `Imaginary Base`。每个整数对应**一条笔划**，形态在「输出」里二选一：

| 输出形态 | 一个整数是 | 笔划 | 视觉 |
|---|---|---|---|
| `圆点`（默认） | 一个单顶点笔划 | 1 点 | 半径 = 「点半径」的圆点 |
| `实心格` | 一块闭合的瓦片 | 4 点（`I` 域方格）/ 6 点（`W` 域正六边形） | **只有填充、没有描边**；格子铺满平面 |

**为什么圆点只能一点一笔。** GP 的笔划是折线：把一万个点塞进一条笔划，GP 会老老实实
把它们连成一万段线，画出来是一张蛛网。要把点画成点，只能一点一笔 —— 实测 Blender 5.2
里单顶点笔划确实渲染成圆点（半径由 `radius` 决定）。

**实心格的形状就是点阵的胞腔**（`ring.cell_polygon`）：`Z[i]` 上是边长 1 的**正方形**，
`Z[ω]` 上是外接半径 `1/√3` 的**正六边形**（尖顶朝上，平边到中心恰好 0.5）。所以按格点
平移铺开来能严密填满平面，不需要布尔也不需要合并。形状跟着**当前域**走，不另设开关。

「格缝」让每格向内缩进一点：缩成 `0` 相邻格共边、连成一整片实色；默认 `0.06`（边长
0.94）与视口预览一直用的比例一致，于是预览里看到的格子与生成出来的完全重合。

**填充是几何，不是材质开关。** 四条**逐笔划**（`CURVE` 域）属性就够了：`fill_id` 非 0
才填充、`fill_color` 给填充色、`hide_stroke` 关掉描边、`cyclic` 闭合。逐笔划的粒度意味着
一条笔划一块瓦片，相邻格不会被合并成一个连通区域；也就**不需要材质** —— `layer.use_lights
= False` 之后填充色所见即所得（这条结论与 `gen_zellij` 一致，本插件复核过）。

`POINT` 域属性（两种形态都有）：

| 属性 | 类型 | 含义 |
|---|---|---|
| `position` | float3 | 点坐标（GP 自带） |
| `radius` | float | 圆点形态 = 「点半径」；实心格形态 = 发丝细（描边已关，见下） |
| `vertex_color` | color | 线色（**线性**存，与色板逐位一致，实测采样误差 0） |
| `index` | int | 这个点是哪一号整数（地址本身） |
| `digit_slot` | int | 它用哪一号颜色（= 最高位 / 指定位的编号） |

实心格额外四条 `CURVE` 域属性：

| 属性 | 类型 | 含义 |
|---|---|---|
| `fill_id` | int | 逐笔划非 0 → 这一格要填充（值就是格子的序号） |
| `fill_color` | color | 填充色，与同一格的 `vertex_color` 同色 |
| `hide_stroke` | bool | 恒 `True`：只填不描 |
| `cyclic` | bool | 恒 `True`：闭合，填充才有边界 |

`index` / `digit_slot` 是**数据接口**：几何算完就写死在那里，之后按位筛选、做动画、换几何
节点驱动都不用重算点集。实心格形态下它们按顶点重复 —— 一格的每个角点都记着"我属于哪一号
整数"，所以按属性筛选一格仍然是整格。

实心格形态的笔划半径写的是 `0.0015` 而不是「点半径」：描边已经被 `hide_stroke` 关掉，
这个值只是为了让数据自洽 —— 万一有人把 `hide_stroke` 改成 `False`，得到的是一条发丝细的
轮廓线，而不是糊掉形状的粗边。

**点半径默认 0.42**（格距为 1）：参考项目画的其实是"每个整数一个格子"（边长约 0.9），
半径取到 0.42 相邻点才挨在一起连成面；调小就退化成一层散点。想要"每个整数一个格子"的
原味，直接用实心格形态。

## 上色

| 档 | 规则 |
|---|---|
| `聚合`（默认） | 最高位定色，低位身份逐层混进来；`shade = 0.8 + 0.2·shade(去掉最高位)`，越靠表层越淡 |
| `最高位` | 最高位一位一色，平的 |
| `第 k 位` | 指定某一位上色，用来看"哪一层在哪个位置" |

色板前 8 个数字手挑（0 号刻意压暗），之后按黄金角散开色相，所以几十个数字也不会撞色。

## 动画：贴零 · 生育

面板「输出」下面是**动画**区块 —— 一按就把参考视频 4:18 之后那段讲解写成一个逐帧的 GP
对象 `Imaginary Base Steps`（与静态对象分开，两个可以同时存在、各自开关）。

视频把进位制的构造拆成两个动作，反复做就长出整片点集：

| 动作 | 数学 | 几何 |
|---|---|---|
| **贴零**（slap a zero） | `n → n·b` | 乘底数 = **旋转 `arg(b)` + 缩放 `|b|`**，整片形状转着长大，还是一个缩放副本 |
| **生育**（give birth） | `n → n + d`，`d ∈ D` | 每个数字一份拷贝，`|D|` 份；上一级留下的空隙正是被这一步填掉的 |

于是 `places` 位的点集满足递推 `S₁ = D`、`S_{k+1} = b·S_k + D`。收缩比 `|b|` 与分支数 `|D|`
刚好配平（`|D| = N(b) = |b|²`），所以每裂一次轮廓不变、只是被切得更碎 —— 这就是"为什么
自仿射基会造出分形"。

**为什么分成两步**：一步到位的话点会从父辈跳到子辈的落点，「整体转着长大」和「按数字裂开」
糊在一起，就看不出来了。所以每到一级都是先"转"`每相位帧数` 帧、再"裂"同样多的帧，然后
停 `每级停留` 帧让人看清长好的形状。

**转动是真的转动**：环元素嵌进复平面后乘以 `b^t` 就是旋转 `t·arg(b)`、缩放 `|b|^t`，所以
缩放阶段逐帧取 `b^t`（`t` 从 0 到 1），点走的是一条对数螺线 —— 不是把两端坐标线性插值
（那样点会走弦，看起来是"穿过去"而不是"转过去"）。0 点始终在集合里，所以转动就绕着原点。

**上色**跟着第 1 级的数字走（= 最高位，静态输出里的 `最高位` 档）：生育那一步看起来是
"一团裂成 `|D|` 团、每团守着自己的颜色"，一路跟下去就能看出**整片 = `|D|` 个缩放副本**。
最后一帧的位置、地址、颜色与静态输出选 `最高位` 时**逐点一致**。

> 按"刚贴上去的那一位"上色也说得通（那正是视频里 "each color is now its own triangle" 的
> 画面），但最低位在方格点阵上就是奇偶，最后一帧会变成一张棋盘格，反而把龙形糊掉。

**帧与预算**：一帧 = 一层 `frames` 里的一张 drawing，所以**每帧点数可以不同**（生育那一步
正好翻 `|D|` 倍）。整段的笔划总数是各帧点数之和，超过 `STROKE_LIMIT`（8 万）就自动少做一级，
面板上直接写着"笔划预算：7 级只做 6 级"。生成后场景帧范围被设成整段动画，并跳到第 1 帧。

**动画区块里那个 `PRESET` 图标按钮**一键载入视频里的例子（底数 `−1+i`、数字 `0` 与 `1`、
6 位、上色切到 `最高位`），省得手工拖那两个数字。

## 与参考实现的取舍

| 参考项目 | 这里 | 为什么 |
|---|---|---|
| 每个整数画一个格子（方块 / 六边形） | 可选：`实心格`（`fill_id` + `hide_stroke`）；默认仍是 `圆点` | 实心格是最贴近参考品的形态；圆点笔划数更省、也更好被几何节点按点驱动，所以留作默认 |
| 点数上限约 6000 | 512 – 120000，默认 8000 | GP 一个点一笔，预算就是笔划数；两万笔视口仍可拖动 |
| 上色按极角分配 | 手挑 + 黄金角 | 数字集可以任意大，不必先排序 |
| 不判断数系有效性 | 完全剩余系判定 + 提示 | 参考图里"点叠在一起"多半就是数系无效，这里直接说清楚 |
| 网页 canvas，无输出 | 真实 GP 对象 + 数据属性 | 本插件是 Blender 扩展 |

## 实测记录（Blender 5.2.2）

* 单顶点笔划 `add_strokes([1]*n)` 可用，渲染成圆点；`add_strokes` 是结构性改动，
  之后必须重新取 `layer.frames[0].drawing`（否则 `foreach_set` 报
  `internal error setting the array`）。
* 无材质也能上色：写 `vertex_color`（线性）即可，实测渲染采样值与色板 hex 一致。
* `POST_VIEW` 画点是 `POINTS` 图元 + `gpu.state.point_size_set`（屏幕像素，缩放视口不
  跟着变大）。
* HUD 的 `blf` 画不了汉字时自动退回英文 msgid；数字太多时 `_elide` 截断标题。
* 一个坑：第一版把数字的命中区 `_rect_hotspot` 误加进 `primitives`，于是 `hud._draw`
  取 `primitive["kind"]` 抛 KeyError 被吞掉 —— 整个 HUD 静默不画。现在绘制端对未知
  图元直接跳过。
* 填充不需要材质：`fill_id`（CURVE/INT）+ `fill_color`（CURVE/FLOAT_COLOR）+
  `hide_stroke`（CURVE/BOOLEAN）+ `cyclic`（CURVE/BOOLEAN）四条属性就能得到"只有填充、
  没有描边"的闭合瓦片。四条都**必须与笔划数等长**。
* 写入很便宜：4096 格实测整轮 1–2 ms（`add_strokes` 之后重新取 `drawing` 再 `foreach_set`），
  8000 个六边形 ≈ 2.2 ms，两万四方格 ≈ 3.4 ms。瓶颈从来不是这几个数组。
* `layout.prop(enum, ..., text="", expand=True)` 会把按钮标签一起抹掉，整行变成一个
  没有字的蓝条 —— 面板里 expand 的枚举要传标题。
* 视口预览的格子现在直接取 `ring.cell_polygon(domain, cell_gap)`，与「实心格」输出的
  形状和缝隙逐位一致（早先预览里那套 0.94 的常量已经删掉）。
* **动画的多帧**：一帧就是 `layer.frames.new(frame_number)` 后那张 drawing，**每帧的笔划数
  可以不同**（生育那一步翻 `|D|` 倍）。取回帧要按 `frame_number` 找 —— `layer.frames[i]`
  是集合下标、不是帧号，混用会 IndexError。每帧写完 `add_strokes` 都要重新取一次
  `frame.drawing`。92 帧 / 6.5 万笔实测 0.04 s。
* 动画的最后一帧与静态输出逐点一致（位置、`index`、`digit_slot` 都比对过），差别只有
  `AGGREGATE` 档的淡出 —— 动画恒为纯色。
