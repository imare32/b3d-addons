# Gen Imaginary Base — 虚数进制分形

二次整数环上的**进制展开**，画成自仿射点集。

一个**数系**由底数 `b` 与数字集 `D` 决定，整数 `n` 写成 `n = Σ dₖ·bᵏ`。取遍 `|D|^N` 个
地址（`|D|` 为基的 `N` 位混合进制编号），把每个整数画在它自己的位置上，就得到那片
自相似的点集 —— 底数是负的、纯虚的、带 `ω` 的，形状都跟着变。

移植自 TheGrayCuber 的网页项目 **imaginary_bases**（见 [来源与许可](#来源与许可)），
插件形态、HUD 交互与代码分层沿用了 `fractal_family` —— 那是与工作空间目录并列的
**独立仓库**（`C:\git\fractal_family`，自己一套 git 与商店发布流程），不是本仓库的子目录。

## 与 Fractal Family 的关系

两者共用同一对环，但算的不是同一种对象 —— 这对关系值得先说清楚，否则很容易误以为
是把同一个算法换了个皮：

| | Fractal Family | Gen Imaginary Base（本插件） |
|---|---|---|
| 环 | Z[i]、Z[ω]，ω² = −1 或 −1−ω | 同（切换 `i` / `ω` 就是它的 G / E） |
| 参数 | 基因：段 eᵢ（复整数）+ R/M 标记 | 底数 b + 数字集 D |
| 规则 | 每段替换成整条上一级曲线的缩放副本 | `n = Σ dₖ·bᵏ`，对 `|D|^N` 个整数求值 |
| 收缩比 | `|eᵢ| / |T|`，逐段不同（可变比） | `1 / |b|`，全体统一（自仿射） |
| 产物 | 折线**曲线** | 自仿射**瓦片的点集** |
| 编辑 | 拖格点节点、切 R/M、滚轮改等级 | 拖数字与底数、增减数字、滚轮改位数 |

所以"孪生"成立在：**同一对环、同一套格点吸附、同一个「有限地址集 → 点」的机制**；
不成立在公式上：它的每段是"终点"，这里的每个数字是"加数"；地址权重一边是连乘
`∏(eᵢ/T)`，一边是幂 `bᵏ`。经典例子里这两者正好是"瓦片"与"瓦片边界"的关系
（`base −1+i` 配数字 `{0,1}` 是 twindragon，而它的边界就是龙形曲线）。

## 数学

**环。** `I` 域 ω = i（ω² = −1，高斯整数，方点阵）；`W` 域 ω = ζ = e^{2πi/3}
（ω² = −1−ω，艾森斯坦整数，三角点阵）。乘法靠把二次项折回去：

```text
(a + bω)(c + dω) = ac + (ad + bc)ω + bd·ω²
ω² = d0 + d1·ω   →   (ac + d0·bd,  ad + bc + d1·bd)
```

**有效数系判据。** 参考项目允许随便拖数字，但从不判断"这个数系是否有意义"。这里判了，
两条都是可判定的：

1. `|D| = N(b)`（位数等于底数的范数）；
2. `D` 在 `Z[ω]/(b)` 里两两不同余，即 `D` 是模 `b` 的**完全剩余系**。

满足这两条，地址 → 整数的映射就是双射（Knuth 对高斯整数，Kátai–Kovács 对一般二次环），
面板与 HUD 会显示"有效数系"；不满足则给出具体原因（位数不对 / 两个数字同余）。

**为什么点数是指数。** `|D|^N`：4 个数字 16 位就是 43 亿。所以位数永远先被**点数预算**
夹一次（`ring.max_places`），改数字集时也会自动往下夹 —— 否则把 4 个数字换成 40 个数字
会瞬间炸掉视口。

**点集是预计算成表的。** 每个数字乘 `bᵏ` 的结果只有 `N × |D|` 项，与点数无关；算点集时
用 numpy 的 fancy indexing 一次性求和，循环只发生在小表上。见 `ring.point_set`。

## 界面

侧栏 `View3D > Sidebar > Fractal Base`：预设、环、底数、数字列表、位数、上色档、点数预算、
点半径、生成 / 删除 / 取景 / HUD。

**HUD**（模态）在视口里直接改数系：

| 操作 | 效果 |
|---|---|
| 拖数字圆点 / 底数菱形 | 改数字或底数，总是吸附到整数格点（底数不能为 0） |
| 滚轮 | 改位数 |
| Shift + 滚轮 | 缩放地图 |
| `F` / `Shift+F` | 取景：只框数字 / 连点集一起框（也可点 `Fit` 在两个档之间切） |
| `Tab` | 切换环（i ↔ ω） |
| `A` / `X` | 加一个数字 / 删最后一个 |
| `Esc` / 右键 / `×` | 关闭 HUD |

面板与 HUD 改的是同一套参数，两边实时同步。

**两个取景档是有必要的**：点数一多，点集会跨几十个格距，而数字都挤在原点附近两格内 ——
按点集取景，数字就变成一团墨点；按数字取景，才拖得动。所以默认框数字，`Shift+F` 看整体。

## 输出

一个 GP 对象 `Imaginary Base`，**每个整数一条单顶点笔划**（实测 5.2 里单顶点笔划渲染成
圆点，半径由 `radius` 属性决定）。折线笔划会把点连成蛛网，所以只能一点一笔。

`POINT` 域属性：

| 属性 | 类型 | 含义 |
|---|---|---|
| `position` | float3 | 点坐标（GP 自带） |
| `radius` | float | 点半径 = 「点半径」参数 |
| `vertex_color` | color | 线色（**线性**存，与色板逐位一致，实测采样误差 0） |
| `index` | int | 这个点是哪一号整数（地址本身） |
| `digit_slot` | int | 它用哪一号颜色（= 最高位 / 指定位的编号） |

后两条是**数据接口**：几何算完就写死在那里，之后按位筛选、做动画、换几何节点驱动都不用
重算点集。

**点半径默认 0.42**（格距为 1）：参考项目画的其实是"每个整数一个格子"（边长约 0.9），
半径取到 0.42 相邻点才挨在一起连成面；调小就退化成一层散点。

## 上色

| 档 | 规则 |
|---|---|
| `聚合`（默认） | 最高位定色，低位身份逐层混进来；`shade = 0.8 + 0.2·shade(去掉最高位)`，越靠表层越淡 |
| `最高位` | 最高位一位一色，平的 |
| `第 k 位` | 指定某一位上色，用来看"哪一层在哪个位置" |

色板前 8 个数字手挑（0 号刻意压暗），之后按黄金角散开色相，所以几十个数字也不会撞色。

## 与参考实现的取舍

| 参考项目 | 这里 | 为什么 |
|---|---|---|
| 每个整数画一个格子（方块 / 六边形） | 每条单顶点 GP 笔划 + 点半径 | 要真正落在 Blender 的数据里；半径调到 0.42 视觉等价 |
| 点数上限约 6000 | 512 – 120000，默认 8000 | GP 一个点一笔，预算就是笔划数；两万笔视口仍可拖动 |
| 上色按极角分配 | 手挑 + 黄金角 | 数字集可以任意大，不必先排序 |
| 不判断数系有效性 | 完全剩余系判定 + 提示 | 参考图里"点叠在一起"多半就是数系无效，这里直接说清楚 |
| 网页 canvas，无输出 | 真实 GP 对象 + 数据属性 | 本插件是 Blender 扩展 |

## 文件

```text
gen_imaginary_base/
├─ ring.py         数学层（不含 bpy）：环、进制展开、完全剩余系、点集
├─ presets.py      43 套社区数系（原样保留分享码与投稿者）
├─ palette.py      色板与 sRGB → 线性
├─ props.py        scene.imaginarybase、点集缓存
├─ preview.py      POST_VIEW 预览（不建数据块）
├─ hud_layout.py   HUD 图元与命中区（纯函数，可离线跑）
├─ hud.py          POST_PIXEL 面板
├─ build.py        写 Grease Pencil
├─ ops.py          生成 / 取景 / 加删数字 / HUD 模态
└─ ui.py           侧栏面板
```

`ring.py` 与 `hud_layout.py` 都不 import `bpy`：前者能直接在系统 Python 里跑（批量扫参数、
对拍），后者能把 HUD 的图元用 Pillow 画成 PNG 检查排版 —— 本插件开发时就是这么验的。

## 实测记录（Blender 5.2.2）

* 单顶点笔划 `add_strokes([1]*n)` 可用，渲染成圆点；`add_strokes` 是结构性改动，
  之后必须重新取 `layer.frames[0].drawing`（否则 `foreach_set` 报
  `internal error setting the array`）。
* 无材质也能上色：写 `vertex_color`（线性）即可，实测渲染采样值与色板 hex 一致。
* `POST_VIEW` 画点是 `POINTS` 图元 + `gpu.state.point_size_set`（屏幕像素，缩放视口不
  跟着变大）。
* HUD 的 `blf` 画不了汉字时自动退回英文 msgid；数字太多时 `_elide` 截断标题。
* 一个坑：第一版把数字的命中区 `_rect_hotspot` 误加进 `primitives`，于是 `hud._draw`
  取 `primitive["kind"]` 抛 KeyError 被吞掉 —— 整个 HUD 静默不画。现在绘制端对未知
  图元直接跳过。
