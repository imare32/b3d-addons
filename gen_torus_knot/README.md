# 生成式环面 (p, q) 结（Gen Torus Knot）

参数化环面 (p, q) 结（扩展 id `gen_torus_knot`，Blender 5.2.2 实测）。

参数化照搬参考实现 `ga4/addons/torus_knot.py` 的 Taichi kernel（去掉并行、去掉随机）：

```text
theta = p · t · u_mult + 绕转相位
phi   = q · t · v_mult + 自旋相位
x = (R + r·cos φ)·cos θ
y = (R + r·cos φ)·sin θ
z = r·sin φ · h
```

默认输出是 **Grease Pencil 笔划**，不是网格：环面结是一条一维的曲线，画成笔划最贴身，也便于
后续拿几何节点扫成实体管。几何核心的**两条属性落在 `u_map` / `v_map`（POINT 域）**上——它们就是
点的两个归一化角度，扫管后跟着到网格顶点，可以直接拿去驱动颜色 / 动画。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Gen Torus Knot**；
2. 3D 视图侧栏出现 **Torus Knot** 面板（F3 里也有 `gen_torus_knot.*` 算子）；
3. 点「生成」——场景里长出 `Torus Knot` 对象：一个 **Grease Pencil 对象**，每股一条
   **闭合笔划**（p、q 互质时是 1 股，不互质时裂成 gcd(p, q) 股），带 `Tube` 几何节点修改器
   （扫管用，默认关着）；
4. **之后改参数不用再点「生成」**：自动更新开着时，松手约 0.08 s 结就跟着重算好了
   （见下「自动更新」）；
5. 想看实体管就打开「管状实体」：修改器本来就挂着，这一下是瞬时的（笔划不画了，改画网格）；
6. 出图点「场景预设」：3/4 视角透视相机、2048×2048、Standard 色彩、世界背景铺项目色板的
   `BACKGROUND`、一盏三点式简化的太阳主光。

算子：`gen_torus_knot.generate`（生成 / 更新）、`gen_torus_knot.delete`、
`gen_torus_knot.setup_scene`、`gen_torus_knot.sync_from_object`（从对象上记录的参数回读面板）。

生成对象上记了 **20 项**设计参数（15 项几何 + 5 项就地），换文件 / 换场景后「从对象回读参数」
就能把面板还原成当初的样子。

## 自动更新（`live.py`）

**几何参数一改，结就自动重算** —— 不用再点「生成」。面板头部有个「自动」开关，默认开着。

| 环节 | 做法 |
|---|---|
| 谁发现改动 | RNA 的 `update` 回调（几何档的每个参数都挂了 `_mark_dirty`） |
| 什么时候算 | 回调里**只排一次 timer**，真正的重算推到 timer 里跑 |
| 拖滑块 | 每次改动都把 timer **重排**一遍（`DEBOUNCE = 0.08 s`），连续改动只算最后一次 |
| 算的是哪一版 | 重算时现读 `scene.gen_torus_knot` —— 面板上是什么值，视口里就是什么形状 |

**为什么不在 `update` 回调里直接算**：那会儿 Blender 可能正在拖滑块、撤销 / 重做、换数据块，
往生成对象里写几何（删图层重建）等于把数据从它脚下抽走 —— `gen_celtic` 的实时更新踩过这个坑，
直接把 Blender 干掉了。挪进 timer 之后，写操作一定发生在求值 / 撤销恢复之后。

**什么时候不重算**：

| 情况 | 行为 |
|---|---|
| 场景里还没有结对象 | 不凭空长出对象（点「生成」才建） |
| 自动更新关着 | 只标「待生成」，人工点按钮 |
| 文件加载期间（`load_pre` / `load_post`） | 加载也会触发参数的 update 回调，那会儿不碰几何 |
| 「从对象回读参数」 | 回读的值与几何本来就相符（`props.suspend_auto_update()` 挂起） |

**口径一致**：手动生成与自动更新走同一条路（`builder.rebuild`）—— 算点 → 写笔划 → 挂修改器
→ 记参数，重算不会把关掉的管状实体又打开、也不会把对象上的参数记录抖掉。

**已知取舍**：自动重算走的是 timer，**不进撤销栈** —— Ctrl+Z 撤的是面板上的参数，几何要再点
一次「生成」才追得上（同 `gen_celtic` 的实时更新）。

## 面板参数

三档参数的生效方式不同，面板上也分开摆：

| 分组 | 参数 | 说明 |
|---|---|---|
| 头部 | 生成 | 按当前参数算一遍结（自动更新开着时，平时用不着点） |
| | 自动 | 几何参数一改就自动重算（松手约 0.08 s），不用再点「生成」 |
| (p, q) 结 | p / q | 绕主圆 / 副圆的圈数，**带符号**（负号就是反着绕，等价参考实现的 flip p / q）。**都不能为 0** |
| | 翻转 p / q | 把符号取反的小按钮，和直接填负数等价 |
| | 多股 | p、q 不互质（gcd > 1）时结会裂成 gcd(p, q) 条同轴的股；关掉就恒为一条（图形不变，只是把各股连成一条来回绕的曲线，闭合笔划会变成 8 字形） |
| 参数化 | 绕转倍数 / 自旋倍数 | `theta` / `phi` 的额外整数倍（改的是参数化，不是 p / q） |
| | 绕转相位 / 自旋相位 | `theta` / `phi` 的起始相位（弧度）：整体转一下 / 沿截面扭一下 |
| 尺寸 | 主半径 / 副半径 | 环面的 `R` / `r`（r > R 时结会自穿） |
| | 整体缩放 | 同时乘 `R` / `r`（线宽与管半径是绝对尺寸，不跟着变） |
| | 高度 | z 方向的拉伸：1 = 正圆截面，0 = 压成平面曲线，> 1 = 拉成高塔 |
| 分段 | 自动分段 | 按结的平均周长定分段（见下），p / q / 半径一改点数自动跟上 |
| | 分段 | 每股的点数 + 1（100 已够圆滑） |
| 外观（就地） | 线宽 / 线色 | 只改 GP 属性，**拖滑块是实时的**；开了管状实体后笔划不画，这两项当场失效 |
| 管状实体（就地） | 管状实体 | 扫成实体网格的开关（只切修改器可见性，几何原样留着） |
| | 管半径 / 圆周分段 | 只进几何节点接口输入，同样是实时的 |

## 算法（`knot.py`，纯 numpy，不 import bpy）

* **点**：一根股就是 t ∈ [0, 2π / links) 的一段，采 `resolution - 1` 个点。**最后一个点不重复
  首点**（差一个步长），闭合由笔划的 `cyclic` / 曲线的闭合表达 —— 实测量到「首点 ≠ 末点」且
  「首末间距 == 相邻步长」。
* **股**：`links > 1` 时各股整体差一个 `2π / q` 的相位，绕在环面上正好铺满；这些股各自闭合、
  互不相交。p、q 互质时才是真结，否则退化成几条同轴的圈。
* **自适应分段**：结既含 p 圈主圆也含 q 圈副圆，最长的走法与最短的走法差在 `R ± r` 上，取两者
  平均当代表长度，按「每股平均长度每单位 8 个点」折算（下限 3）。实测：`(2,4)` → 56 段、
  `(3,7)` → 168 段、`(3,7, r=0.5)` → 232 段。
* **几何核心两条属性**：`u_map` = θ/2π、`v_map` = φ/2π，各减去自身下取整，落进 `[0, 1)`
  （与参考实现一致，跨圈不累积成 1、2、3……，拿去做颜色 / 动画驱动不用再取模）。

对拍（默认 `p=2, q=3, R=1, r=0.25, h=1, resolution=100`）：

| 检查 | 结果 |
|---|---|
| 点到环面的残差 `max|残差 - 1|` | **1.9e-07** |
| `u_map` vs `wrap(atan2(y, x)/2π)` | **3.0e-08** |
| `v_map` vs `wrap(atan2(z, ρ-R)/2π)` | **5.8e-08** |
| `u` / `v` 值域 | `[0, 0.9899]` / `[0, 0.9697]`（都在 `[0,1)`） |
| 首点 ≠ 末点，首末间距 == 步长 | 都成立（闭合靠 `cyclic`） |

耗时（算法层，同一台机；第一次含 numpy 预热）：

| 形状 | 点数 / 股 | 分段 | 耗时 |
|---|---|---|---|
| `2,3` 默认 | 99 / 1 | 100 | **0.12 ms**（其后同类 0.04–0.06 ms） |
| `2,4` 自动分段 | 110 / 2 | 56 | **0.05 ms** |
| `3,7` | 511 / 1 | 512 | **0.06 ms** |
| `8,12` 多股 | 796 / 4 | 200 | **0.05 ms** |
| `3,5` 压平 `h=0` | 299 / 1 | 300 | **0.04 ms** |

整套生成算子（算点 + 写 GP 属性 + 挂修改器 + 记住参数）端到端 **2–3 ms**，所以「生成 / 更新」
完全可以当实时用。

## Grease Pencil 后端（`gp.py`）

一个对象、一个图层、每股一条笔划；属性全部落在 **POINT（vertex）域**：

| 域 | 属性 | 类型 | 谁写的 |
|---|---|---|---|
| POINT | `position` | float_vector | 几何核心（GP 自带属性） |
| POINT | `radius` | float | 本插件——线宽（每条笔划的粗细） |
| POINT | `opacity` | float | 本插件——恒 1.0 |
| POINT | `vertex_color` | float_color | 本插件——线色，**线性**存 |
| POINT | `u_map` | float | 几何核心——绕主圆的归一化角度 |
| POINT | `v_map` | float | 几何核心——绕副圆的归一化角度 |
| CURVE | `cyclic` | bool | 本插件——每股闭合 |
| CURVE | `curve_type` | int8 | GP 自带 |

**实测坑（5.2.2）**：

* 图层 `use_lights` 新建时默认 `True`，场景里没有灯时颜色只剩约 **四分之一**亮度 —— 本后端一律
  建**无光照层**（`use_lights = False`），颜色所见即所得；
* 不给 `miter_angle` 属性：没有它拐角按**圆角**连，有它才是斜接，结的折点不会崩出尖角；
* **颜色不走材质**（`vertex_color` 就够，对象上还会 `materials.clear()`）——因此 3D 视图 Solid 模式
  要把「着色 → 颜色」切到 **Attribute** 才看得见，生成算子会顺手切一次；
* 属性长度对不上时 Blender 只报一句 `Array length mismatch (expected n, got m)`，不说是哪条 ——
  `_set_points` 按字段分量数（`value` / `vector` / `color` 各 1 / 3 / 4）先自己比一遍，报错带上属性名。

`GENTK_OT_generate` 把「算点 → 写笔划 → 挂修改器 → 记参数」整段收在一个 `try` 里，出错（p/q 为 0
之类）就落成面板上的一句话并把 `dirty` 标回去，不把 traceback 甩到操作上。

## 管状实体（`tube.py`）

节点组 `Torus Knot Tube`（只建一次，所有生成对象共用）：

```text
Group Input(Geometry, Radius, Resolution)
  → Grease Pencil to Curves  （Layers as Instances = False）
  → Curve to Mesh            （截面 = Curve Circle，Fill Caps 开）
  → Set Shade Smooth
  → Set Material             （管材质）
  → Group Output
```

**Blender 5.2 上必读的三条（都是实测记下来的）**：

* `Grease Pencil to Curves` 的 **`Layers as Instances` 必须关掉**：默认 `True` 时它把每层吐成
  **实例**，后面的 `Curve to Mesh` 拿到实例什么也产出不了（渲染出来是空的）；
* **管径 = 截面圆环的半径**。GP 笔划的 `radius`（线宽）不会带到曲线上，`Set Curve Radius` 也改不动
  管径 —— 所以半径直接驱动 `Curve Circle` 的 Radius 插口；
* 修改器的接口输入是 `modifier.properties.inputs.<identifier>.value`（identifier 形如
  `Socket_2`，得回 `node_group.interface.items_tree` 按显示名查），而且**写完不会自动标脏** ——
  得自己 `obj.update_tag()`，不然拖滑块时视口停在旧几何上。老的 `modifier[identifier]` 在 5.x 上
  直接抛 "id properties not supported"（修改器不是 ID）。

扫出来的管上，`u_map` / `v_map` / `opacity` / `vertex_color` **跟着到网格的 POINT 域**，
`material_index` 也齐。实测（默认 `2,3`，99 点）：

| 管半径 / 圆周分段 | 顶点 / 面 | 包围盒 z 半幅 |
|---|---|---|
| `0.04 / 8` | **792 / 792** | ±0.2888（= 副半径 0.25 + 管半径 0.04） |
| `0.12 / 16` | **1584 / 1584** | ±0.3678（= 0.25 + 0.12） |
| `2,4` 多股（110 点）`0.04 / 8` | **880 / 880** | ±0.0400（压平到 `h=0`） |

包围盒 z 半幅正好是「副半径 + 管半径」，从几何上确认了管的粗细就是管半径。同一场景渲染对比
（EEVEE，512²）：笔划 9,778 个红色像素 → 管 12,596 个（**+29%**），管确实画出来了。

开关只切 `show_viewport` / `show_render`，**不删几何** —— 所以「关掉再打开」是瞬时的，参数也能
一直从对象上回读。

## 边界与错误

| 情况 | 行为 |
|---|---|
| `p = 0` 或 `q = 0` | 算法层抛 `ValueError`，算子收成面板上的「p、q 都不能为 0」，返回 `CANCELLED`，`dirty` 标回来 |
| 分段 < 3 | `IntProperty` 的硬下限 `min=3` 已挡住（实测填 2 会被夹成 3）；算法层另有一道 `MIN_RESOLUTION` 校验 |
| 管状实体（几何节点）出问题 | 同上，和算点失败走同一条 `try` / `report` 路径 |

## 模块

```
knot.py     几何核心：参数化 / 股拆分 / 自适应分段 / u_map、v_map（纯 numpy，可脱离 Blender 跑）
gp.py       默认后端：GP 对象 / 笔划 / POINT 域属性（GP v3 的 drawing.attributes）
tube.py     可选后端：几何节点「笔划 → 曲线 → 扫管」+ 管材质 + 修改器接口输入
builder.py  重算入口：算点 → 写笔划 → 挂修改器 → 记参数（算子与自动更新共用）
live.py     自动更新：参数一改就重算（防抖 timer，推迟到空闲时再写几何）
props.py    scene.gen_torus_knot 参数组 + 对象上回存的设计参数
ops.py      生成 / 删除 / 回读参数 / 场景预设
ui.py       View3D > 侧栏 > Torus Knot
palette.py  项目色板副本（改色记得与 _shared/palette.py 同步）
viewport.py 视口 Solid 着色检查副本（与 gen_zellij / gen_tsubayaki 同一份）
```

`knot.py` 不 import bpy，可以单独跑：`build(p=2, q=3, resolution=100)` 返回
`TorusKnot(points, u_map, v_map, counts, links, resolution, closed)`。

## 局限与下一步

* **没有扫管以外的网格化**：输出要么是笔划、要么是几何节点扫出来的管，没有「一键转成真网格」
  （进视口用 `Object > Convert` 走的就是修改器求值，等价可用）；
* **没有材质化的粗细变化**：线宽 / 管半径都是常数，`radius` 属性虽然逐点存在，但面板没有
  「按 u / v 调粗细」的入口（属性已经在那儿了，接个几何节点即可）；
* **管截面固定是圆**：没有椭圆 / 多边形截面，也没有沿程扭转；
* **`links > 1` 的股之间不理会相交**：p、q 不互质时各股是分层的同心圈，不是真结；
* **自适应分段只按平均周长**：p、q 相差很大时（比如 `1,13`）曲率很不均匀，密的地方仍会显棱；
* 分段上限只给了 `soft_max=512`，硬上限没设：真要几万点也能跑（算法层 0.1 ms 量级），
  但 GP 属性写入会线性变慢。
