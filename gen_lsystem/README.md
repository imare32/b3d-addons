# 生成式 L-system（Gen L-System）

L-system（Lindenmayer system）：**公理**是一串符号，**产生式**把它们一代代同时重写，**turtle**
再把符号串解释成几何。这个扩展把「几何」做成**纯路径**，输出 Grease Pencil v3 笔划：

- 每条分支一笔（闭合的曲线如龙形曲线 / 科赫雪花就只有一笔）；
- **粗细逐点变化**（`!` 变细、`#` 变粗、`¤` 直接设半径）—— 树从主干到枝梢自然收尖；
- 可选「按粗细 / 按深度 / 按进度」在两种颜色之间渐变；
- 十套 ABOP 预设，2D 俯视正交 / 3D 四分之三透视两档场景预设；
- 几何参数一改就自动重算（防抖 0.2 s），不用点「生成」。

扩展 id `gen_lsystem`，Blender 5.2.2 实测。符号语义对齐参考实现 [`.ref/lsystem`](../.ref/lsystem)
（krljg/lsystem）与 ABOP（*The Algorithmic Beauty of Plants*）；重写引擎与 turtle 按同一套语义
**重新实现**了一遍（差异见[与参考实现的差异](#与参考实现的差异)），不共享参考实现的代码。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Gen L-System**；
2. 3D 视图侧栏出现 **L-System** 面板（F3 里也有 `gen_lsystem.*` 算子）；
3. 面板默认已经填好「分形植物」那一套（公理 `X`、两条规则、迭代 5）；
   点「生成」——场景里长出 `L-System` 对象：一个 **Grease Pencil 对象**、一个 `Branches` 图层、
   512 条笔划（11 ms）；
4. **之后改参数不用再点「生成」**：自动更新开着时，松手约 0.2 s 就重算好了；
5. 出图点「场景预设」：2D 预设给俯视正交相机、3D 预设给四分之三透视相机，都是 2048×2048、
   Standard 色彩、世界背景铺项目色板的 **`SILK`（绢白 `#F4F0EA`）**
   —— 这是本插件的默认底色：线稿在绢白上反差最大，渲染出来的像素值就是色板上的那个十六进制。

算子：`gen_lsystem.generate` / `.delete` / `.setup_scene` / `.sync_from_object` /
`.apply_preset` / `.rule_add` / `.rule_remove`。

## 符号表（turtle 层）

| 符号 | 含义 |
|---|---|
| `F` / `G` | 前进并画线（可带长度 `F(1.5)`）；`G` 与 `F` 同义，ABOP 常拿它当孪生兄弟 |
| `f` | 只前进不画（当前笔划在此断开） |
| `+` / `-` | 绕局部 Y 轴左 / 右转（可带角度 `+(45)`，**单位是度**） |
| `^` / `&` | 绕局部 X 轴抬头 / 低头 |
| `\` / `/` | 绕局部 Z 轴翻滚 |
| `\|` | 掉头（绕 Y 转 180°） |
| `$` | 扶正：把局部「左」轴摆到水平（ABOP 的 rotate upright） |
| `[` / `]` | 压栈 / 出栈（分支，深度 +1） |
| `!` | 变细（×「变细倍率」，可带倍率 `!(0.7)`） |
| `#` | 变粗（×「变粗倍率」） |
| `¤` | 直接设半径（`¤(0.02)`） |
| `s` | 整体缩放（步长与半径一起乘） |
| `£` | 把转角换成一个随机角（按种子定） |
| `%` | 剪掉本分支剩余部分：之后的 `F` 只前进不画，直到 `]` |
| `X` `A` `B` … | 其余字母是**占位模块**，不画线（L-system 里最常见的就是这种「非终结符」） |
| `p` `m` `w` `~` `:` `;` `{` `}` | 参考实现里是网格 / 对象 / 材质 / 多边形相关，**GP 用不上**；命中会在面板「状态」里列出来 |

**朝向**沿用参考实现：前进方向是局部 **+Z**，所以 `+`/`-` 绕 Y、`^`/`&` 绕 X、`\`/`/` 绕 Z。
二维预设把整张图绕 X 轴转 -90° 躺到 **XY 平面**（+Y 朝上），与其他二维插件的画布朝向一致。

## 产生式与参数表达式

每条产生式三个字段：

```text
左侧(参数名)   条件          右侧
A(l,w)        gt(l,0.1)    F(l)[&(45)B(mul(l,0.6),mul(w,0.707))]/(137.5)A(mul(l,0.9),w)
```

- 左侧只允许**一个模块**，括号里是参数名（标识符）；右侧自由写；
- **条件**可空（= 永远成立）。同一左侧写成多条，就是**随机**选一条（种子固定 → 结果固定）；
- 参数表达式走一个**只认函数式写法**的求值器，不认中缀运算符，也**不用 `eval`**
  （面板里填的东西永远不会执行到任意代码）：

| 类别 | 函数 |
|---|---|
| 算术 | `add sub mul div pow`、`neg abs floor`、`min max` |
| 三角 / 指数 | `sin cos tan`（弧度）、`log(x[,base])`、`sqrt` |
| 随机 | `rand(x,y)` |
| 比较 | `eq gt gteq lt`（真 = 1，假 = 0） |
| 上下文 | `get(i)` 实例号（单实例恒 0）、`get(iter)` 当前迭代号 |

## 参数分档

| 分组 | 参数 | 说明 |
|---|---|---|
| 系统 | 公理 / 维度 / 迭代 / 随机种子 | 改的是折叠本身，必须重跑「重写 + turtle」 |
| 产生式 | 左侧 / 条件 / 右侧 | 同上；「+ / −」按钮增删，选中行在下面编辑 |
| 解释 | 转角 / 步长 / 基础线宽 / 变细倍率 / 变粗倍率 / 向重力 | 同上 |
| 外观（**就地**） | 宽度倍数 / 线色 / 渐变 / 末色 / 不透明度 | 只重写 GP 属性，拖滑块实时，路径一点不重算 |
| 输出 | 落在帧 | 笔划写进哪一帧（GP 显示「不晚于当前帧的最后一帧」，所以 1 一直可见） |
| 预设 | 预设 + 「应用预设」 | 整组写进面板（公理 / 规则 / 解释参数 / 维度） |

**为什么「宽度倍数」能就地改**：`radius` 属性拆成了两条 —— `base_radius` 是几何算出来的粗细
（`!` / `#` / `¤` 的结果），`radius` 是它乘上宽度倍数。拖宽度倍数只是拿 `base_radius` 重算一遍
`radius`，不碰任何点。

## 算法（`lsystem.py` / `turtle.py`，纯 Python，不 import bpy / mathutils）

### 重写（`lsystem.py`）

1. **切词**：模块 = 一个字符，`A(1,2)` 的参数按**第 0 层逗号**切开（`mul(l,0.6)` 里的逗号不算），
   括号按层数配对；
2. **匹配**：模块名相同 + **参数个数相同** + 条件为真。同一模块命中多条就按种子随机挑；
3. **生成**：把右侧的表达式在当前环境（左侧参数名 → 值）里求值，得到带数值的模块；
4. **规模上限**：展开后模块数超过 `DEFAULT_MAX_SYMBOLS = 400_000` 直接报错，
   面板上写一句「把迭代数调小」，而不是把 Blender 卡死。迭代数硬上限 16。

字符串按**模块列表**处理，不是按字符处理 —— 所以 `A(1,2)` 是一个原子，不会被"半个参数"切开。

### 解释（`turtle.py`）

- **一笔怎么断开**：`[` 时父路径**不 flush**（它穿过 `]` 之后接着往下走），分支自己开一条新路径；
  `]` 时把分支路径收掉、恢复父路径继续追加。于是分叉点在 GP 里是**两笔起点重合**，
  父笔划仍然连贯 —— 等价于参考实现「同一个 mesh 里续边」；
- **路径深度**记在 `Path.depth` 上（`[` 的层数），写成 POINT 域的 `depth` 属性，
  渐变配色与后续节点都能用；
- **向重力**：每走一步，把朝向朝 `(0,0,-1)` 扳 `force × |heading × gravity|` 弧度
  （绕世界轴、左乘）。参考实现把世界轴当本地轴右乘，侧枝一多就歪；
- **扶正 `$`**：直接用三个基向量重建旋转矩阵（不影响朝向，只摆平「左」轴），
  比参考实现的「打印 + 反余弦」干净得多；
- 3×3 矩阵是自己写的（`_multiply` / `_rotation` / `_rotation_about`），算法层因此
  **不依赖 mathutils**，可以 `python -c` 直接跑。

### 与参考实现的差异

| | 参考实现 | 这里 |
|---|---|---|
| 规则匹配 | 按字符串**前缀**匹配；左侧不带参数时连 `A(1,2)` 也匹配（消费一个字符，`(1,2)` 当普通字符抄下去） | 模块 + **参数个数**精确匹配 |
| 参数求值 | 每次展开都重新扫字符串 | 一次切词、按环境求值，结果直接是数值 |
| `%`（剪断分支） | 在重写层吞掉输入 | 在 turtle 层：之后的 `F` 只前进不画线 |
| `G` | 不识别（当占位符） | 与 `F` 同义（画线） |
| 输出 | 网格 / 曲线 / 皮肤 / 圆柱等 9 种 pen | 只有 GP 笔划（+ 逐点半径） |
| 随机 | 全局 `random`，`seed` 打散 | 局部 `random.Random(seed)`，同参数必同图 |

### 对拍（参考实现的单元测试逐条复现）

| 检查 | 参考实现期望 | 这里 |
|---|---|---|
| 藻类 `A→AB, B→A` 迭代 5 | `ABAABABAABAAB` | ✅ 一致 |
| 参数化 `A(1,10) → F(1)[\(45)B(...)]` | `F(1.0)[\(45.0)B(0.6,7.069…)]` | ✅ 数值一致（格式更短） |
| `¤(sub(1,div(pow(x,2),16)))` | `¤(0.9375)` | ✅ 一致 |
| `get(iter)`：`X→AX, A→F[-(get(iter))F]` 迭代 4 | `F[-(1)F]F[-(2)F]F[-(3)F]AX` | ✅ 一致 |
| 随机规则（种子 0）迭代 3 | `++FX` | ✅ 一致 |
| `%` 剪断：`"AXA"`，`X→%` | `"A"` | ✅ 语义一致（turtle 层实现） |

|---|---|---|
| 分形植物 | 512 / 2000 | 5.1 ms |

## Grease Pencil 后端（`gp.py`）

一个对象、一个图层 `Branches`、每条路径一笔；属性全部落在 **POINT（vertex）域**：

| 域 | 属性 | 类型 | 谁写的 |
|---|---|---|---|
| POINT | `position` | float_vector | 几何核心（GP 自带） |
| POINT | `radius` | float | 本插件 —— **最终**线宽 = `base_radius × 宽度倍数` |
| POINT | `base_radius` | float | 几何核心 —— `!` / `#` / `¤` 的结果 |
| POINT | `taper` | float | 归一化粗细 0..1（1 = 最细），「按粗细」渐变按它插值 |
| POINT | `progress` | float | 沿这一笔的进度 0..1（**按弧长**，每笔各自从 0 走到 1），「按进度」渐变按它插值 |
| POINT | `opacity` | float | 本插件 —— 整层不透明度 |
| POINT | `vertex_color` | float_color | 本插件 —— 线色 / 渐变，**线性**存 |
| POINT | `depth` | int | 分支深度（`[` 的层数） |
| CURVE | `curve_type` | int8 | GP 自带 |

### 三档渐变

| 档 | 用哪条属性 | 用在什么图案上 |
|---|---|---|
| 关闭 | — | 单色 |
| 按粗细 | `taper` | `!` / `#` / `¤` 造成的锥度：细处暖、粗处墨（树从主干到枝梢） |
| 按深度 | `depth` | 分叉树按层数分色：主干一色、深一层一个色 |
| 按进度 | `progress` | 沿这一笔从起点到终点：单笔图案整条扫过去，分叉树则是每根枝条各自朝梢部推进 |

`progress` 按**累计弧长**归一化（与几何节点 `Spline Parameter.Factor` 同一口径），不是按点数 ——
单轴树那种段长逐级变短的规则，两者会差很远。三条量都躺在属性里，**切档只重写 `vertex_color`**，
路径与几何一概不动。

> 一笔画到底的图案（龙形 / 科赫 / 希尔伯特 / 谢尔宾斯基）既没有分支也没有 `!`：`depth` 恒 0、
> `taper` 恒 1，前两档在它们身上是**单色**的 —— 「按进度」是这四套唯一能出渐变的档。

**实测坑（5.2.2）**：

- 新建图层 `use_lights` 默认 `True`，场景里没灯时颜色只剩约 **四分之一**亮度 —— 本后端一律建
  **无光照层**（`use_lights = False`）；
- `add_strokes` 是**结构性**改动：改完手里那个 drawing 指针就失效了（再往上 `foreach_set` 会报
  `internal error setting the array`），必须重新从 `layer.frames[0].drawing` 取一次；
- `foreach_set` 的长度对不上时 Blender 只报一句 `internal error setting the array`，不说是哪条属性 ——
  `_ensure()` 每次按领域长度（POINT = 点数，CURVE = 笔划数）自己比一遍；
- 颜色不走材质（对象上会 `materials.clear()`），所以 3D 视图 Solid 模式要把
  「着色 → 颜色」切到 **Attribute** 才看得见 —— 生成算子会顺手切一次（`viewport`）；
- 不给 `miter_angle` 属性：没有它拐角按**圆角**连，折线不会崩出尖角。

两条包围盒（`gen_lsystem_bounds_min` / `_max`）也记在对象上：GP 对象的 `bound_box` 在数据刚写完时
可能还是旧的，「场景预设」按属性取景，不靠它。

## 自动更新（`live.py`）

| 环节 | 做法 |
|---|---|
| 谁发现改动 | RNA 的 `update` 回调（几何档每个参数、规则每一行都挂了） |
| 什么时候算 | 回调里**只排一次 timer**，真正的重算推到 timer 里跑 |
| 拖滑块 | 每次改动都把 timer **重排**一遍（`DEBOUNCE = 0.2 s`），连续改动只算最后一次 |
| 算的是哪一版 | 重算时现读 `scene.gen_lsystem` —— 面板是什么值，视口就是什么形状 |

**为什么不在 `update` 里直接算**：那会儿 Blender 可能正在拖滑块、撤销 / 重做、换数据块，往生成对象里
写几何等于把数据从它脚下抽走（`gen_celtic` 的实时更新踩过这个坑）。

**什么时候不重算**：还没有生成对象（不凭空长对象）/ 自动更新关着 / 文件加载期间 /
回读参数与套用预设期间（`props.suspend_auto_update()`）。

**已知取舍**：自动重算走 timer，**不进撤销栈** —— Ctrl+Z 撤的是面板参数，几何要再点一次「生成」
才追得上（同 `gen_torus_knot`）。

## 场景预设

| 维度 | 相机 | 取景依据 |
|---|---|---|
| 2D | **正交**，正上方俯视（相机默认朝 -Z） | 包围盒 XY 跨度 × 1.15 当 `ortho_scale` |
| 3D | **透视** 40°，方位 `(1, -1, 0.55)` | 逐角点算退距，图案填满画面又不切边 |

两种都做：2048×2048、`view_transform = "Standard"`、`look = "None"`、世界背景铺
**`SILK` 绢白 `#F4F0EA`**（强度满 1.0，渲染出来的底色 = 色板值，实测 244/240/234）、
并把 3D 视图背景从「主题」切成「世界」（`viewport.ensure_world_background`）。

> 底色与别的插件不同：仓库统一画布是 `BACKGROUND`（`#E4D9D0`，带一点暖灰）。
> 这个是**线稿**插件，全程不出填色块，所以用更亮的一档绢白 —— 墨玄细线与朱砂梢在绢白上
> 反差最大，也不会像 `PAPER`（`#F9F7F3`）那样接近纯白而吃掉浅色线。

GP 是无光照层，**不需要灯** —— 所以预设不建灯，也不做实体化 / 平滑。

## 设计参数回存

全部参数 + 整张规则表存成**一份 JSON**（对象上的自定义属性 `gen_lsystem_design`），
「从对象回读参数」整组写回面板。规则是变长集合，塞进十几个自定义属性既难读也容易漏项；
JSON 字符串没有 `int` 属性那种 2³¹ 上限的坑。

## 边界与错误

| 情况 | 行为 |
|---|---|
| 括号不配对 / 参数不是数字 / 未知函数 | 算法层抛 `LSystemError`，算子收成面板上的「错误」一行，返回 `CANCELLED`，`dirty` 标回来 |
| 展开超过 40 万模块 | 同上，提示「把迭代数调小，或把规则写得更紧凑」 |
| 迭代数 > 16 | `Iterations` 的硬上限 + 算法层各一道校验 |
| 规则全被删光 | 生成时**兜底套回当前预设**（否则一张空图什么都看不见） |
| 还没生成就点「场景预设」/「从对象回读参数」 | 只报一句提示（`nothing to frame` / `no generated object found`）并返回 `CANCELLED`，**不抛异常** —— 取景要靠对象上记的包围盒，没有对象就没有可框的东西 |
| 对象被删掉后改参数 | 不凭空重建对象：自动更新发现没有生成物就直接返回，形状等下次点「生成」 |
| 左侧写了两个模块 | 报错「规则左侧只能写一个模块」 |
| 面板上选了已删掉的预设名 | 回读时跳过那一项，其它项照常读 |

## 模块

```text
lsystem.py   重写引擎：切词 / 规则 / 条件 / 表达式求值 / 并行重写（纯 Python）
turtle.py    解释器：符号 → 折线路径（纯 Python，自带 3×3 矩阵）
presets.py   十套预设 + 套用函数（纯 Python）
gp.py        GP v3 后端：笔划 / POINT 域属性 / 就地改宽改色
builder.py   重算入口：算路径 → 写笔划 → 记参数与包围盒
live.py      自动更新：防抖 timer
props.py     scene.gen_lsystem 参数组（含规则集合）+ 设计参数 JSON 回存
ops.py       生成 / 删除 / 回读 / 场景预设 / 应用预设 / 规则增删
ui.py        View3D > 侧栏 > L-System（含规则 UIList）
palette.py   项目色板副本（改色记得与 _shared/palette.py 同步）
viewport.py  视口着色检查副本（与其它插件同一份）
```

`lsystem.py` / `turtle.py` / `presets.py` 不 import bpy，可以脱离 Blender 单独跑：

```python
from gen_lsystem import presets, lsystem, turtle
p = presets.by_key("dragon")
rules = [lsystem.parse_rule(a, c, b) for a, b, c in p.rules]
sk = turtle.build(axiom=p.axiom, rules=rules, iterations=p.iterations,
                  angle=math.radians(p.angle), length=p.length, radius=p.radius)
print(sk.path_count, sk.point_count, sk.bounds())
```

## 局限与下一步

- **只画线，不填充**：`{` `}`（ABOP 的多边形 / 表面 pen）没有实现，叶子类预设因此不收录；
  要实体就自己加几何节点「笔划 → 曲线 → 扫管」（`gen_torus_knot` 有现成的节点组）；
- **没有「生长动画」**：参考实现按代生成一堆对象再逐帧隐藏，这里只出最终一代；
  要动画可以给「迭代」打关键帧，让它逐帧重算（代价是每帧重跑一遍）；
- **向重力只有 -Z 一档**：没有可调方向、没有逐个符号的向量运算；
- **表达式只认函数式写法**：`mul(l,0.6)` 好写，`l*0.6` 不支持（刻意为之，见上文）；
- **参数是浮点数**：没有字符串参数（`p(curve)` 这类只能当裸标识符看一眼，不参与运算）；
- **一笔最多几十万点会明显变慢**：GP 属性写入是线性的，几十万点以上建议降迭代数。
