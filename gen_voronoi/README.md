# 生成式 Voronoi（Gen Voronoi）

种子点 → 一层 Voronoi 单元，实时画成 Grease Pencil 笔划（扩展 id `gen_voronoi`，
Blender 5.2.2 实测）。

种子取自源物体：**网格的每个顶点**，或 **Grease Pencil 每一层的每个点**。后者是主用法 ——
在 GP 编辑模式里画点 / 拖点，单元**跟着实时重划**（实测 5.2.2：GP 编辑模式编辑的就是
同一份 drawing 数据，往 `position` 属性写字面量与真手拖一样都会触发
`depsgraph_update_post`）。输出是一层 GP：**每个单元一条闭合笔划**，逐点带 `cell_index`。

Voronoi 只在 **XY 平面**上划分，每个单元的 z 取自己种子的 z：把种子撒在起伏的表面上，
得到一层贴着它们高度的平面图案（参考实现 `voronoi_lab.py` 就是这么做）。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Gen Voronoi**；
2. 3D 视图侧栏出现 **Voronoi** 面板（F3 里也有 `gen_voronoi.*` 算子）；
3. 什么都不选直接点「生成」：会先撒一把 48 个抖动格点（GP 对象 `Voronoi Seeds`），
   再划分出 `Voronoi Cells` 对象。也可以自己选一个网格 / GP 当种子源；
4. 点面板上的编辑按钮（铅笔图标）进源物体的编辑模式，拖点 / 画新点 —— 松手前单元就变
   （GP 编辑模式里每动一次就重划一次，64 个点约 4 ms）；
5. 出图点「场景预设」：顶视正交相机、2048×2048、Standard 色彩、世界背景铺项目色板的
   `BACKGROUND`，并把 3D 视图的**背景从「主题」切成「世界」** —— Blender 默认是暗色主题，
   而单元线是墨玄，暗底上黑线几乎看不见；切过去正好是浅底配深线（实测世界色在 Solid 里
   显示为 `0.890 / 0.847 / 0.812`，就是 `#E4D9D0`）。

算子：`gen_voronoi.generate`（生成 / 更新）、`gen_voronoi.scatter`（撒点）、
`gen_voronoi.delete`、`gen_voronoi.edit_source`（进出源物体编辑模式）、
`gen_voronoi.sync_from_object`（从对象上记录的参数回读面板）、
`gen_voronoi.toggle_source_wire`（源网格在实体 / 线框之间切）、`gen_voronoi.setup_scene`。

## 面板参数

两档参数的生效方式不同：

| 分组 | 参数 | 说明 |
|---|---|---|
| 输入 | 种子源 | 网格的顶点，或 GP 每一层的每个点。源不能是生成物自己。读的是**求值后**的网格几何（修改器 / 几何节点生效），并按源物体的世界变换摆放 |
| 单元（改完自动重划） | 单元形状 | `直边` = 数学上原本的多边形；`二次` / `三次` = 把拐角磨圆 |
| | 间距 | 每个单元沿边往里缩多少（世界单位）：单元之间留出等宽的缝；0 = 紧贴不留缝 |
| | 最短边 | 只有 `三次` 用：比它短的边整条吃掉，两边中点直接连起来（种子很密时防碎边） |
| | 采样 | 曲线形状每段插多少点（2–64，默认 8）：GP 笔划是点链，点数决定圆滑度 |
| 气泡 | 气泡 | 把每个单元收进自己种子周围「气泡半径」的圆里 —— 单元互相拉开、形状变圆（肥皂泡） |
| | 气泡半径 | 一个单元离自己种子最远能到多少；调小 = 缩成小圆点，调大 = 慢慢长回互相贴合的完整单元 |
| 边界 | 边界 | `不裁` / `自动`（种子包围盒外扩 `边距` 倍对角线）/ `固定`（面板给的宽高，以原点为中心） |
| 外观（就地生效） | 线宽 / 线色 / 填充 / 填充色 / 填充浓度 | 只重写 GP 属性（`radius` / `vertex_color` / `fill_id` + `fill_color`），不重划单元。填充色是**预乘 alpha** 的（见下），浓度 1.0 才是原色 |
| 实时 | 实时 | 源物体一变就重划；关掉就只在点「生成」时重划 |

面板底部读数：单元数 / 笔划点数 / 耗时、源上的种子数、丢掉了几个单元（种子重合、
被边界裁光或内缩过头时这个数不为 0）、错误信息。

抬升与尺寸都是世界单位（不像 `gen_celtic` 那样按平均边长折算）：Voronoi 的尺度由种子
自己决定，换网格密度不用重调参数。

## 算法（`voronoi.py`，只 import `mathutils` / `numpy`）

```text
Delaunay 三角剖分（mathutils.geometry.delaunay_2d_cdt）
  → 每个三角形的外心 = 一个 Voronoi 顶点
  → 围着某个种子的外心按极角排序 = 这个种子的单元
```

* **垫包围盒**：种子的包围盒要往外垫 10 倍对角线。Delaunay 的**外部**三角形没有外心，
  不垫的话最外圈种子的单元不封闭；
* **重合种子**会被 Delaunay 合并（容差 `1e-5`），它们拿到同一个单元；
* **裁剪顺序**照参考实现：① 气泡半径收圆 → ② 组织边界 → ③ 沿边内缩 `间距`。
  内缩放最后，缝宽才处处相等；气泡模式下把边界按种子外扩一圈，圆才不会被远处的边界切平；
  严格模式（气泡关掉）则要求种子自己在框里，框外的单元整个不要；
* **圆形裁剪**是解析的（`clip_circle`）：一趟走完多边形，外侧那段折线换成按 `ARC_SEGMENTS`
  段折线化的圆弧。比「造正 48 边形再逐个半边裁」快一个量级 —— 实时更新全靠这一条；
* **内缩**照参考实现：每条边平移后求相邻边交点，缩没了就丢掉这个单元。判「缩没了」不能只看
  面积 —— 缩过内切半径后多边形会整个翻面，相邻边的交点又拼出一个面积极小、「看着还在」的
  假单元（实测：缩 0.2 判掉了，缩 0.45 反而又活了）。所以先比一次「种子到最近边的距离」
  （`_inradius`），过了这条线直接丢；两条偏移边的交点也按**无限长直线**求，因为内缩后交点
  常常落在原来那条线段之外；
* **曲线形状**（参考实现的二次 / 三次两档）：每个拐点一段曲线，端点落在相邻边的中点，
  `三次` 会先滤掉短于 `最短边` 的边。采样是把三次贝塞尔按 `resolution` 求值（numpy 一次算完，
  权重按分辨率缓存），再把相邻段重复的端点剔掉 —— 不去掉的话每条笔划都多一串零长度段。

## 几何后端（`gp.py`）

写进 drawing 的属性（跟参考实现的 `cell_index` 同名，方便互通）：

```text
POINT  position      float3   点坐标（GP 自带）
POINT  radius        float    线宽
POINT  opacity       float    不透明度
POINT  vertex_color  color    线色（线性存）
POINT  cell_index    int      这个点属于第几个种子
CURVE  fill_id       int      非 0 = 填充，逐格一个 id
CURVE  fill_color    color    填充色
CURVE  cyclic                每条笔划闭合
```

**Blender 5.2 上必读的四条**（都是实测结论，改动前先看）：

* 新图层 `use_lights` 默认 `True`，没有灯时颜色只剩约四分之一亮度 —— 本后端一律建
  **无光照层**；
* 不给 `miter_angle` 属性：缺它就是**圆角**连接（有它才是斜接），圆润的轮廓不会崩尖角；
* `add_strokes` / `remove_strokes` 是**结构性**改动，改完手里那个 `drawing` 指针就失效，
  再往上 `foreach_set` 会报 `internal error setting the array` —— 必须重新
  `layer.frames[...].drawing` 取一次；
* `foreach_set` 长度对不上时 Blender 只报一句 `internal error setting the array`，不说是哪条
  属性，所以每次写之前按领域长度对一遍（`_ensure`）。

**图层复用**：生成对象上只有一层 `Cells`，每轮只把笔划清掉重写，图层本身不重建 ——
实时更新时不会每帧重建数据块，编辑模式里也不会打断。图层固定只有一帧，并且每轮挪到
当前帧上（GP 只显示「不晚于当前帧的最后一帧」）。

**颜色不用材质**：`vertex_color` 就够，`build_object` 还会 `materials.clear()`。因此 3D 视图
Solid 模式得把「着色 → 颜色」切到 Attribute 才看得见 —— 生成算子会顺手切一次（`viewport.py`，
与 `gen_torus_knot` 逐字相同）。

**填充色是预乘 alpha 的**（5.2.2 实测，逐像素采样）：`fill_color` 的 alpha 是**乘在颜色上**，
不是「透出背景」。Standard 视图变换下，绢白 `SILK` 实测：alpha 1.0 → sRGB `0.957 / 0.941 /
0.918`（就是原色），0.7 → `0.816 / 0.804 / 0.780`，0.4 → `0.635 / 0.624 / 0.608` ——
**越小越暗**，背景（画布底 `0.894 / 0.851 / 0.816`）从不透出来。所以面板上这一项叫「填充浓度」，
默认配浅色（绢白 0.6）当淡底用；想要成片的暖色就选赭石、把浓度推到 1.0。

## 实时更新（`live.py`）

两段式：`depsgraph_update_post` 处理器只做**廉价判断**（实时开关、源物体类型、生成对象在不在、
种子数过不过上限），通过就往 timer 里排一次「立刻执行」；真正的划分在 timer 里跑，走
`build.apply`（先比指纹，都没变就直接返回）。

**为什么不在处理器里划**（教训来自 `gen_celtic`）：撤销 / 重做时 Blender 正在换一批数据块，
处理器如果此时往生成对象里写几何（`build_object` 开头就是把笔划全删了重建），等于把数据
从它脚下抽走。挪进 timer 之后，写操作一定发生在求值 / 撤销恢复之后。

**两份指纹**：种子指纹（`seeds.geometry_key`，crc32 over 坐标 + 物体变换）管「源几何变没变」；
参数指纹（`build.params_key`）管「参数变没变」—— 参数一动种子一点没动，只靠前者会漏掉重划。
两者都只存 31 位：自定义属性里的整数是 C 的 `int`，写 2³² 以上会抛
`Python int too large to convert to C int`（实测）。

**GP 编辑模式**（实测 5.2.2）：

* 往 `layers[...].frames[...].drawing.attributes['position']` 写值，编辑模式里当场生效，
  退出编辑模式也还在 —— 编辑的就是同一份 drawing，不存在「另一份编辑数据」；
* 选中并 `bpy.ops.transform.translate(...)` 移动点，坐标会写进同一份 drawing，
  并且 `depsgraph_update_post` 照常触发。所以拖点、画新点都能实时抓到；
* 网格编辑模式则相反：`obj.data` 是进编辑模式那一刻的旧坐标，求值网格在编辑模式里是空的，
  正在拖的坐标只有 `bmesh.from_edit_mesh(obj.data)` 拿得到（`seeds._mesh_points` 里分了两条路）。

`SEED_LIMIT`（2000）是保护：几百个种子整份重划不到 20 ms，拖点很舒服；1600 个种子已经
要 60 ms（直边）/ 140 ms（曲线），超过 2000 就跳过实时更新（面板亮一条提示），
手动点「生成」照常工作。

## 实测

Blender 5.2.2，同一台机；气泡开、边界自动、间距 0、采样 8。64 个种子撒在 4×4，
更多种子撒在 8×8 且气泡半径相应放大（点数会随撒点的随机抖动略有出入）：

| 种子 | 形状 | 单元 | 笔划点 | 整份重划 |
|---|---|---|---|---|
| 64 | 直边 | 64 | 686 | **3.4 ms** |
| 64 | 三次（采样 8） | 64 | 4,802 | **7.4 ms** |
| 400 | 直边 | 400 | 3,197 | **17 ms** |
| 400 | 三次（采样 8） | 400 | 22,379 | **38 ms** |
| 900 | 直边 | 900 | 6,395 | **35 ms** |
| 900 | 三次（采样 8） | 900 | 44,765 | **82 ms** |
| 1600 | 直边 | 1600 | 10,793 | **60 ms** |
| 1600 | 三次（采样 8） | 1600 | 75,551 | **141 ms** |

1600 个种子上逐项开销：

| 动作 | 耗时 |
|---|---|
| 处理器本身（`on_update`：判断 + 排 timer，含数种子） | **9.7 µs** |
| `seeds.count`（数种子，GP 逐层读属性长度） | **6.0 µs** |
| timer 里空转一次（crc32 指纹，`apply` 早退） | **0.28 ms** |
| Delaunay + 外心 + 极角排序（`build_cells`） | **12.7 ms** |
| 裁剪 / 内缩 / 采样（`cells_from_points`，直边） | **55 ms** |

开销几乎全在逐单元的 Python 多边形运算上（Delaunay 只占两成）。所以「能不能实时」取决于
**种子多少**；曲线形状因为点数暴涨（采样 × 拐点数）比直边慢一倍多。

## 模块

```
voronoi.py  算法层：Delaunay → 外心 → 单元；圆形 / 矩形裁剪、内缩、曲线采样（不 import bpy）
seeds.py    种子提取：网格 / GP → 世界坐标点列 + crc32 指纹（编辑模式里也是活的）
gp.py       GP v3 后端：笔划 / 顶点色 / fill_id / cell_index / 原地改线宽线色填充
build.py    生成入口：种子 → 单元 → 对象（算子与实时处理器走同一条路）
props.py    scene.gen_voronoi 参数组 + 对象上回存的设计参数
live.py     实时更新：depsgraph_update_post 只判断，划分推迟到 timer 里跑
ops.py      生成 / 撒点 / 删除 / 编辑源 / 回读参数 / 场景预设
ui.py       View3D > 侧栏 > Voronoi
viewport.py Solid 模式着色检查（与 gen_torus_knot 逐字相同）
palette.py  项目色板副本（改色记得与 _shared/palette.py 同步）
```

`voronoi.py` 不 import bpy，只有 Delaunay 那一步用 Blender 自带的 `mathutils.geometry`，
可以脱离界面单独跑算法：`build_cells(points)` 吃 `(n, 3)` 的坐标，返回与种子序号对齐的
多边形列表（拿不到的位子是 `None`）。

## 局限与下一步

* **只有二维划分**：种子投影到世界 XY 平面，z 只用来定高度。想要贴曲面的三维 Voronoi
  得改成「切平面 + 逐单元投影」，现在没做；
* **单元本身不带填充的洞**：填充是「整格一个色块」，没有做「只在环里填、中间留空」的
  环状填充（参考实现也没有）；
* **曲线形状不会真的绕开邻居**：拐角磨圆让单元在三个单元交汇处留出小三角缝，这是圆角化
  的必然结果，不是 bug；
* **重合种子**被合并成一个单元（Delaunay 的容差），面板上看到的种子数会比单元数多；
* 实时更新是「整份重划」，没有做增量：几千个种子时请关掉实时、手动点「生成」；
* 生成物**不要进编辑模式改**：每轮重划会把笔划全删了重写（数据层面是安全的，实测在编辑
  模式里重划、再退出编辑模式都不出问题，但你在编辑模式里做的改动会丢）。要编辑的是**种子源**。
