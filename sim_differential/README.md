# 差分生长（Sim Differential）

一条闭合折线在**平滑 + 斥力 + 培养皿边界**下逐帧弛豫，每帧再把最长的几条边切开：弧长一直
涨、外围不许扩，多出来的长度只能自己打褶 —— 差分生长（differential growth）的脑回 / 珊瑚
图案就这么长出来。输出是**一笔闭合的 Grease Pencil 笔划**（扩展 id `sim_differential`，
Blender 5.2.2 实测）。

计算后端两档，代码同一套约束：

| 后端 | 依赖 | 1000 节点 × 8 子步 | 说明 |
|---|---|---|---|
| **Taichi GPU**（默认「自动」时优先） | 需要在 Blender 的 Python 里 `import taichi` | **约 8 ms/帧** | 斥力 O(n²) 暴力扫描（GPU 上便宜） |
| **NumPy**（回退） | 只要 Blender 自带 numpy | 约 14 ms/帧 | 斥力走空间哈希，几千节点也能实时 |

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Sim Differential**；
2. 3D 视图侧栏出现 **Differential** 面板（F3 里也有 `sim_differential.*` 算子）；
3. 点「构建」——建求解器、一笔闭合笔划、正俯视正交相机，画面停在初始圆环；
4. 播放：环先被均匀细分，然后开始打褶，节点数一路涨到「节点上限」；
5. 出图点「场景预设」：1600×1000、Standard 色彩、世界背景铺项目色板的 `BACKGROUND`，
   并把时间轴设成 **24 fps**（生长速率是按 24 fps 调的，见下）。

算子：`sim_differential.build`、`sim_differential.reset`（只回到初始圆环，不重建笔划）、
`sim_differential.step`（时间轴 +1 帧）、`sim_differential.setup_scene`、
`sim_differential.fix_viewport`、`sim_differential.delete`。

颜色只写在 `vertex_color` 顶点属性里，Solid 视图默认的「着色颜色 = Material」读的是材质
单色，线会是黑的 —— 所以「构建」「场景预设」会顺手把 Solid 视图切成 **Attribute**；播放中
切回 Material 时面板会亮一条红色提示，点 `sim_differential.fix_viewport` 即可。

## 面板参数

| 分组 | 参数 | 说明 |
|---|---|---|
| 初始条件 | 初始节点数 / 初始半径 | 缺省 60 个节点、半径 1：节点间距 ≈ 斥力半径，起始就接近平衡，序列开头不会先甩一下 |
| | 初始抖动 / 随机种子 | 完美的圆在对称力场里只会均匀膨胀，必须有扰动才打褶；同一个种子重建出同一个形状 |
| | 节点上限 / 后端 | 节点上限同时是笔划的**定长容量**（GP 拓扑不能逐帧变），改它要重建 |
| 物理 | 斥力半径 R / 分裂距离 | 图案尺度的总开关：R 越大折痕越粗；分裂距离远小于 R 时生长最快 |
| | 斥力权重 / 平滑权重 | 斥力撑开节点、平滑往相邻中点收；两者配比决定折痕是"硬"还是"圆" |
| | 边界半径 / 边界刚性 | 培养皿：0 = 不设边界（曲线一直往外长） |
| | 生长速率 / 惯性 | 生长速率 = 每帧切几条边（**生长速度**）；惯性 = 速度低通（见「顺滑度」） |
| | 子步 / 切口抖动 | 子步 = 每帧的弛豫次数；切口抖动 = 新节点相对弦中点的随机偏移 |
| | 锁定到 Z = 0 | 严格 2D；关掉就是 3D 生长（初始抖动的 Z 分量会让曲线自己绕出去） |
| 外观 | 配色 / 线宽 / 单色 | 曲率（折痕）、拉伸（下一帧会长在哪）、单色 |

三档参数的生效方式不同：

- **物理 / 子步**：下一帧就生效，不重建；
- **外观**：当场重刷当前帧（不推进物理）；
- **初始条件 / 节点上限 / 后端**：进签名，下一帧由 handler 自动重建（也可以手动点「构建」）。

## 物理模型

```
Δᵢ = w_s·(½(pᵢ₋₁ + pᵢ₊₁) − pᵢ)                      平滑（拉普拉斯）
   + w_r·Σ_{|pᵢ−pⱼ|<R} (pᵢ−pⱼ)/|pᵢ−pⱼ|·(R − |pᵢ−pⱼ|)   斥力
   + w_b·(−p̂ᵢ)·max(0, |pᵢ| − R_b)                      培养皿边界
vᵢ ← vᵢ·damping + Δᵢ·(1 − damping)                  速度低通（惯性，damping = 0 即纯 PBD）
pᵢ ← pᵢ + clamp(vᵢ, 0.25·R)                         单步位移上限
```

每帧结尾做一次拓扑生长：把长于 `split_dist` 的边按长度降序切开（每条边插一个弦中点，最多
`growth_rate` 条，节点数不超过容量）。斥力把相邻节点推开 → 边长被重新拉长 → 下一帧又被切开
→ 弧长不断增长；边界不许整体外扩，多出来的长度只能打褶，折痕越挤越密。

## 顺滑度（实测）

- **稳态**每帧节点位移只有边长的 **4%~5%**（1400 px 渲染里约 1 px）：不是"线条在抖"；
- **开头**才是能看出跳的地方：24 个初始节点时首帧平均位移 0.030（≈ 3/4 个边长、约 14 px/帧），
  改成 60 个初始节点后降到 0.0125，而且第 1 帧就是干净的圆环；
- **时间轴 fps 决定观感**：生长速率是"每帧切几条边"，同一个 8 在 60 fps 下就是 480 节点/秒、
  图案 3 秒长完，看着像跳过去。所以「场景预设」把 fps 设成 24；坚持 60 fps 就把生长速率调到 3~4；
- 每帧开销 8 ms（Taichi）/ 14 ms（NumPy），60 fps 的预算是 16.6 ms —— NumPy 后端 + 60 fps 会掉帧。

两条**试过但没采用**的做法（都会毁掉图案的均匀性，留个记录）：

| 尝试 | 结果 |
|---|---|
| 把每帧的分裂摊到各子步之间 | 图案锁死在单侧（120 帧后一半周向是光滑圆弧）：切完一刀若立刻弛豫，新节点的子边又被斥力拉长、又成了最长边，分裂集中到同一片 |
| 惯性/速度低通 0.5~0.8 | 轨迹确实更连贯（加速度/速度比 0.90 → 0.62），但图案同样偏科；所以做成可选项、缺省 0 |

## 数据接口

笔划上的属性（几何节点 / 着色器可按名字取）：

| 属性 | 类型 / 域 | 含义 |
|---|---|---|
| `position` | FLOAT_VECTOR / POINT | 节点位置 |
| `radius` | FLOAT / POINT | 逐点笔划半径（空槽位为 0） |
| `opacity` | FLOAT / POINT | 逐点不透明度（空槽位为 0） |
| `vertex_color` | FLOAT_COLOR / POINT | 线性 RGBA |
| `stretch` | FLOAT / POINT | 相邻边长均值 / `split_dist`（1.0 = 马上要被切开） |
| `curvature` | FLOAT / POINT | 逐点转角 / π（0 = 直，1 = 完全折回） |

**笔划是定长的**：GP 的拓扑不能逐帧变，所以笔划永远铺到「节点上限」个点，真正画出来的只有
前 `n` 个 —— 其余点位置塌在末点上（零长度线段画不出东西），半径与不透明度都是 0。于是节点数
每帧都在涨也不用重建图层，逐帧只有几次 `foreach_set`。

## 模块

```
solver.py        位置约束 + 拓扑分裂求解器（纯 NumPy，斥力走空间哈希）+ 工厂 create()  （不 import bpy）
taichi_solver.py 同一套约束的 Taichi GPU kernel（可选后端）
colour.py        曲率 / 拉伸 → 逐点颜色（只用项目色板）                          （不 import bpy）
gp.py            GP v3 后端：定长笔划缓冲、逐点半径 / 不透明度、逐帧重刷
sim.py           frame_change_pre handler：推进生长 → 写笔划
scene.py         世界底色 / 正俯视正交相机 / 渲染设置
viewport.py      Solid 视图的着色颜色检查（颜色写在属性里，Material 着色下是黑线）
props.py         scene.sim_differential 参数组
ops.py           构建、重置、步进、场景预设、视口修正、删除
ui.py            View3D > 侧栏 > Differential
```

`solver.py` / `colour.py` 可以脱离 Blender 单独跑（系统 Python + numpy）：

```powershell
python -c "from sim_differential import solver; g=solver.create(); [g.step(8) for _ in range(120)]; print(g.node_count)"
```

## 与参考实现的差别

参考实现 `.ref/differential_growth.py`（Taichi、直接改网格顶点与边）：方程、参数语义、培养皿
边界一致，差别在工程结构：

| | 参考脚本 | 本扩展 |
|---|---|---|
| 组织方式 | 单文件、场景属性 + 网格写顶点 | 扩展包：算法层与 Blender 层分开，可单独测试 |
| 后端 | 只有 Taichi（O(n²) 斥力） | Taichi GPU 优先；NumPy 回退用空间哈希，CPU 上也实时 |
| 结果落到场景 | 网格顶点 + 边（折线） | 一笔闭合 GP 笔划（可直接渲染 / 加效果器），定长缓冲容纳逐帧变化的节点数 |
| 参数 | 场景属性组 + 重建靠 hander 里的分支 | 三档语义（物理 / 外观 / 重建）分明，并带读数 |
| 顺滑度 | 纯位置约束、分裂攒到帧尾、中点带 0.1·split_dist 噪声 | 同上（噪声保留），另加可选的速度低通、初始节点数按斥力半径给足 |

## 局限与下一步

- **没有烘焙**：动画靠 `frame_change_pre` 实时算，回退会重置（`target < 当前帧` 即从初始圆环
  重算，每帧 `substeps` 个子步）；
- 图案是**混沌**的：同一个种子可复现，但换种子 / 换后端（浮点顺序不同）会长成不同形状，
  有时会偏向单侧（脑回状），这属于差分生长本身的特性；
- 节点上限到顶后停止分裂，画面只剩弛豫，需要更大更密的图案就调高上限（同时变慢）；
- 编辑模式下 handler 会跳过（点列由 GP 编辑器掌管，`foreach_set` 会被丢掉），退出编辑即恢复。
