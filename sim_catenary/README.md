# 铁环相扣悬链线（Sim Catenary）

XPBD 物理模拟 + Grease Pencil 线稿（扩展 id `sim_catenary`，Blender 5.2.2 实测）。

一串**相扣的铁环**从等高的拱形松手落下，在重力与杆约束下摆成悬链线；每一环是一个
GP 笔划，逐帧由物理改写控制点（默认**贝塞尔**：跑道形 6 个控制点 + 手柄，形状误差
0.017 mm），颜色按链的张力走项目色板。

环的截面按真实链条做：**「操场跑道」形**（两段直边 + 两个半圆端），长轴永远沿链方向，
偶环与奇环只差一个绕链轴的 90° 翻转。直段长度是面板参数（0 = 退回正圆）。

物理模型与几何结论沿用参考实现 `.ref/ring_catenary`（那边是「控制网格 + 几何节点
实例化 torus」），差别在于：

| | `.ref/ring_catenary` | 本扩展 |
|---|---|---|
| 链条的表达 | 控制网格（环心）+ GN 实例化 mesh 圆环 | **GP 笔划**：一环一整圈 3D 曲线（跑道形，默认贝塞尔） |
| 求解器 | Taichi（CUDA/CPU）kernel | **纯 NumPy**，矢量化的奇偶红黑投影 |
| 依赖 | 需要把 taichi 装进 Blender 的 modules | 只用 Blender 自带的 numpy（扩展自包含） |
| 结果落到文件 | 播放/渲染时实时驱动 | 同上（**没有烘焙**，见「局限」） |

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Sim Catenary**；
2. 3D 视图侧栏出现 **Catenary** 面板（F3 里也有 `sim_catenary.*` 算子）；
3. 点「构建」——建 GP 对象、求解器、正交相机，画面停在初始的上拱形态；
4. 播放（或拖时间轴）即实时演算：链从拱形落到悬链线，环全程相扣；
5. 出图点「场景预设」：1600×1000 正交相机、Standard 色彩、GP 抗锯齿 16、
   世界背景铺项目色板的 `BACKGROUND`。

相扣的遮挡由 GP 的 3D 深度排序（`stroke_depth_order = '3D'`）负责 —— 环是真正的 3D
曲线，靠前的会把靠后的一段切掉，切口是笔划自身的圆头轮廓（见「遮挡交给 3D 深度」）。
需要更"实"的轮廓（描边/管壁）时，建议把 GP 转成 mesh 再补几何（例如几何节点里
`Grease Pencil to Curve` + `Curve to Mesh`），那样才有真正的体积与遮挡，而不是屏幕空间描边。

「构建」与「场景预设」都会顺手把还停在 **Solid + 着色颜色 = Material** 的 3D 视图切成
**Attribute（顶点色）** —— 颜色只写在 `vertex_color` 属性里，Material 着色下画出来是全黑
（见 `viewport.py`）。播放中要是又切回 Material，面板会亮一条红色提示，点一下
`sim_catenary.fix_viewport` 即可；材质预览 / 渲染模式本来就看得到颜色，不动它们。

算子：`sim_catenary.build`、`sim_catenary.reset`、`sim_catenary.setup_scene`、
`sim_catenary.fix_viewport`、`sim_catenary.delete`。

## 面板参数

三档参数的生效方式不同，面板上也分开摆：

| 分组 | 参数 | 说明 |
|---|---|---|
| 运动 | 重力 | 9.81 地球 / 1.62 月球 / 3.71 火星 / 0 失重；**只影响下落快慢与张力**，不影响稳态形状 |
| | 环境阻力 | 0~100%：0 = 自由落体长摆，15% 默认，100 ≈ 匀速下落。整条滑杆都是有效区间 |
| | 弹性 | 0~100%：0 = 刚杆（与理论离散链最吻合），100% 稳态下垂多出约 0.39 m |
| | 折角上限 | 30~180°，关节处允许的最大折角。真实链环有体积、不可能对折；**180 = 不限制**（锚点那根杆会整个甩翻折回来，环看着"飞出去"）。默认 110 |
| 精度 | 子步 / 迭代 | 每帧 10 子步 × 每子步 12 次杆约束投影（实测 12 次与 20 次的稳态 RMSE 差在小数点后第四位） |
| 几何 | 环数 / 跨度 A | 环数须奇数（最低点是一个环心）；跨度是悬链线特征长度 `a` |
| | 环主半径 R / 环管半径 r | R = 端头半径，r = 管的粗细。**相扣节距 = L + 2(R−r)**（孔的内长，不是外长）；r 不决定笔划粗细，那是「线宽」 |
| | 直段长度 L | 0 = 正圆；默认 0.06（= R）就是真实链环的比例：外长 0.18 × 宽 0.12，相邻环端头重叠 2r |
| | 笔划 / 段数 | 「贝塞尔」跑道形 6 个控制点（606 个/101 环）；「折线」每环 24 点（2424 个）。切换类型时段数自动换成推荐值（4 / 24） |
| 外观 | 线宽 / 脊线 | 笔划半径（世界单位，线宽是它的 2 倍）；脊线是沿环心的辅助折线，默认关 |
| | 配色 | 「张力」= 石青 → 赭石 → 朱砂；「单色」= 面板给的颜色（默认墨玄） |
| | 张力平滑 / 平滑系数 | 对张力做指数滑动平均，只影响热力图观感 |

- **物理参数**：下一帧就生效，不重建；
- **外观参数**：当场重刷当前帧（不推进物理）；
- **几何参数**：改完置 `待重建`，下一帧由 handler 自动重建（也可以手动点「重建」）。

右下角「读数」实时显示：当前帧、最低点 z、RMSE vs 理论离散链、相扣对数、张力峰值。

## 物理模型

* 连续悬链线 `y = a·cosh(x/a) − a`；离散链平衡 `tan θ_i = i·l/a`（从最低点往上第 i 段），
  逐段递推节点 —— `chain.arch_chain()` 同时给出**理论悬链线**与它关于端点高度的**镜像拱形**
  （等长、端点相同），后者就是模拟的初始状态：从上拱落到悬链线，全程保持相扣；
* 求解器的**节点 = 相邻两环共享的关节**（比环数多 1 个），相邻节点一根杆约束
  （长度 = 相扣节距），两端节点逆质量为 0（固定锚点）；环心与环的长轴方向由关节算出
  （`chain.chain_links` → `link_axes`）；
* 每子步：重力预测 → `iters` 次杆约束投影（+ 折角下限）→ 速度/位置更新 → 端点钳位；
  `lambda` 每子步清零，子步末的累积值就是约束乘子，张力 `T = max(λ,0)/dt²`（链只能拉不能推）；
* **折角下限**（`bend_limit`）：`|p[i+2] − p[i]| ≥ 2·l·cos(φ_max/2)` 表达"关节最多折 φ_max"，
  按 `i mod 3` 分三批投影（步长 2 的约束跨过中间节点，三批才互不共享节点）。没有它，
  锚点那根杆会绕锚点甩翻 180° 折回来压在邻居身上 —— 这就是"环飞出去"的真正原因；
* 杆约束按**奇偶红黑**分两批向量化：同批的杆不共享节点，可以一次性广播修正而不互相竞争。

实测（101 环、10 子步、60fps、7.5 帧/秒的物理时间尺度，系统 Python）：

| 迭代 | 600 帧稳态 RMSE vs 理论 | 求解耗时 |
|---|---|---|
| 8 | 0.00395 m | 1.8 ms/帧 |
| 12 | 0.00329 m | 2.7 ms/帧 |
| 20 | 0.00292 m | 4.4 ms/帧 |
| 30 | 0.00281 m | 6.5 ms/帧 |

Blender 里的整链路（推进 + 环几何 + 写 GP，24fps，101 环；空载、每档 3 轮取中位）：

| 笔划 | 每环控制点 | 笔划数 / 点数 | 每帧 |
|---|---|---|---|
| 贝塞尔（默认，跑道形） | 6 | 101 / 606 | **4.7 ms** |
| 折线 24 点 | 24 | 101 / 2424 | **4.9 ms** |

时间几乎全在求解器；写 GP 很便宜——点数翻 4 倍只多 0.2 ms。"用贝塞尔"省不出多少时间，
它的价值是**形状是真曲线**（跑道形+正圆都是精确的）、控制点少 4 倍（文件小、编辑模式下
好调）。重建一次约 3~10 ms —— NumPy 没有 kernel 要编译，改环数不用等。

> 跑道形的节距是 `L + 2(R−r)` = 0.14 m，所以 101 环的链比正圆版长 75%，相机的取景
> 范围也跟着变（构建/场景预设会自动按新的跨度重算）。

## 环的轮廓：跑道形

真实链环不是正圆，而是「操场跑道」：两段直边 + 两个半圆端，长轴沿链方向。几何上是把
`直段 L` 接在两个半径为 `R` 的半圆之间（`L = 0` 时退化成正圆）：

* **贝塞尔**：6 个控制点就够 —— 每个半圆端 2 段 90°（端头一个控制点），上下直边各 1 段；
  直边与半圆在 `(±L/2, ±R)` 相切，同一个控制点两侧的手柄同向但长度不同
  （直边 = L/3，弧 = `4/3·tan(22.5°)·R` = 0.5523R）。实测最大形状误差 **0.017 mm**
  （0.028% R），比 24 点折线还准；
* **折线**：沿轮廓按弧长均匀取 `segments` 个点（24 点误差 0.0005 mm）。

| | 贝塞尔 6 点（默认） | 折线 24 点 |
|---|---|---|
| 控制点数（101 环） | **606** | 2424 |
| 形状误差 | 0.017 mm | 0.0005 mm |
| 整链路 | 4.7 ms/帧 | 4.9 ms/帧（差在写 GP，几乎被求解器淹掉） |

**相扣节距 = 孔的内长 = `L + 2(R−r)`**。默认参数下节距 0.14 m，而环的外长
`L + 2R` = 0.18 m，两者差正好 `2r` —— 相邻环的管在端头刚好相切，也就是真链条的手感
（不是"悬空相扣"，而是每个环的端头压在邻居的端头上）。

实现要点：每环的基底是 `(切线 t, 侧向 v = 轴 × t)`（**长轴永远是 t**），2D 轮廓
`(s, t)` 通过 `s·t̂ + t·v̂` 映射到 3D；贝塞尔手柄是同一映射下的常量偏移。所以
**换环数、换半径、换姿态都不需要重算任何东西**，逐帧照着新的环心与轴重摆一遍即可。

## 环的姿态与相扣

环面轴（环所在平面的法线）奇偶交错，两者都垂直于局部切线；**长轴两端都沿链方向**：

* **偶环**：轴 = `+Y` → 环面 = 链平面 XZ，从 -Y 看过去是一个完整的跑道形；
* **奇环**：轴 = 链平面内的法线 `(-tz, 0, tx)` → 环面 = `span{切线, Y}`，从 -Y 看过去
  是**一条边对边的直线**（长度 `L + 2R`），正好从偶环的孔里穿过去。

`chain.interlock_stats()` 逐对校验：取环 B 的**两个端头**里离环 A 更近的那个，看它是否
落在 A 的孔里（孔 = 端头半径 `R−r` 的跑道形区域），两边都得穿过去。101 环默认参数下
**100/100 相扣**，面板直接显示这个读数。

> 读数按帧刷新（每 6 帧量一次）。链刚松手的那十几帧、或者弯得很狠（连续折角 > 100°）时
> 读数会掉几对，那是端头刚好贴着孔边；末态总是 100/100。真正"脱钩"的样子是读数掉一半
> 以上并一路掉下去，那时才该去看锚点和折角上限。

### 遮挡交给 3D 深度，几何不做任何"断开"

环是**真的 3D 曲线**，一层里一个环就是一整圈连续笔划。`gp.write` 把
`stroke_depth_order` 设成 **`'3D'`**（"3D Location"），GP 按 3D 位置**逐像素**比深度：
靠前的环用自己的笔划轮廓把靠后的环切掉一段，切口就是笔划的圆头形状 ——
不需要拆半圆、不需要按视角排绘制顺序、也不会有手工剪裁的接缝，换透视/斜视角同样成立。

实测（800×500，两个 3D 环交叉）：`'3D'` 下靠前的环把后者的线切开约一个线宽，
`'2D'` 下则完全按存储顺序压（同色时读不出前后）。

### 为什么不在这里做"描边/轮廓"

试过两条屏幕空间的路线，结论是**不值得**：

1. 手工把笔划"断开"（在交叉处切缺口）——切口是直的、会和相邻笔划撞出接缝；
2. 给每个环套一圈更粗的 case 描边 —— case 与墨线共面在 `'3D'` 排序下是深度平局，实测会被
   啃成条纹或整圈被吃掉；就算靠"沿视线后退"避开平局，GP 仍然是深度测试渲染：画出来的
   描边**无论如何都会挡住后面的笔划**，所以不透明度只改变描边自己的色调，不会让缺口变软。

真要"实"的轮廓，正确做法是离开屏幕空间：把 GP 转成 mesh，做成有体积的管/环，让几何自己
产生遮挡（几何节点里 `Grease Pencil to Curve` → `Curve to Mesh` 一轮即可）。本扩展只负责
物理与笔划表达，不掺这一层。

## GP v3 实测结论（改动前先读）

* **点坐标是 3D**：`position` 是 `FLOAT_VECTOR`（POINT 域），z 原样保留，所以环面可以任意
  朝向 —— 轴为 +Y 的环绕成圆、轴为 Z 的环从 -Y 看是一条线；
* **`stroke_depth_order`**（数据块属性）只有 `'2D'`（按层/存储顺序）和 `'3D'`
  （"3D Location"）。`'3D'` 是**逐像素比深度**：交叉的笔划由几何自己分出前后，切口是
  笔划的圆头轮廓。本扩展用 `'3D'`，所以环之间不需要任何手工排序或剪裁；
* **颜色是线性**：`vertex_color` 按线性存，sRGB 必须先过 `palette.srgb_to_linear`，
  否则整体发灰；不用材质（`gp.write` 会清空材质槽）；
* **Solid 模式的着色颜色**：颜色既然只写在属性里，3D 视图默认的
  `shading.color_type = 'MATERIAL'` 就无材质可显示 —— Solid 里是**全黑**。
  所以「构建」「场景预设」会先检查并切成 `VERTEX`（界面叫 *Attribute*），
  面板也会在还停在 Material 时给一条可点的提示（`viewport.py`）；
* **`layer.use_lights` 新建时默认 `True`**，无灯时颜色只剩约 25% 亮度；本后端一律
  `use_lights = False`，线稿所见即所得；
* **`foreach_set` 的长度必须精确**：建属性时顺手塞"默认值 × 点数"很容易算错分量数
  （`FLOAT_COLOR` 是 4、`FLOAT_VECTOR` 是 3），报的是
  `RuntimeError: internal error setting the array`。本后端的做法是建完属性直接写满整条缓冲；
* **改完点列要 `drawing.tag_positions_changed()`**，否则视口拿到的是旧点列
  （实测：depsgraph 里的几何不跟着变）；
* **图层帧号放在场景起始帧上**：GP 图层帧之间是"保持"，所以一帧 drawing 就能覆盖整段动画，
  不用逐帧建 drawing；
* **曲线类型**：`curve_type` 是 CURVE 域的 `INT8` 属性，**1 = POLY、2 = BEZIER**
  （没写过就是 0）。改类型用 `drawing.set_types(type=...)`，而且 `type` **必须是关键字
  参数**（位置传参会报 required parameter to be a keyword argument）。转换类型**不改
  点数**：贝塞尔手柄是另存的 `handle_left` / `handle_right`（POINT 域 `FLOAT_VECTOR`，
  3D 坐标），`handle_type_left/right` 缺省 0 = 自由手柄（按给定坐标走）。
  Blender 只给了 `point.handle_left.position` 的代理、类型不可写，但直接写属性效果一样。

## 局限与下一步

* **没有烘焙**：动画是靠 `frame_change_pre` 实时算的，所以渲染动画时帧要按顺序走
  （Blender 默认如此），且**回退会重置**整个模拟（`target < 当前帧` 即从拱形重算）。
  要可撤销/可导出的成品，下一步可以逐帧写 GP 图层帧（一帧一个 drawing）当烘焙缓存；
* 端点是硬固定的，还没有"拖动锚点"；
* 环与环之间只有杆约束 + 折角下限，没有真实接触/碰撞（与参考实现的结论一致：原生凸包
  碰撞不支持相扣，真实"穿过对方环孔"的凹形接触需要自定义约束）。折角下限是"关节最多
  折几度"的几何近似，不区分弯折方向，也不管环的粗细；它作用在关节上，所以**卡死在锚点
  两侧的第一、二个关节**，长链的观感由 `bend_limit` 决定，默认 110° 是实测的折中（90°
  太小、链看着硬；180° 锚点那根杆会翻过去）。
