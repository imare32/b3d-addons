# 曲面生命游戏（Sim Game of Life）

Conway 生命游戏跑在**网格的面上**：一个面就是一个细胞，至少共用一个顶点的面互为邻居，
逐帧推进代数并把结果实时画成面颜色（扩展 id `sim_game_of_life`，Blender 5.2.2 实测）。
几何一个顶点都不动 —— 插件只往目标网格上写 `alive` / `age` / `color` 三个属性，
所以任何网格都能直接拿来跑，也随时可以拿掉。

**但不是任何网格都好看**：康威规则默认「每个细胞 8 个邻居、每个细胞一样大」，而这只有
四边形、且面大小均匀的网格才满足。低模猴头那种 500 个面的网格上，一个细胞就是眼睛 /
耳朵那么大一块；三角面有 11~12 个邻居、边界上的面只有 3~5 个，同一条规则在不同面上会
跑出不同的"方言"。实测数据与做法见[什么网格上才好看](#什么网格上才好看实测)。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Sim Game of Life**；
2. 3D 视图侧栏出现标签页 **GOL**（只有一个面板，标签用缩写省竖向空间）；
3. 点「构建」——没有目标网格时会自建一个 48×16 的环面（768 个四边形），加进**当前
   激活的 collection**（不是场景根），铺第 0 代、建材质、按目标取景；
4. 播放（或点「+1 代」）即实时演化：缺省 **每代 6 帧**，24 fps 下每秒 4 代；
5. 出图点「场景预设」：按目标包围盒重新取景的透视相机、1600×1000、Standard 色彩、
   世界背景铺项目色板的 `BACKGROUND`。

算子：`sim_game_of_life.build`、`sim_game_of_life.reset`（回到第 0 代，不重提拓扑）、
`sim_game_of_life.step`（时间轴 +「每代帧数」帧 = 一代）、
`sim_game_of_life.setup_scene`、`sim_game_of_life.fix_viewport`、
`sim_game_of_life.delete`（只删插件自建的网格）。

颜色只写在 `color` 角点属性里，而 Solid 视图默认的「着色颜色 = Material」读的是材质
单色，看不出生死色 —— 所以「构建」「场景预设」会顺手把 Solid 视图切成 **Attribute**。
播放中要是又切回 Material，面板会亮一条红色提示，点 `sim_game_of_life.fix_viewport`
即可；材质预览 / 渲染模式本来就看得到颜色，不动它们。

## 面板参数

| 分组 | 参数 | 说明 |
|---|---|---|
| 目标 / 规则 | 目标网格 | 细胞跑在它的面上。留空 = 用自建环面；用你自己的网格时几何不会被改动 |
| | 规则 | B/S 记号五档：康威 B3/S23（缺省）、HighLife B36/S23、Seeds B2/S、Day & Night B3678/S34678、无死亡 B3/S012345678 |
| 演化 | 初始密度 / 种子 | 第 0 代里活细胞的比例与随机种子：同种子 + 同网格 = 同一条演化路径 |
| | 每代帧数 | 多少动画帧推进一代。24 fps 下 6 帧 = 每秒 4 代；调小演化更快 |
| | 过渡帧数 | 每代开头多少帧用来插值（0 = 硬切，细胞逐帧闪；有过渡才看得到生灭的中间态） |
| | 插值 | 线性 / 平滑（缺省）/ 缓入 / 缓出 |
| | 后端 | 「自动」= 有 taichi 就用 GPU，取不到直接回退 NumPy（原因写在读数里） |
| 外观 | 配色 | 生死（绢白死格 → 石青活格，生灭的过渡处是赭石→朱砂的高光带）/ 年龄（石青→苔绿→赭石→朱砂） |
| | 年龄尺度 | 「年龄」配色里多少代算「老」 |

参数生效方式分三档：

- **拓扑 / 后端**（目标网格、后端）：下一帧自动重建（重新提邻域、重建求解器）；
- **初始条件**（种子、密度）：下一帧自动重播第 0 代；
- **节奏 / 规则 / 显示**：下一帧就生效，连代数都不用重跑（换规则从当前状态重算下一代）。

右下角读数：第几代、存活比例、每代耗时（指数滑动平均）、上次构建耗时、后端名与回退原因。

## 模型

细胞自动机的规则本身没什么可讲的，全部信息在这两句里：

```
出生：n ∈ B    存活：n ∈ S    其余一律死亡     n = 活邻居数（Moore：共点即邻居）
```

真正决定画面的是**邻域怎么来**：细胞是面，邻居 = 至少共用一个顶点的其他面。

| 网格 | 每个面的邻居数 | 效果 |
|---|---|---|
| 四边形网格（环面、平面细分） | 8 = 4 条边 + 4 个对角 | 和平面四方格棋盘同构，滑翔机 / 振荡子照样出现 |
| 三角网格（球面、ico 球） | 一般 11~12 | 更"稠密"，纹理更碎 |
| 高价顶点附近（UV 球两极） | 真值可达 50 | 截断到 24，且**共边邻居优先**（先掉对角邻居） |

上限 `MAX_NEIGHBORS = 24` 是为了让 Taichi 的邻域表是定长数组。参考脚本用 12，UV 球两极
的一个三角面会被砍掉 38 个邻居，而且砍哪个全看 Python 集合顺序；这里改成按「共边优先」
排序再截断，高价处退化成"边邻居 + 一部分对角"，行为稳定、可复现。

实现上一共两处细节：

- **代与代之间是插值的**：`state`（第 g 代）与 `next`（第 g+1 代）按过渡帧数在
  `alive` 属性里插值，所以「生灭」是渐变的，而不是逐帧闪；
- **回退即重算**：状态不是缓存，拖时间轴回退会从第 0 代重算到当前帧 —— 于是同一条
  时间轴每次播出来的演化完全一样（实测回退后重放与正向播放逐属性一致）。

## 什么网格上才好看（实测）

同一颗种子、同一套缺省参数（康威 B3/S23、密度 0.3、每代 6 帧），在 Blender 里逐网格跑
出来的体检结果（「8 邻域」= 恰好 8 个邻居的面占比；存活率取第 30 代，除非另注）：

| 网格 | 面数 | 8 邻域占比 | 邻居数 | 第 30 代存活 | 观感 |
|---|---|---|---|---|---|
| 环面 48×16（闭环） | 768 | 100% | 8 | 15.2% | 标准棋盘：滑翔机、闪烁器、稳定块都认得出来 |
| 平面网格 24×24（有边界） | 576 | 84% | 3~8 | 16.1% | 内部正常，**边框一圈先死**（第 40 代：内部 19.0% vs 边界 5.4%） |
| UV 球 48×24 | 1152 | 92% | 8~24 | ≈14% | 中间正常，两极那一圈面邻居太多，纹理糊成一片 |
| 猴头（原始低模） | 500 | **53%** | 5~14 | 9.2% | 一个面就是一大块眼睛 / 耳朵，看不出细胞自动机 |
| 猴头 + Catmull-Clark ×2 | 7872 | 93% | 5~12 | 13.5% | 恢复成棋盘质感，面够细了 |

由此得到三条判据：

1. **面要小、要匀**：细胞就是面，面大等于像素大。低模直接跑只有"一大块一大块的蓝"；
2. **每个面最好 8 个邻居**：三角面 11~12 个邻居时，B3/S23 里的「3 个活邻」在 12 邻域里
   只占四分之一，规则的"密度档"被整体推高 —— 图案更碎、寿命更短；
3. **边界会给细胞减邻居**：平面 / 开口曲面的边框面只有 3~5 个邻居，活不下去，于是画面
   自然留出一圈死边（闭环网格没有这个问题）。

想跑得好看，按这个顺序处理目标网格：

- 低模先加一级 **Subdivision**（Catmull-Clark），三角面先做 **Tris to Quads**，让面接近
  正方形、每个面 8 个邻居；
- 优先用**闭环**网格（环面、球面、闭合曲面），或者接受边界那一圈会死；
- 面数就是细胞数：50 万面的高模该换 Taichi 后端，而 100 面的方块网格只有 100 个"像素"；
- 面板「目标 / 规则」里直接显示 `N 面 / X% 是 8 邻域 / 后端`，低于 80% 会亮红字并提示
  先细分。

## 性能

| 网格 | NumPy 每代 | Taichi 每代 |
|---|---|---|
| 768 面（缺省环面） | ≈0.15 ms | ≈0.02 ms（首次要 1.2 s 编译 kernel） |
| 1152 面（UV 球 48×24） | ≈0.12 ms | — |

几千个面的网格 NumPy 后端就够实时了，Taichi 后端是为几万个面准备的。想更快演化请调
小「每代帧数」，不要指望减少过渡帧数 —— 后者只影响画面平滑度。

## 数据接口

目标网格上的属性，几何节点 / 着色器可以直接按名字取：

| 属性 | 类型 / 域 | 含义 |
|---|---|---|
| `alive` | FLOAT / FACE | 插值后的状态 0~1（第 g 代与第 g+1 代之间），几何节点里按 `> 0.5` 取活格 |
| `age` | FLOAT / FACE | 连续存活代数（这一代活着就 +1，死掉归零） |
| `color` | FLOAT_COLOR / CORNER | 线性 RGBA，Solid 的 Attribute 着色与渲染共用 |

颜色属性只能落在 POINT / CORNER 域上（RNA 限制），所以写的时候按「每个 loop → 所属面」
展开了一遍，一个面里的所有 loop 拿同一个颜色。材质里是
`Color Attribute → Base Color`，没有第二套色；节点的属性名**留空**（不设置），由渲染器
自动取活跃色属性 —— 填上 `color` / `vertex_color` 会被 Cycles 当成它自己的标准顶点色名，
取到空值、渲染成纯黑（EEVEE 不受影响，只测 EEVEE 发现不了）。

> 插件**接管**这三个属性名：目标网格上同名的属性如果类型 / 域不对（例如参考脚本留下的
> `alive` INT、或用户自己的 BYTE_COLOR `color`），会被重建成本插件要的形状。

## 模块

```
solver.py        NumPy 求解器（边表 + bincount）+ 规则库 + 后端工厂 create()  （不 import bpy）
taichi_solver.py 同一套规则的 Taichi GPU kernel（可选后端）
colour.py        生死 / 年龄 → 面颜色（只用项目色板）                         （不 import bpy）
mesh.py          面邻域提取、alive / age / color 属性、材质、缺省环面
sim.py           frame_change_pre handler：推代数 → 插值 → 写面属性
scene.py         世界底色 / 按目标取景的相机 / 渲染设置
viewport.py      Solid 视图的着色颜色检查（颜色写在属性里，Material 着色看不出生死）
props.py         scene.sim_game_of_life 参数组
ops.py           构建、重置、步进、场景预设、视口修正、删除
ui.py            View3D > 侧栏 > GOL
```

`solver.py` / `colour.py` 可以脱离 Blender 单独跑（系统 Python + numpy）：

```powershell
python -c "import numpy as np; from sim_game_of_life import solver; nb=np.tile(np.arange(8),(64,1)); s=solver.create(64); s.load_topology(nb, np.full(64,8)); s.set_state(np.random.rand(64)); s.step(5); print(s.state_flat().sum())"
```

## 与参考实现的差别

参考实现 `common/game_of_life.py` + `scripts/blender_game_of_life.py`（Taichi 求解器 +
几何节点着色）的规则与插值照搬，差别在工程结构：

| | 参考脚本 | 本扩展 |
|---|---|---|
| 组织方式 | 两个独立脚本（求解器 / Blender 集成） | 扩展包：算法层与 Blender 层分开，可单独测试 |
| 后端 | 只有 Taichi | NumPy 与 Taichi 两档（实测同状态同规则下逐位一致），工厂自动回退 |
| 结果落到场景 | 几何节点 `Store Named Attribute` 上色 | 直接写 `color` 角点属性 + 材质，不依赖几何节点 |
| 面板 | category `Taichi` | category `GOL`（缩写，省竖向空间） |
| 邻域上限 | 12，集合顺序截断 | 24，共边优先截断 |
| 换代之判 | 靠 `last_tick_frame` 帧号比较，回退会乱 | 代数直接由帧号算出（`frame // 每代帧数`），回退从第 0 代重算，可复现 |
| 重建判据 | 每次点「初始化」都重来 | 拓扑 / 后端变了下一帧自动重建；初始条件改了只重播第 0 代 |

## 局限与下一步

- **不是"任意网格"都好看**：细胞 = 面，所以要求面小、大小均匀、每个面 8 个邻居。低模、
  三角面为主、开口（有边界）的网格都会明显走样 —— 见[什么网格上才好看](#什么网格上才好看实测)；
- **三角面跑得动但不像康威**：11~12 邻域下 B3/S23 的"密度档"被推高，图案碎、存活率低；
  想要经典观感请先 Tris to Quads 或细分；
- **边界会吃掉一圈**：开口网格的边框面只有 3~5 个邻居，实测第 40 代边界存活 5.4%、
  内部 19.0%，视觉上就是一圈死边；
- **邻域是顶点邻接**（Moore），不是拓扑意义上的"边邻接"：四边形网格上和四方格棋盘同构，
  但邻居数一变化，规则的实际行为就跟着变；
- **高价顶点被截断**：UV 球两极那种 50 邻域的顶点只保留 24 个邻居（共边优先）；
- **面大小不均会拉伸图案**：长条 / 大小差异大的面上，一个细胞覆盖的面积天差地别；
- **没有烘焙**：演化靠 `frame_change_pre` 实时算，渲染动画时帧要按顺序走（Blender 默认
  如此）；跳帧会逐代补算，面越多、跳得越远越慢；
- **编辑模式下 handler 会跳过**（面属性由 BMesh 掌管，`foreach_set` 会被丢掉），退出编辑
  即恢复；「构建」也会拒绝在编辑模式下跑；
- 图案库（滑翔机、振荡子、枪）没做：现在只有随机初始状态，要在曲面上"摆"图案得自己写
  `alive` 属性。
