# 生成式斐波那契穹顶（Gen Dome）

半球上的斐波那契点 → 球面 Voronoi 面板 → 一座会**生长**的穹顶（扩展 id `gen_dome`，
Blender 5.2.2 实测）。

生成方式**照搬参考实现**（`ga2/scripts/blender_fibonacci_dome.py` +
`ga2/common/fibonacci_voronoi.py`）：每一帧换一个新点数，把**整座半球**重新划分一遍 ——

* **每一帧都是完整的半球**，尺寸从头到尾不变；
* 第 1 帧只有 3 个点：3 块大面板就铺满整个半球；
* 点数逐帧 +1，于是面板越来越多、每块越来越小，叶序螺旋跟着整体重排。

也就是说画面里变化的是**格子的粗细**（外加螺旋在缓慢地淌），不是穹顶在长大，所以不会忽大
忽小地闪。

跟原版唯一的区别是实现：原版用 `frame_change_pre` 处理器逐帧重算 Voronoi、重建整份网格；
这里把每一代**烘**进同一份网格（逐面属性 `gen` 记代号），几何节点按当前帧挑一代显示。
播放、拖动、倒放、循环都只是切代 —— 一帧删几万面里的绝大部分，不重算几何，进度条一拖到底
也是即时的。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Gen Dome**；
2. 3D 视图侧栏出现 **Dome** 面板（F3 里也有 `gen_dome.*` 算子）；
3. 点「生成」——烘出 `Fibonacci Dome`：一个网格对象（里面装着每一代的面板）+ **只加一个**
   `Phyllotaxis` 几何节点修改器（不给厚度、不做平滑着色，要就自己往后面接）；
4. 按播放键（第 1 → 251 帧）：穹顶一直是完整的半球，表面从 3 块大面板慢慢细分到 250 块；
   不播放也可以拖「生长进度」滑块，一格一代；
5. 出图点「场景预设」：3/4 视角透视相机（按网格数据取景，不受当前帧影响）、2048×2048、
   Standard 色彩、世界背景铺项目色板的 `BACKGROUND`、一盏三点式简化的太阳主光。

算子：`gen_dome.generate`（生成 / 重新烘焙）、`gen_dome.delete`、`gen_dome.sync_from_object`
（从对象上记录的参数回读面板）、`gen_dome.setup_scene`。

## 面板参数

三档参数的生效方式不同，面板上也分开摆：

| 分组 | 参数 | 说明 |
|---|---|---|
| 几何（改完要重新生成） | 终点种子数 | **最后一代**的点数（= 面板数），3–4000，默认 250。第 1 代固定 3 点，之后线性加到这里 |
| | 半径 / 高度比 | 赤道半径（世界单位）；顶点高度 = 半径 × 高度比（1 = 半球，小于 1 扁穹顶） |
| | 缝宽 | 面板之间的缝（世界单位）：每块面板的边界各往里退一半，**缝宽处处相等**。默认 0 = 面板紧贴成完整球壳 |
| | 封底 | 用口沿那一圈顶点封一张底板（没缝时正好封成实心碗底）。**默认关**，穹顶就是个开口的碗 |
| 生长（实时） | 跟时间轴生长 | 生长进度改由场景时间算：`(当前帧 - 起始帧) / 时长`，一格一代 |
| | 起始帧 / 时长 | 生长区间的两头，默认第 1 帧起、**250 帧**长满。**改它不用重新生成**；场景的「结束帧」如果比「起始帧 + 时长」小，会自动拉到刚好够（只增不减），免得播放到不了最后一帧 |
| | 生长进度 | 关掉「跟时间轴生长」时用它拖代（0 = 第一代，1 = 最后一代） |
| 几何节点（实时） | 立柱 / 立柱半径 | 每块面板的种子上放一颗小球；跟着这一代的面板走 |
| 外观 | 面板色 / 立柱色 | 只改材质基色，几何一点不动（默认绢白 `SILK` / 赭石 `OCHRE`） |

面板上写着这次烘了几代、每代加几个点、每代停几帧、大概多少面。三个数各算各的：

| 显示 | 公式 | 默认 250 点 / 250 帧 | 150 点 / 250 帧 |
|---|---|---|---|
| 代数 | `min(时长, 点数-2, 面数预算, 256)` | 96（被面数预算 `2×12000/点数` 压到 96） | 148 |
| 每代加点 | `(点数 - 3) / (代数 - 1)` | **+2.6** | +1.0 |
| 每代停几帧 | `时长 / (代数 - 1)` | 2.6 帧 | 1.7 帧 |

也就是说「每代 +2.6 点」是**一代之内**从第 i 代跨到第 i+1 代加的点数（不是每帧）；
摊到帧上，每帧只加 `247/250 ≈ 1.0` 点。代数被预算压得比时长小的时候，一代会连停好几帧。
穹顶对象上另存了一份生成参数，换文件 / 换场景后「回读参数」能把面板还原成当初的样子。

**厚度 / 平滑**：插件只给几何 + 材质 + 生长，**不加实体化、也不做平滑着色** ——
要壳厚就自己加 Solidify；要圆润就在物体上 Shade Smooth 或加「着色平滑」修改器。
（想保留平直多边形的观感就别加平滑，Voronoi 的棱面本来就是这个味道。）

## 算法（`dome.py`，纯 numpy）

### 1. 点：半球上的斐波那契排布

方位角按黄金角 `π(3-√5)` 一步步转，`z` 在 `0..1` 上逐点均分。`z` 均分 ⇒ 球面上按
**面积**均匀（球带的面积正比于 `z` 的差），所以点不会在顶点附近挤成一团；索引 0 贴着赤道、
末尾贴着顶点。点数是这一代唯一的输入，`n` 一变整张图就重排 —— 这正是生长的来源。

### 2. 多边形：球面 Voronoi = 一堆过原点的半空间之交

「离我比离 j 近」在单位球上等价于 `x·(pᵢ - pⱼ) >= 0`（两边平方后 `|pᵢ|² = |pⱼ|² = 1` 抵消）。
所以每个点的单元就是若干个过原点半空间的交：

1. 在种子切平面上摆一块半径 1e3 的 24 边形（**必须是一块远大于单元的平面多边形**，
   不能是球面上的一圈顶点 —— 平面多边形的内部躺在它的平面里，球面上的一整块区域根本不在里面）；
2. 拿最近的 16 个点做半空间裁剪，**所有单元一起裁**（每个候选平面一轮 numpy 运算）：
   每条边最多产出两个顶点（端点在里面就留端点，跨越平面就补个交点），按边序交错进 2K 个
   槽位，再用 `cumsum` 压实 —— 顺序自然保持；
3. 裁完才把顶点投影回球面。裁剪平面都过原点，顶点沿自己那条射线挪多远都不改变内外关系，
   所以整段裁剪都在切平面尺度上做，中途投影回去只会把多边形缩成球面上几乎共面的一圈。

批量化前后的实测：150 个点 **82 ms → 9.4 ms**；500 个点 60 ms；2000 个点 164 ms。

### 3. 半球：直接裁到 `z >= 0`，不镜像

参考实现把上半球的点镜像到下半球凑成整球再算。**镜像没必要**：对 `z > 0` 的 `x` 有
`|x - p'|² = |x - p|² + 4·z·z_p > |x - p|²`，所以上半球里镜像点从来不构成约束 ——
把单元直接裁到 `z >= 0` 得到的多边形与镜像法**逐点相同**（对拍 scipy 逐块面积的相对误差
150 点 2.0e-12、1200 点 5.0e-12）。顺带还避开了镜像法「两个几乎重合的点」带来的数值退化。

**为什么不直接用 scipy**：`scipy` 不是 Blender 自带的，装了 scipy 的机器上能跑、别人的机器上
`import` 就炸；本仓库的约定是除 numpy 之外不带依赖（见根 `README.md`）。

### 4. 生长：一代一次完整重划分

第 `i` 代取 `n = 3 + i·step` 个点（`i = 0..代数-1`，最后一代正好是「终点种子数」），
算一场**独立**的半球 Voronoi，拼进同一份网格并记上 `gen = i`。面板数就是
`3, 3+step, 3+2·step, …`，单元面积 ∝ `1/n`：数量单调增、大小单调减，而任何一帧的覆盖面
都是整个半球。`step` 默认 1（一代一点，跟原版逐帧 +1 点一样）；代数被面数预算压小之后
`step` 会大于 1，生长就是跳着加点了。

### 5. 缝：沿大圆朝种子退让

球面上「把单元边界往里推一个固定的弧长」就是对每个顶点做球面线性插值 `seed → v`，
走到离种子 `α - gap/2` 的位置。相邻两块各退一半，中间留出的缝**处处等宽**（面板在球面上
大小不一，缝却一样宽）。退没了的面板直接丢掉，面板底部会报个数。

### 6. 封底

赤道上的单元顶点正好落在 `z = 0` 这张平面上（每个单元在口沿上一条边，合起来是一整圈）。
把它们按方位角排一圈就是底板的边界；没缝时它与面板底边是同一批坐标，**顶点会被并掉**，
整座穹顶是闭合流形（每条边正好被两张面用）。

## 几何节点（`gn.py`）

```text
Group Input(Geometry, Grow, Animate, Start Frame, Length, Last Gen, Studs, Stud Radius)
  ├─ (帧 - 起始帧) / 时长 × Last Gen  ┐
  ├─ Grow × Last Gen                 ┴→ Switch(Animate) → 取整 → 当前代
  └─ gen 属性 → |gen - 当前代| > 0.5 → Delete Geometry(FACE)   只留当前这一代
       ├→ Set Material(面板) ────────────────────────────┐
       └→ Mesh to Points(FACES, 位置 = seed_pos 属性)     │
            → Ico Sphere(立柱) → Set Material ─┐         │
                 → Instance on Points → Switch(Studs) ────┤
  └────────────────────────────────────→ Join Geometry ───┴→ Group Output
```

组里**没有** Shade Smooth 节点：面板保持各自的平面法线（平直多边形），要圆润自己加。

* **挑代**：进度先取整再比较 `|gen - 当前代| > 0.5`，所以**永远只有一代在场**
  （不取整时进度正好落在两代中间，两代会同时显示、互相穿插）。
* **立柱**取的是 `seed_pos` 属性（逐面的种子坐标）而不是面心：面心是「退了缝之后那块的质心」，
  种子的位置才是真正的那颗点。底板那张面 `seed_idx = -1`，靠一个 `seed_idx >= 0` 的比较排除。
* `Last Gen` 是**烘进网格的**代数（生成时写在对象上），不是面板上的帧数 ——
  改「时长」只改 `Length`，不用重新生成。

节点组只建一次（`GROUP_VERSION` 变了就地重搭），所有生成对象共用；接口输入按名字回
`node_group.interface.items_tree` 查 identifier 再写 `modifier.properties.inputs.<id>.value`
（5.x 的写法，老的 `modifier[identifier]` 会抛 "id properties not supported"）。

## 数据接口

网格上三个**逐面**（`FACE`）属性，长度 = 面数（底板那面也在内，序号 `-1`）：

| 属性 | 类型 | 含义 |
|---|---|---|
| `seed_idx` | INT | 种子序号，赤道 → 顶点；底板是 `-1` |
| `seed_pos` | FLOAT_VECTOR | 种子位置（局部坐标，已经是最终世界尺度） |
| `gen` | INT | 属于第几代（几何节点按它挑代） |

面板底部的「数据接口」一行就是这三条，缺了哪个会标红。

## 实测

| 场景 | 面 | 顶点 | 耗时 |
|---|---|---|---|
| 静态单代，250 点（关掉「跟时间轴生长」） | 250 | 498 | **7 ms** |
| 生长，96 代 / 250 点（默认参数） | 12,144 | 24,096 | **≈0.4 s**（含界面刷新 0.4–0.9 s） |

**播放**只切代：一帧删掉几万面中的绝大部分，实测没有可感知的卡顿；拖动时间轴、倒放、
循环同样即时（几何是烘好的，不依赖缓存）。逐帧面板数 `3, 4, 5, …`，相邻两代只差一个点，
画面是连续的缓慢细分。

**正确性**（150 / 1200 点）：每一代的单元总面积 = `2π`（半球面积，误差 < 1e-9）、
全部朝向面外、与 `scipy.spatial.SphericalVoronoi` 的镜像法逐块面积相对误差 2e-12 / 5e-12；
缝隙 0 时是闭合流形（每条边正好两张面）。

## 模块

```
dome.py    算法层：斐波那契点 / 球面 Voronoi（批量半空间裁剪）/ 逐代生成 / 缝退让 / 封底
gn.py      几何节点组：按帧挑代 + 立柱（按 seed_pos 属性放小球）
mesh.py    几何后端：网格 + 逐面属性 + 几何节点修改器 + 两个材质
props.py   scene.gen_dome 参数组 + 对象上回存的设计参数
ops.py     生成（带进度条）/ 删除 / 回读参数 / 场景预设
ui.py      View3D > 侧栏 > Dome（含「数据接口」披露）
palette.py 项目色板副本（改色记得与 _shared/palette.py 同步）
```

`dome.py` 不 import bpy，可以脱离界面单独跑：

```python
from gen_dome.dome import build_generations

panels = build_generations(count=250, generations=96)
panels.verts, panels.faces, panels.gen, panels.seed_pos  # numpy / list
panels.generations, panels.gen_faces(0)  # 代数 / 某代的面数
```

## 局限与下一步

* **内存是 O(代数 × 点数 / 2)**：默认 96 代 250 点 ≈ 2.4 万顶点、1.2 万面。想更密就减点数
  或接受更长的生成时间；面数预算是 `dome.PANEL_BUDGET`（约 1.2 万面），超了会自动跳代
  （想做到「一代一点」得把预算提到 `点数²/2`，250 点就是 3 万面 ≈ 3 s）；
* **代与代之间是跳变**：面板直接换掉，没有「缩放 / 淡入」过渡（参考实现同样如此，
  因为相邻两代只差一个点，看起来本来就是连续细分）；想要形变过渡得按面板独立实例化再插值；
* **是单面的壳**：没有实体化，所以从背面看是透的、边沿也没有厚度；要壳厚自己加 Solidify；
* **封底是一张 n 边形**：400 点就是 400 条边的面，想拿去做 3D 打印得先三角化；
* **立柱只有一种**：小二十面球，没有朝向 / 高度变化；立柱是**实例**，想编辑得先
  「物体 > 应用 > 视觉几何」把修改器烘成实体几何；
* **点数上到 4000 只能做静态**：生长模式下面数预算会把代数压到个位数（跳代很明显）。
