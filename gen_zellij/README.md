# 生成式 Zellij

伊斯兰几何镶嵌（zellij）的生成器 + Blender 扩展（扩展 id `gen_zellij`，在 Blender 5.2.2
上实测）：给一个整数种子，得到一张可复现的分层 Grease Pencil 图案。

同一个目录里是两半互不依赖的代码：

- **算法层**只回答"要画什么"：给一个整数种子，吐出哪些多边形、什么颜色；
- **Blender 层**只回答"怎么画"：把这些多边形写成 Grease Pencil v3 的分层笔划与填充。

## 快速开始

1. 仓库按根目录 `README.md` 注册为本地扩展仓库并启用本扩展（或安装
   `blender --command extension build` 打出的 zip）；
2. 3D 视图侧栏出现 **Gen Zellij** 面板；
3. 点「生成」得到一块图案；种子旁的按钮抽新种子重画。生成前会自动检查 3D 视图着色
   （Solid 模式下若不是顶点色，会切成 Attribute，否则图案全黑，见下节第 3 条）；
4. 要直接出图点「场景预设」：建 2048×2048 正交相机、切 Standard 色彩、GP 抗锯齿
   调到 16，按图案实际包围盒取景，并把世界背景铺成项目色板的画布底色
   （`BACKGROUND = #E4D9D0`）。

算子（F3 搜索同名命令）：`gen_zellij.generate`、`gen_zellij.random_seed`、
`gen_zellij.delete`、`gen_zellij.sync_from_object`、`gen_zellij.setup_scene`。

## Blender 集成

### 面板参数

| 分组 | 参数 | 对应 |
|---|---|---|
| 种子 | 种子 / 每次换种子 | `build_design(seed)`；勾选后每次生成抽新种子并写回 |
| 设计 | 密度 / 焦点 / 颜色抖动 | `build_design()` 三个可选覆盖 |
| 画布 | 画布 / 边距 | 世界单位；图案等比缩放进画布 |
| 图层 | 填充 / 块轮廓 / 编织 / 描边 / 瓷砖线 / 构造线 | 六个 GP 图层的显隐（见下） |
| 线宽 | 块轮廓宽 / 编织带宽 / 编织间隙 / 编织色 / 编织描边宽 / 描边色 / 瓷砖线宽 / 构造线宽 | 笔划**半径**（总宽 = 2×半径） |
| 工具 | 场景预设 / 回读参数 / 删除 | 相机与色彩设置、从对象读回生成参数 |

**就地生效**（不重建几何）：图层显隐（`layer.hide`）、块轮廓 / 瓷砖线 / 构造线的线宽
（改 `radius` 属性）、Dot Dash 开关（改修改器）、调试图层配色。**需要重新生成**：种子、
密度、焦点、抖动、画布、边距，以及**编织的带宽、间隙与描边宽**——缺口是几何，宽度改了
缺口就不对了（见 §13）。

### Grease Pencil 数据映射

| 概念 | GP v3 实现 | 实测要点 |
|---|---|---|
| 一个图层 | `data.layers`，索引越大越靠上 | 建层顺序 = `Shape.layer` 首次出现顺序：`Fills` → `Outlines` → `Tiling` → `Lines` |
| 一条 `Shape` | 一条 stroke，`cyclic = shape.closed` | 点列写 `position` 属性 |
| 描边色 | `vertex_color`（POINT，FLOAT_COLOR） | 存**线性**值，sRGB 先转线性；颜色由场景层给（`Fills` 不描边，靠 `hide_stroke` 关掉） |
| 填充 | `fill_id`（CURVE，INT）非 0 + `fill_color`（CURVE，FLOAT_COLOR） | 每条形状一个独立 id，相邻瓷砖不会被并成一片 |
| 线宽 | `radius`（POINT，FLOAT） | 半径 = 总宽 / 2，按图层写；不影响几何 |
| 编织缺口 | 折线本身（在缺口处收尾） | 端头默认是圆头，末点之外还会糊出半个笔宽，切距要把它算进去 |
| 端头 | `start_cap` / `end_cap`（**CURVE**，INT8） | `0` = 圆头，`1` = 平头（`caps_set(type='FLAT')` 就是写它）；整层都没有平头时不建这两个属性（见 §13） |
| 尖角 | `miter_angle`（POINT，FLOAT，弧度） | 写 1°（算子下限）；写 0 或缺失等于圆角；`set_corner_type(corner_type='ROUND')` 只是把它写 0 |
| 虚线 | `GREASE_PENCIL_DASH` 修改器的 `segments[0]` | `dash`/`gap` 是**采样点数**：`(1, 0)` 才是实线，`(2, 0)` 已是 1:1 虚线。所以构造线必须等弧长采样 |

三个必须知道的显示坑（都实测过）：

1. **新图层默认 `use_lights = True`**：没有灯时填充只拿到 `World.color` 的环境光，
   实测纯红填充渲染成 0.247 而不是 1.0。本扩展把所有图层建成无光照层
   （`use_lights = False`），颜色所见即所得；
2. **色彩管理**：`view_transform` 必须是 `Standard`，否则 AgX / Filmic 会把色板洗淡。
   「场景预设」会切过去；生成时只给提示，不偷改用户场景；
3. **Solid 模式的着色颜色**：颜色写在 `vertex_color` 属性里，材质槽是空的，而 3D 视图
   默认 `shading.color_type = 'MATERIAL'` —— 没有材质可显示，画出来就是全黑。所以
   「生成」和「场景预设」都会先检查：仍停在 `MATERIAL` 的 Solid 视图直接切成
   `VERTEX`（界面里叫 *Attribute*）。材质预览 / 渲染模式不受影响；你自己选了
   Object / Random / Texture / Custom 的保持原样（见 `viewport.py`）。

### 图层语义

| 图层 | 内容 | 默认 |
|---|---|---|
| `Fills` | 成品马赛克：填充图案的多边形，每条一个 `fill_id`，**不带描边** | 显示 |
| `Outlines` | 同一套几何的描边，颜色由各自的填充色派生 | 隐藏 |
| `Interlace Case` | 带子下面那条更粗的描边，露出来的一圈就是蕾丝边（默认墨玄） | 显示 |
| `Interlace` | 同一套边网编成的带子：交叉点上交替压下，压下的那一端切掉缺口 | 显示 |
| `Tiling` | 瓷砖分界线：去重后的边网络，每条边一条开口笔划 | 隐藏（调试用） |
| `Lines` | 构造线：裁到拼贴区凸包，等弧长采样，可虚线化 | 隐藏（调试用） |

五个"线稿"图层（`Outlines` / `Interlace Case` / `Interlace` / `Tiling` / `Lines`）与
`Fills` 坐标完全一致，所以随时可以整体隐藏、加粗或互换，都不动填充。`Outlines` 与
`Interlace` 是同一套色块边网的两种画法，**通常只开一个**：前者是逐块描边，后者把边网当
带子编起来（§13），`Interlace Case` 是它的描边层、**必须和它一起开**（只开描边就只剩
一圈圈深色轮廓）。`Tiling` 与 `Lines` 是"看得见构造"的辅助图层，默认隐藏；`Interlace
Case` 单独关掉就得到"纯色带子"的旧观感。

## 输出契约

### `Shape`

```python
@dataclass(frozen=True, slots=True)
class Shape:
    points: list[tuple[float, float]]  # 折线 / 多边形的顶点（设计单位）
    fill: RGBF | None  # 填充色 (r, g, b)，各分量 0..1，None = 不填充
    stroke: RGBF | None  # 描边色 (r, g, b)，各分量 0..1，None = 不描边
    closed: bool  # True = 闭合路径（可填充），False = 开放折线
    layer: str = LAYER_FILLS  # 图层名
    caps: tuple[bool, bool] = (False, False)  # (起点平头, 终点平头)；默认圆头
```

颜色是 **sRGB** 的 0..1 浮点三元组。后端若需要线性光，自行换算：

```
C_lin = C / 12.92                       (C <= 0.04045)
C_lin = ((C + 0.055) / 1.055) ** 2.4    (otherwise)
```

### 图层

| 图层 | 内容 | 路径类型 |
|---|---|---|
| `Fills` | 成品马赛克：填充图案的多边形 | 闭合 |
| `Outlines` | 与 `Fills` 同一套多边形，只带描边色 | 闭合 |
| `Interlace Case` | `Interlace` 的同一批折线，画在它下面、笔宽更粗（蕾丝边） | 开放 |
| `Interlace` | 同一套边网编成的带子（已切缺口、端头平/圆混合） | 开放 |
| `Tiling` | 瓷砖分界线（去重后的边网络） | 开放 |
| `Lines` | 构造线（裁到拼贴区域凸包内，等距采样） | 开放 |

图层名常量在 `scene.py`：`LAYER_FILLS` / `LAYER_OUTLINES` / `LAYER_INTERLACE_CASE` /
`LAYER_INTERLACE` / `LAYER_TILING` / `LAYER_LINES`，顺序常量 `LAYER_ORDER`。
`build_layers()` 返回的是**扁平列表**，按 `Shape.layer` 过滤即得分层；编织只有给了
`weave_style`（`weave.WeaveStyle`）才会出现，不给就还是原来那四层。

### 坐标约定

- 设计在 y 向下的平面坐标系里算（画布左上角为原点），场景装配的最后一步统一翻成
  Blender 的 **y 向上**。
- 结果落在 `[margin, margin + size]` 的正方形内；`margin == 0` 时图案包围盒的
  左下角正好对齐原点。
- `size` 是画布边长；线宽不在 `Shape` 里，由后端按图层另行写入。

## 算法

### 1. 随机源

`Mulberry32`：32 位状态的确定性伪随机数发生器，纯整数位运算，所以同一 seed 在任何
平台、任何 Python 版本上都得到完全相同的设计（含颜色）。

随机流只有一条，贯穿设计阶段与场景阶段：`Design.rng_state` 记录设计阶段结束时的
状态，场景阶段从那里接着走。

### 2. 特征与配色

`init_features()` 按固定顺序抽三个量（顺序必须保持，否则随机流错位）：

| 量 | 取值 | 概率 |
|---|---|---|
| 构造线密度 `n` | 10 / 6 / 20 | 70% / 20% / 10% |
| 焦点特征 | `None` / `Eight` / `Sixteen` | 75% / 20% / 5% |
| 颜色抖动 `shimmer` | 关（-1）/ `[2, 4)` 的整数 | 75% / 25% |

密度 `n` 同时决定两个数：交点网格边长 `2n+1`，以及从 `6n+4` 条候选构造线里保留几条
（`DENSITY_TO_LINES`：4→8、6→9、8→16、10→25、12→26、16→30、20→40、24→44）。

`init_colours()` 生成 5 色色板，用色相 / 饱和 0..100、明度按百分比的 `HSB` 语义：

- 1 号色：色相随机，饱和度随机，明度 `0..30`（暗底）；
- 2 号色：色相随机，饱和度 `0..10`，明度 `95..100`（亮底）；
- 3~5 号：色相随机，饱和度 `25..75`，明度 `25..75`。

`shimmer` 打开时，**2 号以后的色**在做亮度抖动：明度加上 `±25` 的随机偏移再截断到
`[0, 255]`（`rand_fill()`）。1 号色不抖。

### 3. 构造线晶格

候选线共 `6n+4` 条，分四组（顺序必须保持原样，后续的索引计划依赖它）：

| 组 | 方向向量 | 起点 | 条数 |
|---|---|---|---|
| 水平 | `(1, 0)` | `(0, 2i)`，`i = 0..n` | `n+1` |
| 垂直 | `(0, 1)` | `(2i, 0)`，`i = 0..n` | `n+1` |
| 西北–东南 | `(-1, -1)` / `(1, 1)` | `(2n, 2i)` / `(0, 2i+2)` | `(n+1) + n` |
| 东北–西南 | `(1, -1)` | `(0, 2i)` / `(2i+2, 2n)` | `(n+1) + n` |

四条线都从画布边缘出发、方向为单位向量（对角线的分量是 `±1/√2`）。

焦点特征先用**写死的索引计划**从候选里删掉 / 保留若干条（`Eight` 2×2、`Sixteen` 星形），
剩下的名额再由随机抽取填满（已保留的线不占随机预算）。

`Sixteen` 的索引计划按下标推导时要求 `n ≥ 5`，所以 `Density 4` + `Sixteen` 会退回
不强制特征。

### 4. 交点网格与瓷砖生长

交点网格是 `2n+1` 见方的整数格点；构造线的方向向量都是整数，所以沿方向步进可以
精确地标记它经过的每个格点（`Grid.mark_line()`）。

瓷砖由**洪水填充**得到（`get_all_tiles()`）：

1. 从任意一个被 ≥ 2 条线穿过的格点出发；
2. 该点的每条线贡献两个方向，共最多 8 个"被用方向"；
3. 按固定顺序 `ORDERED_DIRS` 遍历被用方向，从原点出发，每遇到一个方向就沿它的
   **左法线**走一步——所有步长都是 1，于是得到一个单位边的闭合多边形；
4. 多边形平移到与来路的那条边重合（找与来边同向的边，用它的端点做平移量）；
5. 沿每个方向找下一个交点并继续；找不到邻居时该边是边界，记入 `boundary`。

多边形的形状因此只由"被用方向集合"决定，也就是被几线交叉决定的——这正是后面
签名编码的对象。

### 5. 瓷砖签名与图案匹配

**签名**（`get_signature()`）：对多边形每个顶点 `b`，取前后顶点 `a`、`c`，算

```
s = (a - b) · (c - b)
```

| 条件 | 编码 | 含义 |
|---|---|---|
| `|s| < TOL` | `L` | 直角（两边垂直） |
| `|1+s| < TOL` | `I` | 平角（两边共线反向） |
| `s > 0` | `V` | 凸角 |
| `s < 0` | `C` | 凹角 |

顶点顺序编码成一个字符串，就是这块瓷砖的签名。

**匹配**（`match_filler()`）：图案库按签名索引。匹配过程是

1. 随机取一个旋转起点，把顶点序列循环移位（离散地"换个角开始看"）；
2. 算签名，查库；命中就返回该签名下的若干图案簇；
3. 没命中就把序列再移一位、签名跟着移一位，最多试 `len(签名)` 次。

命中后随机挑一个图案簇，用 `match_two_segs()` 求出一个仿射矩阵，把图案簇的包围盒
对角线映射到瓷砖的某条边上（`filler_transform()`），图案就被摆正了。

图案簇里的每个子形状单独成为一个填充多边形，填充色按 `rand_fill()` 抖动。

### 6. 焦点特征

`Eight` / `Sixteen` 靠写死的构造线索引计划实现，只对固定尺寸成立。

`Block3x3` / `Block4x4`（`CLUSTER_FOCUS`，下拉里显示为 `Block 3×3` / `Block 4×4`）
不动构造线，而是在瓷砖生成完之后
**按邻接关系并块**（`merge_cluster()`）：

1. 邻接表按"重合的边"建立（端点量化到 5 位小数后比较）；
2. 种子从面积 ≥ 中位数的瓷砖里随机挑；
3. 从种子出发做**质心距离优先**的 BFS（最小堆），收集满 9 / 16 块；
4. `group_tiles()` 把这些块合成一条轮廓：方向相反的重合边互相抵消，
   合并后的面积 = 各块面积之和，不会出现洞。

合并出来的那块形状不规则，匹配不到图案，所以它永远是空心的。为了让结果不至于变成
"一大块空心 + 零星小块"，并块后必须至少还剩 `MIN_REMAINING_TILES`（3）块正常瓷砖，
否则整张图放弃并块（`Design.focus_skipped = True`，按普通设计出图）。

### 7. 场景装配：唯一的仿射变换

所有图层共用**同一个**仿射矩阵，基准是填充图案的包围盒：

1. `fill_box(box, canvas, rot)`：等比缩放
   `s = min(canvas.w / box.w, canvas.h / box.h)`（不拉伸），再平移使 `box` 居中于
   `canvas`；`rot = True` 时先比较旋转 90° 后的缩放比，取更大者
   （正方形画布上会直接转 90°，所以默认关闭）。
2. 翻转：设计坐标 y 向下 → Blender 的 y 向上，并把参考框左下角对齐到 `(margin, margin)`：
   `x' = x - ref_min_x + margin`，`y' = ref_max_y - y + margin`。
3. 最终矩阵 = 翻转 ∘ 缩放平移。

为什么要共用：各视图分开算就会各自拟合自己的包围盒，叠在一起必然错位；
只算一次（以填充图案为基准），轮廓与构造线才能严丝合缝地叠在填充上。

### 8. 构造线：凸包裁切 + 等距采样

- **裁切**：构造线两端各延长一个画布边长后再截断，截断基准取
  **填充图案所在区域的凸包**（Andrew 单调链，`O(n log n)`）：
  逐边解直线与边的交点——交点在边上的参数必须落在 `[0, 1]`（否则交点不在这条边上，
  这条边不贡献），再把沿射线的参数收集起来取最小值与最大值，即射线与凸多边形的交集。
  裁到包围盒会留下空角，裁到凸包既不溢出主体又不留空角。
- **采样**：步长固定为
  `Δ = max(图案包围盒宽, 高) / LINE_SAMPLES_PER_WIDTH`（与线长无关），
  点数 `= max(2, round(L / Δ) + 1)`，点沿弧长等分。

等距采样是硬要求：虚线图案以弧长定义（见下），若点距不均，短线点密、长线点稀，
虚线疏密就会随线长变化。

### 9. Dot Dash 图案

构造线的点间距固定为 `Δ`，Dot Dash 的 `dash` / `gap` 就是**采样点数**，
所以图案在弧长上也是等周期的。

实测规律（41 点直线、点距约 40px、逐像素扫描）：周期 = `dash + gap` 个点距，
实段 ≈ `dash − 1` 个点距（两端圆头各糊出半个笔宽），空段 ≈ `gap + 1` 个点距。

| `dash` / `gap` | 亮占比 | 效果 |
|---|---|---|
| `1 / 0` | 100% | **实线** |
| `2 / 0`（默认） | 64% | 约 1:1 虚线 |
| `3 / 0` | 76% | 2 画 1 空 |
| `2 / 1` | 43% | 1 画 2 空 |
| `2 / 2` | 32% | 1 画 3 空 |

注意 **`gap = 0` 不等于实线** —— 只有 `dash = 1` 才是；`(2, 0)` 已经是 1:1 的虚线。
改默认值只需改 `gp.DASH_PATTERN`。

### 10. 填充去重

相邻瓷砖常被匹配到同一个图案簇，投影到同一位置后会产生坐标只差 `1e-5 ~ 1e-4` 的
重合形状。实心填充看不出来，但半透明描边会叠画两次，边界显得更深更粗。

`_dedupe()` 以 `(顶点数, 排序后的顶点集合四舍五入到 4 位)` 为键去重，
保留最后出现的那一份（颜色以盖在上面的为准）。去重在**世界坐标里**做（容差按最终
位置设定），去重后的一份同时喂给 `Fills` 与 `Outlines`。

### 11. 描边色派生

`Outlines` 的描边不是纯黑，而是由各自的填充色推出的同色相深色（HSV 空间）：

```
s' = min(1, 1.35 * s + 0.15)
v' = clamp(0.68 - 0.36 * v, 0.28, 0.78)
```

明度朝填充色的**反方向**推：浅底配深描边、深底配亮描边，每块描边既和自身填充同色系，
彼此又分得开。直接乘一个系数会把深色压成一片黑、浅色压成一片灰，
各层描边看起来就"统一"了。

### 12. 瓷砖轮廓 = 去重后的边网络

每块瓷砖各输出一条闭合路径的话，共享边就有两条路径完全重合，半透明时会叠画两次。

所以瓷砖改成先把所有边按端点量化（5 位小数）去重，每段边输出一条**开放**折线：
每条分界线只出现一次，宽度处处一致、不叠画。
`Tiling` 不参与填充，开口折线不影响任何填充结果。

### 13. 编织（`weave.py`）

`Outlines` 是把每个色块的轮廓各画一圈；编织要的是同一套边网的另一种读法——**若干根带子
在交叉点上交替压上压下**，压下的那一端切掉缺口。判据与几何无关：over/under 是挂在
"顶点 + 边端"上的组合状态，参考 Alhambra 的 `interlace` 图层（顶点出边按角度排序、
绕一圈交替、沿带子走到下一处交叉时取反）。

七步：

1. **平面化边网**（`_edge_network`）：色块轮廓不是现成的一张图，直接拿来用会留下大量
   "同一段缝的两份"。实测 density 10（7843 条边）里：**3971 条只是端点差 1e-6~1e-3
   而没合掉**、**2252 处 T 型结点**（端点落在另一条边内部却没打断）、**593 处两边内部
   真交叉但没有结点**（那里根本编不起来）。量化去重做不到——同一段缝的两份坐标正落在
   桶边界上就分开，所以改成三步：

   * 端点按 `snap` 容差聚类（栅格 + 邻域查询，`WeaveStyle.snap=0` 时取包围盒跨度 ×
     `SNAP_RATIO`，画布 10 下约 0.0017，是色块最短边的 3%）；
   * 每条边在"落在它内部的结点"处**打断**——近似重合、部分共线重叠、T 型一次消掉；
   * 两条非共线边内部相交时**插入结点**并同时打断两边，否则那个交叉点无从编织。

   平面化后（density 10）：4163 结点 / 6076 边，T 型与无结点交叉都是 0；
2. **顶点配对**：每个顶点的出边按"最接近反向"贪心配对（转角 > 90° 的配不上）。配对表
   就是带子的走向——**带子 ≠ 多边形**，闭合色块轮廓只是它的边料；
3. **追带子**：沿配对表一直走，配不上就在那里收尾；绕回起点的是闭合带子；
4. **认交叉**：一个顶点上有 ≥ 2 个"通过段"（配对起来的一对边）才算交叉。度 ≤ 3 的
   T 结点只有一个通过段，自然不断开——这正是拼接处该有的样子；
5. **定上下**：硬约束只有一条——**同一个交叉点上相邻的两根带子一上一下**（绕顶点交替），
   保证每个交叉点正好一根压上、一根压下，任何情况下都不会出现两根带子重叠或两边
   同时缺口。沿带子"走到下一处交叉就取反"只当**偏好**：色块拼图里有三角形/五边形的环，
   奇数个交叉绕一圈本来就不可能交替，硬当约束会把底线破掉。做法是先沿带子 BFS 传播
   一个理想相位（异或方程，奇环按先到的赋值放过去），再在每个顶点上**多数票**选
   "从哪一条开始压上"——票数不够、没能顺带交替的通过段记进 `Weave.mismatches`（不是错误）；
6. **切缺口**：压下的通过段在两边各切掉 ``d``。``reach`` 是**可见半宽**
   （``max(半宽, 描边宽)``——描边画在本体下面且更宽，真正占地方、要被让开的是它），
   ``sin(θ)`` 取该顶点上**最斜**的那根交叉带。两种端头两套公式：

   * **平头**（切面垂直于自己的中心线）：两个角到对方中心线的距离是
     `d·sinθ ± reach·cosθ`，要让靠里的角正好贴住对方边缘::

       d = reach * (1 + cosθ) / sinθ = reach / tan(θ/2)

     90° 时 `d = reach`，切口正好压在对方带子的边缘线上、两个角同时贴平——这才是
     Alhambra 那种"切进去"的样子。45° 时靠外的角会甩出 `2·reach·cosθ`，留下一个尖角
     缺口，所以斜交叉不用平头；
   * **圆头**（默认）：GP 会在末点之外再糊出半个笔宽，"切到 d"实际是"圆头尖停在
     `d - reach` 处"，于是::

       (d - reach) * sin(θ) >= reach + gap
       d = reach + (reach + gap) / sin(θ)

     圆头只有一个切点、圆弧顺着对方边缘弯开，斜交叉上比平头干净。

   缺口按**弧长区间**处理：每处压下的交叉给出 `[s-d, s+d]`，取并集后从 `[0, L]` 里减掉，
   剩下的每段一条开口 `Shape`——两头都切、切口吞并、整段被吃掉这些退化情况一次处理完；
7. **端头平/圆**：只有交叉角正弦 ≥ `FLAT_CAP_SIN`（≈ 64°..116°）的那一端用平头，其余
   （45° 交叉、带子自由的端头）留圆头。实测交叉角只有 45° 与 90° 两种，所以实际就是
   "90° 平头、45° 圆头"；逐端写进 `Shape.caps`，后端翻成 GP 的 `start_cap` / `end_cap`；
8. **残段修剪**：见下。

**不靠绘制顺序**：over/under 关系里存在环（A 压 B、B 压 C、C 压 A），任何"分两层、
一层压另一层"都排不出全局序（`Weave.links` 里这个环 3×3 的平纹棋盘格就有）。所以必须把
下面的带子真的切掉——这也是为什么带宽进几何。

**描边（蕾丝边）**：`WeaveStyle.casing > 0` 时每根带子出两条**同点列**的 `Shape`：先一条
更粗的描边（独立图层 `Interlace Case`，默认墨玄），再一条本体（`Interlace`，默认绢白），
露出来的那一圈就是极细的轮廓边。描边放独立图层而不是同层交错，是因为同层里后画的描边会
压到前一根带子的本体上，交叉处会有一根深线横穿别人的身体。两条的端头类型一致，缺口按
`reach` 算，所以描边再宽也不会戳出上方带子之外。

**残段修剪**：缺口把一段切得比两倍可见半宽还短时，画出来就是一颗浮着的"珠子"。这时把切出
它的那一刀收回去（`PRUNE`），那个交叉点两根带子直接叠着——同色不透明时完全看不出来，比
一颗珠子干净得多。代价是该点失去上下之分，记进 `Weave.pruned`；开了描边后叠画处会看到两
圈轮廓互相穿过，所以描边下"珠子"宁可留着。实测默认参数（带宽 0.010 / 描边 0.0125）下
`pruned = 0`，这里用不上。

## 已知行为与取舍

- **填充与描边是两层、共用一套坐标**：`Fills` 只上色、`Outlines` 只描边，改线宽不
  动几何（就地改 `radius`）。两层几何完全一致，所以描边正好压在色块边界上，不需要
  内缩：相邻色块共用的那条边会看到两笔描边重叠，比自由边略粗 —— 想避免就把它当成
  "勾缝"来看，或者换成编织层。
- **编织的带子是"画在填充之上"的**：带子沿色块边界走、两边各占一半，所以越粗越吃填充
  （画布 10 时 0.010 左右是"勾缝"，0.03 以上编织本身就成了主图）。想要纯线稿观感就
  把「块填充」关掉。
- **编织带宽 / 间隙 / 描边宽属于几何**：缺口按可见半宽算（§13），所以改这三项必须重新
  生成；块轮廓 / 瓷砖线 / 构造线的线宽仍然是就地改 `radius`。
- **编织借不了每块派生的描边色**：一根带子通常横跨多个色块，颜色只能整体给
  （本体默认取色板的绢白，描边层默认墨玄）；`Outlines` 那套逐块派生只对"每块一圈"成立。
- **描边层要跟本体一起开**：`Interlace Case` 就是本体的外扩描边，单开只剩一圈圈深色
  轮廓。它必须比本体宽（差多少就是边的粗细），一样宽或更窄就完全看不见。
- **斜交叉上的端头是圆的**：只有接近 90° 的交叉能用平头端（切面正好压在对方带子的边缘
  线上），45° 交叉用圆头——平头的两个角会在斜交叉上甩出尖角缺口（§13）。整层都没有平头
  时后端不建 `start_cap` / `end_cap` 属性。
- **个别交叉点没有上下之分**：残段修剪（`PRUNE`）会把太短的缺口收回，那两处带子直接
  叠着。同色不透明时看不出来，叠了描边就会看到两圈轮廓互相穿过。实测默认参数下
  `pruned = 0`，用不上这条。
- **瓷砖边只画一次**：`Tiling` 是去重后的边网络，共享边不再并排两条路径，
  所以接缝宽度和自由边一致，也就不会叠画；代价是轮廓不再是闭合路径，
  拐角靠相邻段的端点接合。
- **合并出来的瓷砖没有填充**：`Block3x3` / `Block4x4` 并出来的那块形状不规则，
  匹配不到图案库，所以焦点区域本身永远是空心的。为了保证结果不会变成
  "纯线条图"或"一大块空心 + 零星小块"，`merge_cluster()` 要求并块后至少剩 3 块
  正常瓷砖，否则**直接跳过并块**（按普通设计出图，`Design.focus_skipped = True`）。
- **零填充结果兜底**：万一结果里一块可填充的瓷砖都没有，后端可以按确定性步进换 seed
  重试（最多 8 次），仍不行就报错提示换密度 / 焦点特征。
- **构造线长度**：裁到拼贴区凸包，因此比整条构造线短，但不会溢出主体。
- **近似重合的填充块**：算法固有（相邻瓷砖匹配同一图案簇），由 `_dedupe()` 去掉。
- **颜色抖动**：只影响 2 号以后的色板，同一基色的形状会出现多种相近色；
  按精确色分组会得到上百组，按基色量化则稳定在基色数量左右（分组是后端的事）。
- **虚线疏密**：由步长 `Δ` 决定，与线长无关。
- **六个图层始终都写进对象**：`Outlines` / `Tiling` / `Lines` 默认隐藏（`layer.hide`），
  随时可以打开；显隐是就地切换，不重建几何。

## 性能

- `density 10`：约 70–180 ms；`density 12`：约 120–200 ms；`density 20`：约 170–350 ms；
  `density 24`：约 450–550 ms（含凸包与去重开销，实测 seed 1234 全流程 491 ms）
- 编织的额外开销（seed 1234，仅 `build_layers()`）：`density 10` 34 → 125 ms、`density 20`
  101 → 451 ms、`density 24` 126 → 523 ms；其中平面化本身约 45 / 120 / 190 ms
- 平面化后的边网：`density 10` 4163 结点 / 6076 边，`density 24` 14350 / 21348
- `Block3x3` / `Block4x4` 的并块开销在 1 ms 量级（邻接表 + BFS），可以忽略
- 最密集配置约 6800 条路径 / 4.7 万个采样点；开了编织再加 7526 条（density 24，约 2.9 万
  个点），带描边再翻一倍——`Interlace` 与 `Interlace Case` 是两组同点列的形状

## 调试建议

不依赖任何后端，直接看 `Shape` 列表即可：

- **只看构造线**：过滤掉 `Fills` / `Outlines` / `Interlace Case` / `Interlace` / `Tiling`
  层的形状，只留 `Lines`；
- **检查虚线密度**：`length / (points - 1)` 应为常数（等距采样的判据）；
- **检查重叠**：统计填充形状的 `(顶点数, 面积, 质心)` 是否出现重复；
- **检查颜色抖动**：同一基色的形状应出现多种相近色，但数量应等于基色数量；
- **检查图层配准**：`Outlines` 应与 `Fills` 逐条同形，`Tiling` 的每条边都应落在
  `Fills` 的边界上（所有图层共用同一矩阵）；
- **检查编织**：`build_weave()` 返回的 `Weave` 里 `cuts` 应正好等于 `crossings`
  （每个交叉点切一刀）；`pruned`（残段回收）应该很小，`mismatches`（没能沿带子交替）
  是奇数环逼出来的、不是错误；每条路径的长度都该 ≥ `STUB×可见半宽`，且没有零长线段；
  `caps` 与 `paths` 一一对应，平头端应只出现在接近 90° 的交叉上（约六成端头）；
- **检查平面化**：边网里不该有"端点落在另一条边内部"的结点，也不该有两边内部相交
  却没有结点的地方——这两条是"编织出现重叠的边"的根因（§13 第 1 步）；
- **看上下关系**：`Weave.links` 是 `(交叉点, 段序号, 是否压在下面)` 的清单，同一个
  交叉点上必然一上一下。它只用来做次序分析——**不要**指望按它排出一个全局绘制次序：
  编织的"压上"关系天然有环（连 3×3 平纹棋盘格都成环），这是几何事实，不是实现缺陷。
