# 生成式交错编织（Gen Interlace）

一组股线 → 一上一下的蕾丝，实时画成 Grease Pencil 笔划（扩展 id `gen_interlace`，
Blender 5.2.2 实测）。

股线从**曲线对象**（每条样条一条）或 **Grease Pencil**（每一笔一条）来，交叉处一上一下、
被压住的那一条断开。改股线（拖控制点、在 GP 编辑模式里画一笔）**编织跟着实时重编**。

被压住的那一条怎么断，有两档（面板上的「平贴端头」）：

* **平贴端头**（默认）：退到对方**身外**，退出来的斜缺口用一块**沿对方边缘裁齐的补片**填平
  —— 端头一律平头、轮廓贴平，45° 斜交叉也不会留下大豁口。做法照 `gen_zellij/weave.py`
  的 `tuck` + `_tip_patch`；
* **零重叠**（关掉它）：只切到「刚好被上方股线盖住」，斜交叉时看得见一个楔形缺口。

这一版仍然只用**笔划**（线），不是**带子**（有面积的面域）：补片是「只填不描」的多边形，
跟笔划同色，于是看起来就是同一根股线被削平了一个斜角 —— 用不上布尔库，也扛得住实时。
参考脚本 `interlacing_lab.py` 走的是「偏移带 + 从带子上抠洞」那条路，那套在数学上更完整、
实现上也更容易出错；正式的做法在一份独立的 Manim 项目（`manim-lace`）里，分层见下面的
「与 `manim-lace` 的关系」。这个功能是**纯 2D** 的：三维的交织交给 `gen_celtic`。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Gen Interlace**；
2. 3D 视图侧栏出现 **Interlace** 面板（F3 里也有 `gen_interlace.*` 算子）；
3. 什么都不选直接点「生成」：会先铺一把 7 条正弦股线（曲线对象 `Interlace Strands`），
   再编出 `Interlace` 对象；
4. 点面板上的编辑按钮（铅笔图标）进源物体编辑模式拖点 —— 松手前编织就变了；
5. 出图点「场景预设」：顶视正交相机、2048×2048、Standard 色彩、世界背景铺项目色板的
   `BACKGROUND`，并把 3D 视图背景从「主题」切成「世界」（默认暗色主题下墨玄的线看不清）。

算子：`gen_interlace.generate`（编 / 更新）、`gen_interlace.scatter`（撒一把股线）、
`gen_interlace.delete`、`gen_interlace.edit_source`（进出源物体编辑模式）、
`gen_interlace.sync_from_object`（从对象上记录的参数回读面板）、
`gen_interlace.toggle_source_wire`（源曲线在实体 / 线框之间切）、`gen_interlace.setup_scene`。

## 面板参数

| 分组 | 参数 | 说明 |
|---|---|---|
| 输入 | 股线源 | 曲线（每条样条一条股线，`POLY` / `BEZIER` 都行）或 Grease Pencil（每一笔一条，`cyclic` 当闭合）。源不能是编织对象自己 |
| 编织（改完自动重编） | 上下规则 | `交替` = 沿每条股线按被经过的次序一上一下（真正的编织，默认）；`按股线` = 偶数号恒在上（是分层，不是编织）；`按交叉` = 按交叉的发现次序交替（会自相矛盾，但有的图案好看） |
| | 带宽 | 股线总宽（笔划直径）。切口按它的一半算 |
| | 采样步长 | 贝塞尔细分的目标步长；越小越贴合曲线，交叉检测也越贵 |
| | 平贴端头 | 见上；关掉就回到零重叠切法 |
| | 缝宽 | 只在平贴模式：补片边缘与上方股线边缘之间那条可见的缝，按**半宽**计（0 = 完全贴住，两条股线连成一片；0.25 = 一条细缝，编织看得更清楚） |
| | 浅角钳制 | 两条股线越接近平行，切口越长（`1/sin θ`）；用这个下限钳住 |
| | 间隙 | 只在关掉平贴时用：「刚好被上方股线盖住」之外再留多少可见空隙，按带宽计（0.35 = 每边约 1/3 个带宽） |
| | 圆头端帽 | 只在关掉平贴时用：切口两头用圆头（软）还是平头（利落）。圆头会往外多画半个带宽，已自动补进切口。**与平贴端头互斥**（圆头补不平斜缺口） |
| 外观（就地生效） | 线色 / 不透明度 | 只重写 GP 属性（`vertex_color` / `fill_color` / `opacity`），一笔都不重编 |
| 实时 | 实时更新 | 源物体一变就重编；关掉就只在点「更新」时重编 |

面板底部读数：股线 / 交叉 / 截数 / 补片数、耗时、放宽数（严格交替无解的地方）、源上有多少条股线。

## 算法（`interlace.py`，只依赖 numpy）

```text
Strand(折线 + 闭合标记) → Crossing(交叉事件) → 一上一下 → Piece(可见片段)
```

### 交叉检测

线段先摊平成一张表，然后三段全部向量化：

1. **宽相**：按 `xmin` 排序 + `searchsorted` 算出每条线段右边可能相交的候选上界，用
   `repeat` 摊平成索引表（`_candidate_pairs`）。同一条股线上相邻的两段共用端点，剔掉；
2. **粗筛**：y 区间不重叠的扔掉；
3. **精确相**：线段-线段求交，参数
   `t = cross(起点差, 对方方向) / cross(本方向, 对方方向)`，两边都在 `[0, 1]` 内才算。

**不要**写成 Python 循环逐条扫：实测 1500 段时循环版光循环本身就要 15 ms，向量化之后
整段（含精确求交）不到 1.5 ms。最坏情况仍是 O(n²)（一把几乎竖直的长线段），所以
`build.SEGMENT_LIMIT`（40000 段）兜底。

同一个点上报重复的交叉（端点相接、三线共点）按「股线对 + 坐标取 6 位小数」去重。
三线共点时仍会退化成三个两两交叉，面板的「放宽数」会把这些矛盾显出来。

### 一上一下（`solve_weave`）

沿每条股线按被经过的次序交替::

    over(某次经过) = flag[股线] XOR (这次经过的序号 % 2)

一次交叉有两次经过，必须一上一下，于是约束是::

    flag[b] = flag[a] XOR 1 XOR (pos_a % 2) XOR (pos_b % 2)

`flag` 在约束图上传一遍（BFS，每个连通块从小编号股线取 1）就定下来。这不是「每个交叉
随手翻一下」的近似：同一条股线上相邻的两次经过必然相反，整幅图案才真的一上一下。

**无解处**：自交（同一条股线自己跟自己交叉）时上面的约束退化成
`1 XOR (pos_a % 2) XOR (pos_b % 2) == 0`，也就是那两次经过的序号必须奇偶不同；否则（以及
奇数条约束绕成环时）按「a 在上」放宽，并记进 `stats['relaxed']`，面板上显示
「放宽 N 处」。参考实现同一个策略：宁可标记，不冒充严格交替。

### 切段（`cut_pieces`）

被压住的那一条沿**弧长**切掉一段。两种切法，各自的半宽 `r`：

**平贴端头**（`tuck=True`，默认）::

    r = (h * (1 + cos θ) + gap) / sin θ,     gap = 缝宽 * h

平头的两个角到对方中心线分别是 `r·sinθ ∓ h·cosθ`，取近的那个正好落在对方**边缘**上（多出
`gap` 那条就是看得见的缝）。所以 90° 时 `r = h + gap`、缺口为 0（不用补）；角度越斜退得越远
（45° → `2.4h + gap/sin`、22.5° → `5.0h + …`），退出来那条**斜缺口**交给补片。

补片（`_tip_patch`）：在交叉点的局部坐标里画一块 `s∈[0, r+0.25h]`、`q∈[-h, h]` 的四边形，
再用**对方股线的边缘**当半平面裁一刀（Sutherland–Hodgman，保留 `p·n ≥ h+gap` 那一侧，
`n` ⊥ 对方股线），最后转回世界坐标。于是补片的外缘是一条**平行于对方边缘**的直线 ——
贴平与「不压到对方」同时成立。补片是**只填不描**的笔划（`hide_stroke` + `fill_id` /
`fill_color`，见下一节），颜色与笔划相同，看起来就是同一根股线被削了个斜角。

`tuck` 内部**不能**套「浅角钳制」：截断会让 `r` 短于需要的退让距离，切口一角照样戳进对方
footprint。近乎平行时 `r` 会很大，这时靠**残段修剪**兜底：留下的片段短于 `2h` 就把造出它的
那一刀收回去（那个交叉点两根股线直接叠在一起），宁可少编一个交叉点，也不留一颗浮着的珠子。

**零重叠**（`tuck=False`）::

    r = h / max(|sin θ|, 浅角钳制) + 间隙 * 带宽 (+ h/2，只有圆头才补)

* `h / sin θ`：上方那条笔划在下方股线方向上覆盖的长度的一半。按它切，只要不接近平行，
  切口就刚好被上方笔划盖住 —— 按「固定半径的圆」切是盖不住的；
* 圆头会往外多画 `h/2`（实测：半径 0.05 的圆头笔划比两端点距离长 0.0982，两头各多一个
  半径），所以圆头要补这一项；平头不补（实测 0.9987 ≈ 1.0）。也正因为如此，圆头没法用来
  做平贴端头 —— 它会伸进补片那块缺口里。

弧长落在哪一段用累积长度表查（`arc_tables`），切口折到 `[0, L]` 上（闭合股线跨零点就拆
两段），合并重叠区间后取补集。闭合股线的首尾两段在接缝处**拼成一截**，免得白白多一个断头。

## GP 后端（`gp.py`）

写进 drawing 的属性：

```text
POINT  position      float3  点坐标（GP 自带）
POINT  radius        float   线宽（= 带宽的一半；补片写 0）
POINT  opacity       float   不透明度
POINT  vertex_color  color   线色（线性存）
POINT  strand_index  int     这个点来自第几条股线
CURVE  piece_index   int     这是那条股线上的第几截（补片是 -1）
CURVE  fill_id       int     非 0 = 这块要填充（只有补片用）
CURVE  fill_color    color   填充色（与线色同色）
CURVE  start_cap / end_cap   端帽：实测 0 = 圆头、1 = 平头（字节属性）
```

**Blender 5.2 上必读的几条**（都是实测结论）：

* 新图层 `use_lights` 默认 `True`，没有灯时颜色只剩约四分之一亮度 —— 本后端一律建
  **无光照层**；
* 不给 `miter_angle` 属性：缺它就是**圆角**连接（有它才是斜接）；
* `add_strokes` / `remove_strokes` 是**结构性**改动，改完手里那个 `drawing` 指针就失效，
  再往上 `foreach_set` 会报 `internal error setting the array` —— 必须重新取一次；
* `foreach_set` 长度对不上时 Blender 只报一句 `internal error setting the array`，不说是哪条
  属性，所以每次写之前按领域长度对一遍（`_ensure`）；
* `layer.frames.remove()` 收的是**帧号**（int），不是 `GreasePencilFrame` 对象；
* **端帽是 CURVE 域的字节属性**：`stroke.start_cap / end_cap`，`0` = 圆头（默认）、
  `1` = 平头。没有它们时笔划两头是圆头，切口会显得「被自己填掉一半」；
* **补片 = 只填不描**：`fill_id ≠ 0` + `fill_color` + `stroke.hide_stroke = True`，半径写 0。
  实测（同一张图里放一块只填的、一块又描又填的四边形对照）这样就是干净的填充、没有轮廓线；
  改色时 `fill_color` 要跟着重写，否则补片还是旧色。

**图层复用**：生成对象上只有一层 `Lace`，每轮只把笔划清掉重写，图层本身不重建 ——
实时更新时不重建数据块，编辑模式里也不会被打断。图层固定只有一帧，并且每轮挪到当前帧上。

**颜色不用材质**：`vertex_color` 就够，`build_object` 还会 `materials.clear()`。因此 3D 视图
Solid 模式得把「着色 → 颜色」切到 Attribute 才看得见 —— 生成算子会顺手切一次（`viewport.py`，
与 `gen_torus_knot` 逐字相同）。

## 实时更新（`live.py`）

两段式：`depsgraph_update_post` 处理器只做**廉价判断**（实时开关、源物体类型、编织对象在
不在、股线数过不过上限），通过就往 timer 里排一次「立刻执行」；真正编织在 timer 里跑，走
`build.apply`（先比几何与参数的指纹，都没变就直接返回）。

**为什么不在处理器里编**（教训来自 `gen_celtic`）：撤销 / 重做时 Blender 正在换数据块，
处理器如果此时往生成对象里写几何（`build_object` 开头就是把笔划全删了重建），等于把数据
从它脚下抽走。挪进 timer 之后，写操作一定发生在求值 / 撤销恢复之后。

**两种源的编辑模式都是「活」的**（5.2.2 实测）：

* 曲线编辑模式：不像网格那样另开一份 BMesh，编辑模式改的就是 `obj.data.splines` 本身，
  拖控制点 / 手柄都会触发依赖图更新 —— 所以直接读样条就是最新坐标（实测拖点后编织自动
  从 16 个交叉重编成 20 个，不用点「更新」）；
* GP 编辑模式：编辑的是同一份 drawing 数据，画一笔、拖一下都会触发更新。

**两份指纹**：股线指纹（`strands.signature`，crc32 over 坐标 + 闭合标记）管「源变没变」；
参数指纹（`build.params_key`）管「参数变没变」。都只存 31 位：自定义属性里的整数是 C 的
`int`，写 2³² 以上会抛 `Python int too large to convert to C int`（实测）。

`STRAND_LIMIT`（零重叠 30 / 平贴 12）是保护：交叉数随股线数超线性涨，而平贴模式每处交叉
还要多两块补片，整份重编差不多翻一倍。超过上限就不自动重编（面板上亮一条提示），手动点
「更新」照常工作。

## 实测

Blender 5.2.2，同一台机。「撒一把」出来的正弦辫子（同频、同幅、初相依次错开），
采样步长 0.02、带宽 0.03、缝宽 0.25：

| 股线 | 线段 | 交叉 | 截 | 补片 | 笔划点 | 平贴 | 零重叠 |
|---|---|---|---|---|---|---|---|
| 5 | 355 | 30 | 35 | 30 | 520 | **5.7 ms** | 3.4 ms |
| 7（默认） | 497 | 63 | 70 | 84 | 920 | **11 ms** | 5.9 ms |
| 10 | 710 | 139 | 140 | 218 | 1,750 | **23 ms** | 11 ms |
| 20 | 1,420 | 578 | 577 | 912 | 5,680 | **91 ms** | 43 ms |
| 30 | 2,130 | 1,319 | 1,054 | 1,910 | 10,903 | **185 ms** | 90 ms |

（交叉数随股线数超线性涨：股线越多，每条股线被交叉的次数越多。补片数大约是交叉数的
1.4~1.9 倍 —— 两端各一块，但 90° 附近的缺口太小、按 `_TIP_MIN` 直接跳过。）

默认那一档（7 条股线）的逐项开销：

| 动作 | 耗时 |
|---|---|
| 处理器本身（`on_update`：判断 + 排 timer） | **10.6 µs** |
| `strands.count`（数股线） | **6.8 µs** |
| timer 里空转一次（指纹早退） | **0.17 ms** |
| 整份重编（采样 + 交叉 + 一上一下 + 切段 + 写 GP） | **5.3 ms** |

正确性：对自带的 7 股线辫子，向量化版与「全对全暴力求交」的交叉数**逐个相等**（63 = 63）。
补片是否真的填上了：同一机位开 / 关 `fill_id` 渲染两张图做差，差出 8,504 个像素（900×900
的机位下 84 块补片的可见部分）—— 说明填充确实画出来了，不是只写进属性。

端帽实测（一笔长 1.0、半径 0.05 的笔划，顶视正交渲染后量暗像素范围）：

| 端帽 | 渲染长度 |
|---|---|
| 圆头（`start_cap = 0`） | **1.0982** —— 两头各多一个半径 |
| 平头（`start_cap = 1`） | **0.9987** ≈ 1.0 |

## 模块

```
interlace.py  算法层：交叉检测（向量化）/ 一上一下（奇偶求解）/ 按弧长切段（不 import bpy）
strands.py    股线来源：曲线样条（POLY / BEZIER）/ GP 笔划 → 世界坐标折线 + crc32 指纹
gp.py         GP v3 后端：笔划 / 顶点色 / 端帽 / strand_index / piece_index / 只填不描的补片
build.py      编织入口：指纹比对 → 交叉 → 一上一下 → 切段 → 写对象（算子与实时处理器走同一条路）
props.py      scene.gen_interlace 参数组 + 对象上回存的设计参数
live.py       实时更新：depsgraph_update_post 只判断，编织推迟到 timer 里跑
ops.py        生成 / 撒一把 / 删除 / 编辑源 / 回读参数 / 场景预设
ui.py         View3D > 侧栏 > Interlace
viewport.py   Solid 模式着色检查（与 gen_torus_knot 逐字相同）
palette.py    项目色板副本（改色记得与 _shared/palette.py 同步）
```

`interlace.py` 不 import bpy，可以脱离界面单独跑：`Strand(points, closed)` 组好之后
`find_crossings → solve_weave → cut_pieces`，拿到的是 `Piece` 列表（点列 + 闭合标记）。

## 与 `manim-lace` 的关系

分层是照着那份项目抄的（`PolylinePath → CrossingEvent/Pass → WeaveTopology → 渲染后端`），
但这里只取了「笔划」这一条简化路径：

| | 本扩展（简单版） | `manim-lace` |
|---|---|---|
| 一上一下 | 沿股线交替 + 无解处放宽（计数） | 同一个公式；无解时按 `relax / error / manual` 策略处理，并报**最小见证** |
| 被压的那一条 | 平贴端头：退到 `(h(1+cosθ)+gap)/sinθ`，缺口用「沿对方边缘裁齐」的补片填平；或零重叠：`h/sinθ + 间隙` | 笔划后端同一条公式；**带子后端**直接把「被压带 ∩ 上方带」这块面积扣掉，没有半径近似（补片相当于这一步的手工版） |
| 输出 | GP 笔划（线）+ 只填不描的补片 | 笔划 / 偏移带面域 / 平面剖分三种渲染后端 |
| 洞与面域 | 没有面域：补片是「同色多边形」，只补笔划这一侧的缺口 | 带子有真实面域，洞按 `source_contour` / `occlusion` 分类 |
| 交叉阶 | 两两处理（三线共点会退化） | 判 `transverse / near_tangent / endpoint_touch / overlap / multiway / uncertain` |

也就是说：这个扩展的「一上一下」是认真的（奇偶求解，不是随手翻）；被压的那一条用
**平贴端头 + 补片**做到了「轮廓贴平」（比零重叠那版接近带子后端的观感），但补片只是
「同色的填充多边形」，不是真实的布尔面域 —— 没有描边层、没有面域之间的洞。要那套完整的
东西，得把 `shapely` 一类的 2D 布尔库带进来，扩展必须自包含，所以这一版不做。

## 局限与下一步

* **只有笔划**：补片是「同色填充多边形」，不是真实的带状面域 —— 没有描边层（casing），
  也没有面域之间真正的洞；
* **补片按单轴裁**：一个交叉点只取**一根**对方股线的边缘当裁剪平面。两两交叉时正好，
  三线共点就会露一角（`gen_zellij` 是平面图，一个顶点上有多条通过段，才需要多轴）；
* **切口仍是角度近似**：`sin θ → 0` 时平贴模式的 `r` 会很大（靠残段修剪兜底），真实做法
  是面域相减；
* **三线共点会退化**：同一处三条股线相交时按两两交叉处理，可能得到互相矛盾的上下关系
  （面板的「放宽数」会计数，但不会告诉你哪一处）；
* **`NURBS` 只用控制点近似**（面板上会提示）；`BEZIER` 是自己细分的，不借求值网格；
* **交叉只在 XY 上算**：股线的 z 只用来保持形状（可以贴在一张曲面上），编织本身是平面的。
  这个功能就是纯 2D 的，三维交织见 `gen_celtic`；
* 实时更新是「整份重编」，没有做增量：平贴模式股线一多就慢（10 条约 23 ms），超过
  `TUCK_STRAND_LIMIT`（12）就不自动重编了；
* 生成物**不要进编辑模式改**：每轮重编会把笔划全删了重写。要编辑的是**股线源**。
