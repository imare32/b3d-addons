# 群体模拟（Sim Flocking）

Reynolds boids 跑在 **XY 平面**上：分离 / 对齐 / 聚集三条规则逐帧推进，每只鸟画成一个朝前的
三角箭头（扩展 id `sim_flocking`，Blender 5.2.2 实测）。鸟的位置与速度只有两个分量，方向决定
箭头朝向；一帧一次 `foreach_set` 写完所有几何，不依赖几何节点。

参考实现是 `scripts/flocking.py`（Taichi + 几何节点实例化），这里改成了仓库标准的扩展结构：
NumPy / Taichi 两个后端、结果直接写成网格、鸟数可实时增减、边界方式可选、可以往画面上"撒鸟"。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Sim Flocking**；
2. 3D 视图侧栏出现标签页 **FLOCK**；
3. 点「构建」——自建一个 `Flock Boids` 对象（300 只鸟、20×20 的区域），加进**当前激活的
   collection**（不是场景根），并铺项目画布底色、按模拟区域摆一台正交相机；
4. 播放即实时演化（每帧 2 个子步，24 fps 下缺省速度约 0.8 单位/帧）；
5. 出图点「场景预设」：1600×1000、Standard 色彩、正交相机重新取景。

算子：`sim_flocking.build`、`sim_flocking.reset`（按种子重新撒点）、`sim_flocking.step`
（前进一帧）、`sim_flocking.paint`（撒鸟，模态）、`sim_flocking.setup_scene`、
`sim_flocking.fix_viewport`、`sim_flocking.delete`。

颜色只写在 `color` 角点属性里，而 Solid 视图默认的「着色颜色 = Material」读的是材质单色，
看不出速度色 —— 所以「构建」「场景预设」会顺手把 Solid 视图切成 **Attribute**。播放中要是
又切回 Material，面板会亮一条红色提示，点 `sim_flocking.fix_viewport` 即可。

## 面板参数

| 分组 | 参数 | 说明 |
|---|---|---|
| 群体 / 空间 | 鸟数 | 拖动即补鸟 / 减鸟（已经在飞的鸟不被打断）；上限 20000 |
| | 随机种子 | 初始撒点与初速度的随机源：同种子 + 同参数 = 同一条演化路径 |
| | 宽度 / 高度 | 模拟区域（居中于原点）。区域越大平均间距越远，感知半径要跟着放大 |
| | 边界 | 环绕（缺省，环面）/ 软边界（贴边被推回）/ 反弹（镜像反射） |
| 行为权重 | 分离 / 对齐 / 聚集 | 三条规则的权重 |
| | 分离 / 对齐 / 聚集半径 | 三条规则的感知半径。**聚集半径远大于分离半径**时，鸟群会结成几个不断旋转的团 |
| 运动 | 速度上限 / 操舵力上限 | 速度上限决定飞多快；操舵力上限是把三条规则压回同一量级的关键 |
| | 时间步长 / 子步 | 每帧位移 ≈ 速度上限 × 步长 × 子步 |
| | 随机扰动 | 占操舵力上限的比例：0 = 纯 boids，整群迟早锁成同向直飞 |
| | 后端 | 「自动」= 有 taichi 就用 GPU，取不到直接回退 NumPy（原因写在读数里） |
| 外观 | 配色 | 速度（石青慢 → 苔绿 → 赭石 → 朱砂快）/ 朝向（环形色带） |
| | 箭头长度 | 纯显示量，改它只重画几何 |
| 撒鸟 | 画笔半径 / 每次撒几只 | 在视口里按住左键，落点即鸟的位置（ESC / 右键退出） |

参数生效方式分三档：

- **后端**：下一帧自动重建（容量与初始状态都要重来，跳到第 N 帧会从第 0 帧补算 N 帧）；
- **种子**：下一帧按同一种子重新撒一遍，其余参数不动；
- **鸟数 / 物理 / 边界 / 外观**：下一帧就生效，连重建都不用（鸟数、配色、箭头长度点完立刻
  重画，不用等播放）。

右下角读数：第几帧、鸟数、平均邻居数、平均速率、每帧耗时（指数滑动平均）、上次构建耗时、
后端名与回退原因。

## 模型

三条规则（`d` 是两鸟距离，`v` 是速度，`p` 是位置）：

```
分离  sep = Σ_{0<d<sep_rad} (pᵢ−pⱼ) / (d·(d+ε))       「别撞上」，1/d 加权
对齐  ali = mean(vⱼ)      0<d<ali_rad                  「和大家同向」
聚集  coh = mean(pⱼ) − pᵢ 0<d<coh_rad                 「别掉队」
```

每条规则各折算成一次**操舵**，再按权重求和：

```
steer(t) = clamp( t̂·max_speed − vᵢ , max_force )       t = 0 时返回零力
aᵢ = w_s·steer(sep) + w_a·steer(ali) + w_c·steer(coh) + noise·max_force·rand
vᵢ ← clamp(vᵢ + aᵢ·dt, max_speed)
pᵢ ← pᵢ + vᵢ·dt
```

两条容易忽略但决定画面像不像鸟群的项：

- **`max_force` 截断**必须有：不加截断时，分离力在近距离会爆掉（1/d 在 d→0 时发散），整群抖动；
- **`noise`**：纯 boids 在环面边界下迟早收敛成「整群同向直飞」，加一点点随机扰动才一直有
  转弯与分叉。参考实现没有这一项，这也是本插件缺省参数和它差别最大的一处。

`t = 0` 时返回零力同样是必须的：否则「这个半径内没有邻居」会被解释成「以最大速度冲向原点」，
整个群会塌向中心。

边界三种（`p` 超出即处理）：环绕 = 从对边回来（环面，没有边界感）；软边界 = 靠近边缘时给一个
以 `max_speed` 为单位的推回力，再夹回区域内；反弹 = 夹回区域内并把越界那一维的速度取反。

## 缺省参数怎么定的

缺省是「300 只、20×20 的区域」（平均间距 ≈ 1.1）。参考实现的感知半径（分离 0.5 / 对齐 1.0 /
聚集 1.0）在这个密度下连不上足够多的邻居，实测群体是散的。用「平均离群心距」（越小越聚）比较：

| 参数（分离 / 对齐 / 聚集） | 120 帧后 | 300 帧后 | 观感 |
|---|---|---|---|
| 参考实现（0.5 / 1.0 / 1.0，无噪声） | 8.25 | 6.30 | 散成一片小点，看得出空隙 |
| 0.6 / 1.6 / 1.6（本插件初版） | 8.20 | 6.30 | 同上：1.6 的半径在这个密度下连不住 |
| 0.6 / 2.2 / 2.2 | 5.50 | 4.09 | 收成几团 |
| **半径 2.2 / 2.2 + 噪声 0.1（缺省）** | **4.67** | **3.27** | 收成一团（约占画面 1/3），持续分叉 / 汇聚 |
| 半径 2.2 / 3.0 + 弱聚集 0.7 | 6.19 | 5.76 | 松散，边界上更活跃 |

（20×20 区域的半对角线是 14.1，所以 3.3 已经是一团直径约 7 的群体。）

## 性能

每子步的邻居搜索是 O(n²)。实测（300 只、缺省参数，单位 ms/子步）：

| 鸟数 | NumPy | Taichi（CUDA） |
|---|---|---|
| 300 | 1.2 | 0.50 |
| 1000 | 19.6 | 0.73 |
| 2000 | 79 | 0.64 |
| 5000 | 461 | 1.04 |

一帧缺省 2 子步，所以 300 只时 NumPy 后端约 2.4 ms/帧、Taichi 约 1 ms/帧（含写网格，实测面板
读数约 4 / 2 ms）。**上千只请换 Taichi 后端**：NumPy 后端是为「没有 taichi 也能跑」准备的，
5 千只时一帧要 0.9 秒。

两个后端的初始状态完全一致（都由 NumPy 的 `default_rng(seed)` 生成后上传）：`noise = 0` 时
实测 300 只跑 10 子步后平均速率 / 平均位置 / 平均邻居数逐位相同，差别只在浮点累加顺序。
`noise > 0` 时两边会分叉 —— Taichi 的 `ti.random()` 按线程取种子，不是同一条随机序列
（缺省参数带 0.1 的噪声，所以缺省下两个后端看到的是两条相近但不同的演化）。

## 数据接口

`Flock Boids` 对象上的属性，几何节点 / 着色器可以直接按名字取：

| 属性 | 类型 / 域 | 含义 |
|---|---|---|
| `velocity` | FLOAT_VECTOR / POINT | 每只鸟的速度（同一只鸟的 3 个顶点同值） |
| `speed` | FLOAT / POINT | 速率 `|velocity|` |
| `color` | FLOAT_COLOR / CORNER | 线性 RGBA，一只鸟的 3 个 loop 同色 |

三角形是 3 个顶点一组（`0..3n`），每只鸟一个 polygon，**逆时针**（法线朝 +Z，从上方看是正面）。
材质是 `Color Attribute → Base Color`，外加 0.4 强度的自发光：箭头只有几像素大，只靠世界底色
（暖灰）照明时冷色档会被染暖。节点的属性名**留空**（不设置），由渲染器自动取活跃色属性 ——
填上 `color` / `vertex_color` 会被 Cycles 当成它自己的标准顶点色名，取到空值、渲染成纯黑。

> 插件**接管**这三个属性名：对象上同名的属性如果类型 / 域不对，会被重建成本插件要的形状。

## 模块

```
solver.py        NumPy 求解器（分块暴力扫描）+ 边界 + 参数 + 后端工厂 create()  （不 import bpy）
taichi_solver.py 同一套方程的 Taichi GPU kernel（可选后端）
colour.py        速度 / 朝向 → 逐鸟颜色（只用项目色板）                         （不 import bpy）
mesh.py          三角箭头几何、velocity / speed / color 属性、材质
sim.py           frame_change_pre handler：推进 → 写几何与颜色
scene.py         世界底色 / 按模拟区域取景的正交相机 / 渲染设置
viewport.py      Solid 视图的着色颜色检查（颜色写在属性里，Material 着色看不出速度色）
props.py         scene.sim_flocking 参数组
ops.py           构建、重新撒点、步进、撒鸟（模态）、场景预设、视口修正、删除
ui.py            View3D > 侧栏 > FLOCK
```

`solver.py` / `colour.py` 可以脱离 Blender 单独跑（系统 Python + numpy）：

```powershell
python -c "from sim_flocking import solver; f=solver.create(300, seed=1); f.reset(); [f.step(2, 0.5) for _ in range(60)]; print(f.count, f.mean_neighbours)"
```

## 与参考实现的差别

| | 参考脚本 | 本扩展 |
|---|---|---|
| 组织方式 | 单个脚本（Taichi 现场初始化 + 面板 + 模态） | 扩展包：算法层与 Blender 层分开，可单独测试 |
| 后端 | 只有 Taichi | NumPy 与 Taichi 两档，工厂自动回退 |
| 结果落到场景 | 点云 + 几何节点 `Instance on Points` 实例化三角形，用 Viewer 看颜色 | 直接把三角形写进网格 + `color` 角点属性 + 材质 |
| 上色 | 几何节点里用 `abs(velocity)` 做 Viewer 调试 | 速度 / 朝向两档配色，色板统一 |
| 鸟数 | 面板改鸟数，靠「初始化」重来 | 实时增减（`set_count` 只补 / 砍缓冲尾巴） |
| 边界 | 只有环绕 | 环绕 / 软边界 / 反弹 |
| 噪声 | 无（整群会锁成同向直飞） | 有（`noise`，占操舵力上限的比例） |
| 重建判据 | 每次点「初始化」都重来 | 后端变了下一帧自动重建；种子改了只重新撒点 |
| 交互 | 模态撒鸟（`time.time()` 节流） | 同样有，但回写 `count` 时不会触发重建、也不受时间轴回退影响 |
| handler 清理 | 单脚本，`flocking_update_handler`，无冲突 | `flocking_frame_handler` + **按模块命名空间**清理：`bpy.app.handlers` 是平铺列表、没有分区机制，按名字清场会摘掉别家 sim 插件的 handler（仓库里那几个也都叫 `frame_handler`）。判据用 `handler.__module__`（扩展的 `bl_ext.<repo>.<id>` 前缀，热重载后不变），函数名再带插件前缀，兜住还没改判据的旧版本 |

## 局限与下一步

- **是 2D 的**：位置与速度都在 XY 平面，Z 恒为 0。要做 3D 鸟群得把向量扩到 3 维（两个后端
  都要改，箭头也要改成有厚度的形状），现在没做；
- **O(n²) 邻居搜索**：没有空间网格 / 邻域裁剪。Taichi 后端在几万只以内够快，NumPy 后端上千只
  就开始掉帧；
- **没有烘焙**：演化靠 `frame_change_pre` 实时算，渲染动画时帧要按顺序走；跳帧会逐个补算，
  跳得越远越慢。回退会从第 0 帧重算（保证同一条时间轴每次播出来一样）；
- **编辑模式下 handler 会跳过**（顶点数据由 BMesh 掌管，`foreach_set` 会被丢掉），退出编辑即
  恢复；「构建」也会拒绝在编辑模式下跑；
- **撒鸟的鸟数会写回面板**：撒完再拖鸟数滑杆是继续补 / 减，不会把刚撒的鸟悄悄丢掉；但
  「重新撒点」会按种子重来，撒出来的鸟就没了；
- **配色只按速度绝对值 / 朝向**：没有按「邻居数」或「离群心距离」着色（想看离群个体得自己写
  几何节点读 `speed`）。
