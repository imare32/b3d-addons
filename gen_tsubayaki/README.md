# 生成式弦线族（Gen Tsubayaki）

两条轨道之间的一族**弦**生成器 + Blender 扩展（扩展 id `gen_tsubayaki`，Blender 5.2.2
实测）：内轨按半径 `n`、频率 `t` 转，外轨按半径 `400 - n`、频率 1 转，第 k 步的弦连
"内轨第 k 步"和"外轨第 k 步"，一整圈连完就是一张**星图**；把端点按格子边界裁一刀，
星图就散成贴着方块边缘的短弦，拼出开片 / 冰裂的方形骨架。

算法移植自 Processing / p5.js 版 `Tsubayaki`（原 `ga2/common/tsubayaki_pattern.py`
+ `ga2/scripts/blender_tsubayaki.py`，后者走的是 mesh + 几何节点 `Curves to Grease
Pencil`——等于绕远路回到同一处）；本扩展直接写 Grease Pencil v3，后端沿用
[`gen_rosette`](../gen_rosette/README.md) 里实测过的做法。

## 为什么归在 `gen_*`（生成式）而不是 `sim_*`

判据（见根目录 `README.md`「插件一览」）：`gen_*` 是闭式参数化、参数一改就重编；
`sim_*` 是逐帧推进状态、回退要重置。本扩展两条都落在生成式这一侧：

| 判据 | 本扩展 | `sim_*` |
|---|---|---|
| 时间轴 | `n` / `t` 由**帧号闭式**给出（`anim.params`），第 N 帧不依赖第 1..N-1 帧 | 第 N 帧必须从第 1 帧顺序推出来 |
| 跨帧状态 | 没有。`generate()` 是纯函数，输出只由入参决定 | 有一份被逐帧就地改的状态 |
| 跳帧 / 回退 | 任意跳、任意回退，结果一样（也不用重置） | 回退 = 从头重算 |
| 参数改动 | 当场重算一帧（0.1 ms 量级），所以**没有"更新"按钮** | 改动通常要重置再跑 |

参考脚本里 `t` 是在 `draw()` 里**累加**的（`t = t + 0.05`）外加一个 `reset_on_frame_one`
开关——那是"模拟式"写法。这里换成闭式后，那个开关是恒等式（第 1 帧增量本来就是 0），
它的位置由"以**场景起始帧**为基准"取代，于是可以只渲染中间某一帧。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），在偏好设置里启用 **Gen Tsubayaki**；
2. 3D 视图侧栏出现 **Tsubayaki** 面板（F3 里也有 `gen_tsubayaki.*` 算子）；
3. 点「生成」得到一族弦；拖时间轴看它逐帧生长（弦变多、星图变密、墨色退去）；
4. 要直接出图点「场景预设」：2048×2048 正交相机、Standard 色彩、GP 抗锯齿 16、
   世界背景铺面板上的底色（默认墨玄 `INK`）、挂上 GP 自带的辉光，取景按生成对象的
   实际包围盒。

默认是**深底反白**：底色 `INK`、墨色绢白 `SILK`、开辉光——亮线落在深底上就是发光的样子。
想回到纸感就把「背景」切成 `PAPER`（纸底），墨色自己调深（例如墨玄）。

算子：`gen_tsubayaki.generate`、`gen_tsubayaki.delete`、`gen_tsubayaki.setup_scene`。

## 面板参数

| 分组 | 参数 | 说明 |
|---|---|---|
| 图案 | 模式 | `SINGLE` 单轨星图 / `TILED` 分块裁剪 |
| | 象限变体 | `VAR_1..VAR_4`（参考的 `freq_mult = qx + qy * 4`，四格正好是 5 / 7 / 13 / 15 倍频）；`ALL` = 四格整铺 2x2（**本扩展补的**，参考一次只画一个变体） |
| | 裁剪边界 | `TILED` 时端点被按到 ±这个值（默认 180 = 单块 360 的一半）；`SINGLE` 下置灰 |
| | 单块边长 | `TILED` 的单块大小（默认 360）；「单块边长 − n」同时是外轨半径 |
| 生长 | 跟时间轴生长 | 开：`n = 初始 n + (帧 − 场景起始帧) × 每帧增量`（`t` 同理）；关：只用初始值，图案不随时间轴变 |
| | 初始 n / n 每帧增量 | 默认 1 / 0.5；**弦数 = 2n**，所以这两项决定"长多快、长到多密" |
| | 初始 t / t 每帧增量 | 默认 0 / 0.05；`t` 变大 = 内轨拧得更紧，同时触发帧级墨色衰减 |
| 起伏 | Z 向振幅 / 频率 | 默认 0 / 2。振幅单位是**设计坐标**（±180 量级），随画布等比缩放；> 0 时深度排序自动切 3D |
| 墨色 | 墨色 | 所有弦共用一个色（面板上是 sRGB，写进顶点色前转线性；默认项目色板的绢白 `SILK`，配墨底就是反白） |
| | 墨韵淡出 | 逐弦淡出（参考的 Color Ramp：首弦最浓、末弦只剩「余墨」） |
| | 墨色衰减 / 末弦余墨 | 帧级墨量 = `(256 − t × 衰减) / 255`（衰减默认 4，参考硬编码值）；余墨默认 0.1 |
| 墨色 | 辉光 | 给对象挂 / 摘 GP 自带的 `FX_GLOW` 效果器（默认开，**不走合成器**） |
| | 辉光半径 / 强度 / 采样 | 半径单位是**渲染像素**（2048 见方默认 24，给太大会摊薄成灰雾）；强度默认 1、采样默认 32 |
| 画布 | 画布 / 边距 | 世界单位；图案等比缩放、居中放进 `[0, 画布]` 的方块 |
| | 笔划半径 | 世界单位，线宽 = 2 × 半径，**不随画布缩放** |
| 图层 | 显示弦 | 只切图层显隐（`layer.hide`），不动几何 |
| 渲染 | 背景 | `DARK` 墨底 `INK`（默认）/ `PAPER` 纸底 `BACKGROUND`；改了当场重铺世界底色 |
| | 场景预设 / 删除 | 相机、色彩、抗锯齿、底色与辉光；删掉生成对象 |
| 状态 | 帧 / n / t / 弦数 / 墨量 / 耗时 | 只读读数，另外显示图层数 / 笔划数 / 属性数与 `stroke_depth_order` |

**没有"待更新"这一档**：任何一项参数一改就按当前帧当场重画（闭式重算 0.1 ms 量级，
见「性能」），所以拖滑块时图案是跟手的，「生成」只管第一次建对象（以及删掉之后的
再来一次）。这也是本扩展和 `sim_*` / 早期 `gen_*` 面板手感上最明显的差别。

## 图层语义

只有一个图层：

| 图层 | 内容 | 默认 |
|---|---|---|
| `Chords` | 全部弦：每根弦一笔（2 点的 `POLY` 笔划），逐弦不透明度来自「墨韵淡出」 | 显示 |

写进 GP 的数据（属性名都是 GP v3 内置的，实测于 Blender 5.2.2）：

| 属性 | 类型 / 域 | 内容 |
|---|---|---|
| `position` | `FLOAT_VECTOR` / POINT | 世界坐标 |
| `radius` | `FLOAT` / POINT | 笔划半径（**逐点**属性，这里每根弦写同一个值） |
| `opacity` | `FLOAT` / POINT | 逐点不透明度：一根弦两个点取同一个值，逐弦淡出写在这里 |
| `vertex_color` | `FLOAT_COLOR` / POINT | 线性 RGB，**alpha 恒写 1** |

> 实测结论：真正控制渲染透明度的是 `opacity`（线性），`vertex_color` 的 alpha 通道
> 渲染时被忽略。踩过这个坑之后，淡出只走 `opacity`，顶点色只负责颜色。

对象上还有两处**非几何**的设置，每次重写都顺手保一遍：

| 设置 | 值 | 为什么 |
|---|---|---|
| `obj.use_grease_pencil_lights` | `False` | GP 笔划默认吃场景光，环境项是 `world.color`（不是 `Background` 节点）。墨底线性才 0.024，会把线色乘小四十倍，渲出来只剩一片灰雾（实测线芯 0.029 而不是 0.905）。关掉灯光后顶点色就是最终颜色 |
| `obj.shader_effects["Glow"]` | `FX_GLOW` | 发光用 GP 自带的效果器，`mode=LUMINANCE` / `threshold=0` / `blend_mode=ADD` / `use_glow_under=False`，`glow_color` 跟着墨色走。**不碰合成器** |

**只写一帧画**：GP 会把最后一张画保持到后面的帧，所以对象里永远只有 1 帧几何，
逐帧重算交给 `frame_change_pre` 处理器——而不是每帧存一张画（250 帧就是 250 份几何，
跳帧还得先把前面顺序算出来，那是模拟式的做法）。

## 算法

一行公式就能写完，这里拆成四块讲清楚"参考怎么做 → 这里怎么做"。

### 1. 单轨星图（`pattern._single`）

`n` 既是内轨半径也是角步长：轨道角 `r = arange(0, TAU, PI/n)`（**端点不取 2π**，
与参考的 `for` 循环一致，所以弦数是 `ceil(2n)` 而不是 `2n`），第 k 步的弦是

```
内轨端点 = ( n·sin(r_k·t), n·cos(r_k·t) )
外轨端点 = ( (400 − n)·sin(r_k), (400 − n)·cos(r_k) )
```

`t` 是内轨频率：`t` 偏离 1 越多，内端点越快地在圆周上跑，弦就越拧——整数 `t` 会退化成
`t` 组重合的弦，所以动它一般取非整数（默认每帧 +0.05）。Z 向起伏走两条不同的相位
（`sin(freq·r·t)` / `cos(freq·r)`），于是弦在空间里真的互相穿过。

### 2. 分块裁剪（`pattern._quadrant`）

象限变体 `(qx, qy)` 是**格心在 180 单位下的坐标**，倍频取 `freq_mult = qx + qy·4`：

```
q = r · t · (qx + qy · 4)
端点 = clip( …, ±裁剪边界 ) + 格心偏移
```

两处 `clip`（`np.clip` 顶掉 Processing 的 `constrain`）就是"分块裁剪"的全部：参考里
`n` 和 `单块边长 − n` 常常大于裁剪边界（默认 `n` 很快就会超过 180），端点于是被按到
格子的边上——弦不再"绕圆"而是贴着方块边缘走，一串短弦拼出方形的开片骨架。

- 单个变体：**照参考居中放在原点**（参考把格心偏移丢掉了）；
- `ALL` 四格整铺：把四个变体的格心补回来（`±单块边长/2`），四格各自裁到 `±裁剪边界`，
  拼成边长 `2 × 单块边长` 的整张——`裁剪边界` 小于半格时，格间留缝，正好把"分块"画出来。

### 3. 帧 → 参数（`anim.params`）

```
n = 初始 n + (帧 − 场景起始帧) × n 每帧增量
t = 初始 t + (帧 − 场景起始帧) × t 每帧增量
```

两条都是**线性闭式**（就是参考的 `n = n + 0.5` / `t = t + 0.05` 的积分形式），
所以第 N 帧可以直接算出来。处理器只在帧变了的时候按当帧参数重算一遍，不累积任何东西。

### 4. 墨色（`pattern.frame_ink` / `pattern._alpha_for`）

- 帧级墨量：`ink = clamp((256 − t × 衰减) / 255, 0, 1)`（衰减默认 4，参考硬编码）；
- 逐弦淡出：`alpha = ink × (1 − (1 − 末弦余墨) × linspace(0, 1, 弦数))`——
  就是参考那条 Color Ramp（首端 `ink`、末端 `ink × 0.1` 线性插值）；
- 关掉「墨韵淡出」则 `ink = 1`、全部弦同墨。

这两个值与 `t` 挂钩，所以"生长"是**两件事同时发生**：弦变多（`n` 涨）、整族变淡（`t` 涨）。
`t` 到 `255 / 衰减 ≈ 64`（默认参数）时墨量归零，画面只剩空白——想让它一直画下去就
把「墨色衰减」调小或关掉「墨韵淡出」。

## 模块划分

| 文件 | 职责 |
|---|---|
| `pattern.py` | 算法层：两条轨道之间的弦族（`n` / `t` → `Pattern`），含 `chord_count()` / `frame_ink()` |
| `scene.py` | 输出契约：`build_layers()` 得到 `StrokeSet`（等比缩放 + 居中 + y 翻转），并判定 GP 深度排序 |
| `gp.py` | GP v3 渲染后端（图层 / 顶点色 / 逐点不透明度 / 逐帧重写 / 关灯光 / 辉光效果器） |
| `anim.py` | 帧 → `(n, t)` 闭式参数 + `frame_change_pre` 处理器 + 重写指纹缓存 |
| `props.py` | `scene.gen_tsubayaki` 参数组 |
| `ops.py` | 生成 / 删除 / 场景预设 |
| `ui.py` | `View3D > 侧栏 > Tsubayaki` 面板 |
| `viewport.py` | 生成前把 Solid 视图着色切到顶点色（否则 GP 全黑） |
| `palette.py` | 项目色板的逐字副本（源 `_shared/palette.py`） |

`pattern` / `scene` **不 import bpy**（只用 numpy），可以脱离 Blender 单独跑：

```python
from gen_tsubayaki.pattern import generate

pattern = generate(n=24, t=0.0)
pattern.points  # (2m, 3) 设计坐标
pattern.alpha  # (m,) 逐弦不透明度
```

`gp` / `anim` / `props` / `ops` / `ui` 只在 `register()` 里导入，所以 `import
gen_tsubayaki` 本身在纯 Python 下也成立（同一套代码顺手当库用）。

**同步义务**：`palette.py` / `viewport.py` 是 `gen_rosette` 的逐字副本，改色板或改视口
检查时两边一起改（`Get-FileHash` 比对即可确认同步）。

## 与参考实现的差异

| 改动 | 为什么 |
|---|---|
| 逐点 `append` 的循环 → numpy 整段运算 | 同一个式子，结果逐点对拍一致；`pattern.py` 一共 319 行 |
| 去掉归一化（参考末尾 `1/180 * scale`） | 一律输出**设计坐标**（就是参考的像素坐标：象限边界 ±180、单块 360），居中 / 等比缩放 / 单位换算交给 `scene.py`。于是参考的 `scale` 参数消失（`scale = 1.5` ≈ "画布 3 单位、边距 0"，其余都是同一个等比缩放） |
| 补 `ALL` 四格整铺 | 参考的 `TILED` 只画一个变体、居中放在原点（格心偏移丢掉）；想看"整张分块图案"就得自己拼，这里直接给一个选项 |
| `t` 累加 → 闭式 | 见「为什么归在 `gen_*`」 |
| mesh + 几何节点 `Curves to Grease Pencil` → 直接写 GP v3 | 弦线本来就是"一笔一笔的线"，直接写省掉一整层节点树，也不用管材质 |
| 逐弦淡出写 `opacity` | 实测 `vertex_color` 的 alpha 被忽略（见「图层语义」） |
| 关掉 GP 灯光 + 挂 `FX_GLOW` | 参考是白底黑线；这里要的是**深底发光**。GP 笔划默认吃 `world.color`，墨底会把线色乘没，必须关灯；辉光用 GP 自带效果器，不动合成器 |

## 已知行为与取舍

- **弦数是逐帧变的**（`2n` 随 `n` 长），GP 后端因此按需重建笔划：弦数变了就清空重建，
  同拓扑只改属性；代价是每帧一键重写，好处是不留残影。
- **`n` / `t` 上限是"画得动"的上限**，不是数学上限：`n = 400` 时弦数是 800（`ALL` 3200），
  整链仍是 0.3 ms 量级；再往上参考的 `400 − n` 就变负了，图案会翻到对面去。
- **墨量会归零**：`t ≥ 255 / 墨色衰减`（默认 ≈ 64）之后整族全透明，画面是空的——这不是
  bug，是参考自带的"墨迹退去"。默认参数下 `t` 涨到 64 是第 1281 帧。
- **Z 向起伏在俯视相机下看不见**：图案画在 XY 平面，俯视时起伏只体现为互相遮挡；想看
  起伏要转视角，开了之后 `stroke_depth_order` 自动从 `2D` 切成 `3D`。
- **`2D` 深度排序才是默认该有的样子**：共面时用 `3D` 会让深度相同的笔划互相打架
  （谁压谁没定义），`2D` 按存储顺序画，等价于 Processing 的画家算法，稳定可复现。
- **`y` 翻转会把 `VAR_2` / `VAR_3` 对调**：弦线族关于原点镜像对称，所以照仓库惯例走
  y 翻转，代价就是同一张图换个镜像看——核对参考输出时记住这一条。
- **`SINGLE` 下「裁剪边界」「单块边长」无效**：那两项只进分块裁剪分支（面板里置灰）。
- **边距只保证几何在框内**：线宽是独立的笔划半径，`边距 = 0` 时线宽会溢出画布半个半径。
- **弦族是直线不是曲线**：参考就是两点直线（Processing 的 `line()`），GP 里也是 2 点
  `POLY`；想要更柔的观感只能自己改采样密度。
- **GP 笔划默认是"吃光"的，这里把它关掉了**：`use_grease_pencil_lights = False` 写进
  `gp.write` / `gp.update`，所以线色永远是面板上的墨色。副作用是对象不再受灯光影响——
  这个图案本来就该是"发光的线"，不想要这种表现就自己把那个开关打回 `True`（深底会立刻
  暗下去，因为环境项是 `world.color`）。注意它和 `Background` 节点无关：只改节点不改
  `world.color` 时，背景会变、线不会跟着变，很容易误判成"辉光把线吃掉了"。
- **辉光半径的单位是渲染像素**：2048 见方下 `24` 是贴边的一层光，`40` 往上就开始摊薄，
  `160` 基本只剩整体发灰；采样太少（8）时大半径会变成脏雾。所以默认 `24 / 1.0 / 32`
  是"看得出在发光、又没糊"的一档，改分辨率时记得一起调。
- **辉光是对象级效果器，不是合成器**：只在 EEVEE 下参与渲染（Workbench 预览看不到）；
  删掉对象时连带消失，不需要额外清理。
- **处理器里绝不抛异常**：闭式重算出错只会把信息记进面板的「错误」一栏，不打断播放。

## 性能

两层都便宜到可以每帧重算，所以没有缓存几何、也没有"更新"按钮。

| 配置 | 弦数 | `generate`（纯 numpy，系统 CPython 3.13 + numpy 2.5.4，200 次均值） | 整链（`generate` → `build_layers` → `gp.update`，Blender 5.2.2 内实测，50 次均值） |
|---|---|---|---|
| `SINGLE` / `n = 24` | 48 | 19 µs | 0.082 ms |
| `SINGLE` / `n = 96` | 192 | 21 µs | 0.060 ms |
| `SINGLE` / `n = 400`（`MAX_N`） | 800 | 36 µs | 0.092 ms |
| `TILED` `ALL` / `n = 24` | 192 | 79 µs | 0.123 ms |
| `TILED` `ALL` / `n = 96` | 768 | 99 µs | 0.159 ms |
| `TILED` `ALL` / `n = 400` | 3200 | 0.29 ms | 0.302 ms |

读数时注意：这些都是 0.1 ms 量级，"整链"里 GP 重写只占其中一小截，所以数字受缓存与
噪声影响不小（`SINGLE` 三档的耗时基本与弦数无关，就是这个原因）；真正的量级结论只有
一条——**一帧重算的成本远低于一帧的显示时间**，所以拖时间轴、拖滑块都是跟手的。

默认参数（`初始 n = 1` / `每帧 +0.5`）下，第 100 帧是 `n = 50.5`（101 根弦，
`ALL` 404 根），到 `MAX_N` 要第 799 帧——正常动画根本跑不到成本上限。

## 调试建议

- **脱离 Blender 对拍**：`pattern` / `scene` 不 import bpy，所以

  ```powershell
  cd c:\git\b3d-addons
  python -c "from gen_tsubayaki.pattern import generate; p = generate(24, 0.0); print(p.chords, p.bounds, p.alpha[:3])"
  ```

  拿它和 Processing 版的输出逐点比，是最省事的正确性检查（移植时就是这么对的）。
- **检查弦数**：`SINGLE` 应满足 `chords == chord_count(n)`（`ceil(2n)`）；`TILED` `ALL`
  应恰好是它的 4 倍（四个变体各一份）。`n = 24` → 48 / 192。
- **检查墨量**：关掉「墨韵淡出」时 `ink` 恒为 1；开着时 `ink == clamp((256 − t×衰减)/255, 0, 1)`，
  面板状态栏里的「墨量」就是它。
- **检查深度排序**：「Z 向振幅 = 0」必须是 `2D`，非 0 必须是 `3D`（面板底部直接显示）。
- **检查"只写一帧"**：`obj.data.layers[0].frames` 应恒为 1 帧，切帧后笔划数与 `弦数` 一致。
- **检查处理器没有堆叠**：反复启用 / 重载扩展后，`frame_change_pre` 里应只有**一个**
  `frame_change`（`anim.purge_handlers()` 按函数名清理）。
- **画面全黑**：Solid 模式下视图着色要在「生成」时切成顶点色（`viewport.ensure_vertex_colour`
  会处理并回报）；渲染全黑则多半是没跑「场景预设」——世界背景没铺底色、色彩管理也不是
  Standard。
- **线在深底上几乎看不见**：先查 `obj.use_grease_pencil_lights`（必须 `False`）。开着时
  线色被乘上 `world.color`，墨底线性 0.024 → 线芯只剩 0.03，统计上就是"背景 0.169、最大
  0.184、比背景亮 5% 的像素 0 个"。关掉后线芯应回到面板墨色的线性值（绢白 ≈ 0.905），
  这个数字比肉眼看图可靠。
- **辉光没效果**：`obj.shader_effects` 里要有 `Glow`；渲染引擎必须是 EEVEE；半径给太大
  会把能量摊薄（先试 24，再试 80 对比）。逐像素比开 / 关两张图，差值的最大值应该在
  0.25 量级——为 0 才是真的没挂上。
