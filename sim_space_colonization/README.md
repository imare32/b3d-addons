# 太空殖民生长（Sim Space Colonization）

在**任意输入网格**的表面上撒吸收点，让枝条逐帧朝它们长过去 —— 太空殖民算法（space
colonization）的实时模拟（扩展 id `sim_space_colonization`，Blender 5.2.2 实测）。

给定一个网格（雕塑、零件、随便什么），插件按面积加权在它的表面撒点，从根顶点组出发逐帧
生长：枝条爬满整个表面，分叉处自然变粗，枝尖最细。`贴表面` 模式像藤蔓一样沿曲面爬，
`自由空间` 模式则让枝条在空间里跨过凹陷。

**结果是 Grease Pencil 笔划**（不是网格）：每个分叉到下一个分叉 / 枝尖是一笔，逐点半径让
枝条从根到梢收细，逐点颜色给**根→梢的渐变**（石青 → 苔绿 → 赭石）。不需要材质、不需要
几何节点，笔划本身就是成品。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Sim Space Colonization**；
2. 3D 视图侧栏出现 **Colonize** 面板（F3 里也有 `sim_space_colonization.*` 算子）；
3. 在视图里选中要长东西的网格 —— 点「构建生长」时会自动填进「目标网格」；
   **什么都不选也能点**：会自己建一只缺省的输入网格（细分过的猴子，名字
   `Colonization Target`，同名对象已存在就复用），装好插件就能直接看效果；
4. 点「建根顶点组」：在世界空间最低的顶点上建 `root` 顶点组（也可以自己刷：组里放几个
   点就长出几丛；没有这个组就用最低点当根，所以这一步是可选的）；
5. 点「构建生长」，然后播放或点「+1 帧」：每一帧按「子步」向前长一批；
6. 出图点「场景预设」：按目标网格包围盒建 3/4 视角正交相机、世界底色铺项目色板的
   `BACKGROUND`、切 Standard 色彩。

算子：`sim_space_colonization.build`、`reset`（从头再长）、`step`（时间轴 +1 帧）、
`make_root`（建根顶点组）、`setup_scene`、`fix_viewport`、`toggle_target_wire`
（目标网格在实体 / 线框之间来回切）、`delete`。

> Solid 视图默认按「着色颜色 = Material」显示，而 GP 的颜色写在属性里、材质槽是空的 ——
> 这时线是**全黑**的。所以「构建」「场景预设」会顺手把 Solid 切成 **Attribute**；播放中
> 又切回 Material 时面板会亮一条红色提示，点 `fix_viewport` 即可。材质预览 / 渲染模式本来
> 就正常。

## 面板参数

**所有长度参数都是相对「目标网格包围盒对角线」的比例**（0.012 = 对角线的 1.2%），换算成
世界单位在 `sim.py` 里做。这样换一个 1 cm 的小零件和 10 m 的建筑，同一套参数都成立。

| 分组 | 参数 | 说明 |
|---|---|---|
| 输入网格 | 目标网格 | 任意网格对象；吸收点按**面积加权**撒在它（求值后）的表面上。留空 = 构建时自动建/复用缺省网格 `Colonization Target`。右边那个线框小按钮切「显示为：线框 / 实体」——目标网格套在藤蔓外面时切成线框才看得见里面的笔划（切回来时还原你自己原来的显示方式） |
| | 根组 | 根顶点组名，缺省 `root`：组里放几个顶点就长出几丛；没有这个组就退化成最低点 |
| | 约束 | `贴表面` = 藤蔓沿曲面爬（方向先压到切平面再贴回表面）；`自由空间` = 枝条在空间里长向表面吸收点 |
| 吸收点 / 搜索 | 吸收点 | 撒多少个点（2500 缺省）：越多枝条越密、每帧越贵 |
| | 随机种子 | 撒点与生长抖动共用；同种子 + 同参数 = 同一棵树 |
| | 后端 | 「自动」依次试 KD 树 → taichi GPU → 纯 NumPy，回退原因写在读数里 |
| | 子步 | 每帧推进几个子步 —— **唯一的生长速度旋钮** |
| 算法 | 吸引半径 | 吸收点能把方向投给多远的节点：太大 = 整棵树一起冲，太小 = 只有尖端在长 |
| | 消耗半径 | 吸收点离节点多近算被吃掉：越小枝条越密、越长（要小于吸引半径） |
| | 生长步长 | 每子步长多长；缺省 ≈ 吸收点平均间距的一半 |
| | 持久度 | 0 = 完全跟着吸收点走（容易乱拐），0.8 = 很挺拔 |
| | 抖动 / 表面偏移 / 节点上限 | 每步的方向扰动、贴表面时沿法向抬起的高度、节点数硬上限 |
| 外观 | 最细半径 / 梯度 | 枝尖半径 + Murray 指数（`r = 最细半径 × 叶尖数^梯度`） |
| | 倍数 | 整体放大笔划半径（拖滑块当场重画，不动求解器） |
| | 配色 | 生长深度（石青 → 苔绿 → 赭石，**根到梢的渐变**）/ 粗细（赭石 → 苔绿 → 墨玄） |

三档参数的生效方式不同：

- **算法 / 子步**：下一帧就生效，不重建（历史节点不回溯，从当前位置继续长）；
- **外观**：当场重画当前帧；
- **输入 / 取样 / 后端**：进签名，下一帧由 handler 自动重建（也可以手动点「构建生长」）。

右下角读数：当前帧、节点数、**笔划数**、剩余吸收点数（吃完就停）、后端名与回退原因、
每帧耗时。

## 算法

每一子步（Runions 等 2007 的经典形式）：

1. **最近邻**：每个吸收点找离它最近的树枝节点（这一步是开销大头，见下）；
2. **消耗**：距离 ≤ 消耗半径的吸收点被吃掉；
3. **聚拢**：距离 ≤ 吸引半径的吸收点把单位方向投给它的最近节点，节点把收到的方向**求和**
   并归一化；
4. **生长**：`新方向 = (1−持久度)·平均方向 + 持久度·旧方向`，再加抖动、归一化，沿它推进
   生长步长，新节点挂在这个节点下面。

半径按 **Murray 定律的离散版**：叶子（没有子节点的节点）记 1、往上累加子孙叶尖数，
`r = 最细半径 × 叶尖数^梯度` —— 根粗尖细，分叉处自然变粗。缺省 `最细半径 = 0.0045`、
`梯度 = 0.2`（相对包围盒对角线）。

> 早先这里用「每个节点都当一片叶子」起手，累出来的是**子树节点数**而不是叶尖数：一条只有
> 一片叶子的长枝会被算成 60，半径凭空粗 4 倍，「叶尖多枝条细」的原则反成了「枝条越长越粗」。
> 这正是枝干粗细忽然变得很丑的根因 —— 现在只认真正的叶子（`children == 0`）。

### 一个必须绕开的坑：贴表面不能只做投影

一个点被一整圈吸收点围住时，平均方向正好顶着曲面法向、切向分量互相抵消 —— 只做投影的话
枝条会原地打转，一个节点都长不出来。所以先把方向压到切平面（退化时用一个垂直轴兜底），
而且**抖动放在持久度之后**（放在前面会被持久度那一项冲掉）。

### 笔划怎么来：拆链 + 三遍平滑

GP 的一笔是一条折线，而节点树是**图**，所以先把树拆成**链**（`solver.branch_chains`）：
一条链 = 从根或某个分叉点走到下一个分叉点或枝尖。分叉点在相邻两笔里各出现一次，端点
重合；配上 GP 的圆头笔帽，接头看起来就是一整根藤分出来的。

写进 GP 之前还会把显示用的几何捋一遍（`solver.display_geometry`，只动显示副本，
**求解器状态一个字节都不改**，生长轨迹照旧）：

1. **捋顺折线**：沿父/子做 2 遍拉普拉斯平滑（根钉住），一格一格的锯齿变成连续曲线；
   位移上限约一个生长步长（0.037 / 步长 0.044）；
2. **抹平半径台阶**：半径是按**整数叶尖数**算的，分叉处会突然跳一截 —— 沿树做 8 遍邻域
   平均，**但在对数域里**：半径是乘性的（每级分叉乘一个比值），线性平均会把粗枝细枝混成
   均值、过渡带反而更糊；取对数后「每级掉多少」变成可加的量，平滑出来才是一条指数渐变的
   锥度。平滑会顺手削薄主干，所以最后按「最大半径不变」整体缩放回去。实测相邻节点的最大
   跳变 0.057 → 0.032，98% 的边半径比 < 1.1、94.6% 的边跳变 < 最大半径的 5%；
3. **收尖叶尖**：末梢往回 5 个节点把半径收到 25%，梢头是尖的，不是一刀切平。

### GP 后端的三条硬约定（5.2.2 实测）

- 颜色不靠材质：`vertex_color`（POINT，FLOAT_COLOR）按**线性**存，色板的 sRGB 必须转线性；
- `layer.use_lights` 新建时默认 `True`，无光照层（`False`）才是所见即所得 —— 线稿就该这样；
- 点坐标是 3D，`stroke_depth_order = '3D'` 是逐像素深度遮挡：藤蔓自己穿过自己时靠前的段
  会切掉靠后的一段，切口是笔划自身的圆头轮廓。

## 搜索后端

最近邻搜索三档，同一套生长逻辑：

| 后端 | 依赖 | 2500 吸收点 × 3000 节点 |
|---|---|---|
| **scipy `cKDTree`**（自动时优先） | 需要 `scipy`（按根 README 装在 modules 目录即可） | **1.9 ms/子步** |
| **Taichi GPU**（暴力并行） | 可选，`import taichi` 成功才用 | 1.4 ms/子步（cuda） |
| **NumPy**（回退） | 只要 Blender 自带 numpy | 18.6 ms/子步 |

三者结果逐位一致（同种子、同参数 → 节点数 / 剩余吸收点完全相同）。`--factory-startup`
启动时 taichi 会「装了却用不上」，原因与兜底见根 README 的「Python 环境」。

实测（细分过的猴子当目标，对角线 3.64，2500 吸收点）：构建 3~17 ms；第 60 帧 5529 节点 /
4281 笔划；长到 5 500 节点时每帧约 9 ms，**生长停下后降到 0.02 ms** —— 每帧开销怎么来的、
怎么把这个数压下来，见下节。

### 每帧开销：为什么「长满了反而掉帧」，以及怎么治

播放时每显示一帧（`frame_change_pre`）就是「推进生长 → 拆链 → 平滑 → 整丛重画笔划」，
这几步全是 **O(节点数)** 的。节点数随生长一路上涨，于是每帧耗时也跟着涨 —— 树越大越慢。
真正的坑在于**生长停下之后**：拓扑不再变，可这全套活儿照样每帧跑一遍，于是画面明明已经不动，
帧率却卡在最低点。这正是「生长基本完成时突然掉帧、跑不满 60」的原因（不是长满了变慢，
而是**不长了还一直在算**）。

三处改动（都在 `solver.py` / `sim.py`，输出与改前逐位一致）：

1. **没变就跳过**：`_write` 先比一个指纹（节点数 + 粗细 / 梯度 / 倍数 / 配色）。生长停了以后
   指纹每帧都一样，直接 return —— 停滞期从每帧二三十毫秒降到 **0.02~0.06 ms**，稳稳 60 帧；
2. **`branch_chains` 向量化**（10.7 → 0.9 ms）：逐节点建邻接表、再逐节点走链的 Python 双循环，
   换成「最近链头传播 + 一次稳定排序」，链天然落在连续区间里。顺带修掉一个**多根 bug**：
   原代码 `heads[parent]` 在 `parent == -1` 时会命中 Python 负索引 `heads[-1]`（最后一个节点），
   把额外根塞错地方、画出跨节点的假笔划；
3. **`display_geometry` 向量化**（36.9 → 2.9 ms）：`_taper_tips` 的逐叶双重循环换成按「层」推进
   （17.2 → 0.3 ms），`_smooth_radii` / `_smooth_positions` 的 `np.add.at` 换成 `bincount`
   （11.5 → 1.3 ms）—— `np.add.at` 是无缓冲逐元素累加，实测慢 2.7 倍。

对照（同一棵树，20 000 节点上限）：每帧耗时随节点数线性上涨，封顶后 **0.02 ms**。

| 帧 | 改前 | 改后 |
|---|---|---|
| 32（2 747 节点） | 7.9 ms | 6.7 ms |
| 92（8 601 节点） | 17.4 ms | 12.8 ms |
| 182（17 241 节点） | 31.2 ms | 21.9 ms |
| 212 起（20 000 节点，生长停） | ~35 ms / 每帧 | **0.02 ms** |

## 数据接口

结果对象 `Space Colonization Vine` 是 **GREASEPENCIL** 对象，单个图层 `Vine`，一层绘制
（drawing 在第 1 帧，随播放就地更新）。逐点属性：

| 属性 | 类型 / 域 | 含义 |
|---|---|---|
| `position` | FLOAT_VECTOR / POINT | 世界坐标（已捋顺） |
| `radius` | FLOAT / POINT | 笔划半径（世界单位，已乘面板「倍数」、已平滑 / 收尖） |
| `vertex_color` | FLOAT_COLOR / POINT | 线性 RGBA（根→梢渐变的颜色） |
| `opacity` | FLOAT / POINT | 不透明度（恒 1，留着方便改） |

生长时每帧**整丛重画**（`remove_strokes` + `add_strokes` + 写满四条属性缓冲）：枝条在长，
拓扑每帧都变，维护增量索引不值得。颜色只存一份（属性），材质槽是空的。

**生长停下后不再重画**：`_write` 会拿「节点数 + 粗细 / 梯度 / 倍数 / 配色」跟上一帧比，
一样就直接跳过（见「每帧开销」一节）。所以「播放到底、藤蔓不动了」的时候每帧几乎零开销。

## 与参考实现的差别

参考实现：`ga2/common/space_colonization.py`（Taichi solver）+ `ga2/scripts/blender_space_colonization.py`
（脚本级 Blender 集成）。算法骨架与参数名照搬，差别在工程质量：

| | 参考脚本 | 本扩展 |
|---|---|---|
| 组织方式 | 两个独立脚本 | 扩展包：算法层与 Blender 层分开，可单独测试 |
| 吸收点 | 网格**顶点**（粗网格只有几个点，长不出东西） | 按**面积加权**的表面随机取样，与拓扑无关 |
| 根 | 最低点往下偏一个步长 | 根顶点组（支持多根）；没有就取最低点并贴回表面 |
| 贴表面 | 只做「投影到最近表面点」 | 先把方向压到切平面再投影，退化时有兜底；再剔除退化节点 |
| 半径 | 逐节点加常数的反向遍历近似 | Murray 定律：`最细半径 × 叶尖数^梯度`（按层 `bincount` 累加）+ 平滑 / 收尖 |
| 搜索 | 只有 Taichi kernel | KD 树 / Taichi / NumPy 三档，自动回退并说明原因 |
| 着色 | 几何节点转 Grease Pencil + 颜色渐变（整条一个值） | GP 笔划：**逐点半径 + 逐点颜色**，根→梢的渐变直接落在笔划上 |
| 参数 | 世界单位 | 相对包围盒对角线，换尺度不用重调 |

## 局限与下一步

- **没有烘焙**：动画靠 `frame_change_pre` 实时算，渲染动画时帧要按顺序走（Blender 默认如此），
  **回退会从头重算**（`target < 当前帧` 即重新撒点、从根再长一遍）；
- **笔划是独立折线**：接头靠端点重合 + 圆头笔帽咬合，不是焊死的拓扑；要「一根到底」只能用
  网格或布尔并集，那跟 GP 的线稿感不是一路；
- **贴表面是几何近似**：吸收点用欧氏最近邻 + 表面投影，凹得很深的地方枝条会「抄近路」；
  空间模式更是完全不贴面；
- **结果对象不能当输入**：自动填充会跳过它、面板的指针也会挡掉；真手动塞进去会直接报错 ——
  否则算法会拿自己画出来的笔划当表面再长一遍；
- GP 编辑模式下 handler 会跳过（笔画归编辑器管，重建会把正在画的东西冲掉）；退出编辑后**也不会
  立刻重画** —— 指纹没变，你手改的笔划会一直留着，直到动了生长或外观参数才被覆写；
- 半径按叶尖数算，贴表面模式里叶尖又多又密，主干容易偏粗 —— 用「梯度」往下调。
