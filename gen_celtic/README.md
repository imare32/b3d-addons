# 生成式凯尔特结（Gen Celtic）

任意网格 → 交织绳结（扩展 id `gen_celtic`，Blender 5.2.2 实测）。

每条边的中点当结点，带子沿面一路转过去、碰上扭转的边就跨到对侧，跨过去的地方一上一下
（沿逐角法线抬起 `±抬升`）；最后一轮几何节点把折线扫成圆管。源网格在编辑模式里挪一下，
结**跟着重编**（每次更新先比指纹，没变就直接跳过）。

遍历规则照搬 Adam Newgas 的 celtic-knot（Blender 官方 addons 仓库里那份，Celtic /
Lattice / Weave 三种编织），这里只取 Celtic 一种，所以路径跟那个插件逐元素一致。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Gen Celtic**；
2. 3D 视图侧栏出现 **Celtic** 面板（F3 里也有 `gen_celtic.*` 算子）；
3. 选**源网格**（平面 / 球 / 环 / 猴头都行，只要有面），点「编结」——场景里长出
   `Celtic Knot` 对象：一张只有边没有面的带子网格 + 一个 `Tube` 几何节点修改器；
4. 进编辑模式拖源网格的点：松手前结就跟着变（超过 `LIVE_FACE_LIMIT` 的网格自动停）；
5. 出图点「场景预设」：3/4 视角透视相机、2048×2048、Standard 色彩、世界背景铺项目
   色板的 `BACKGROUND`、一盏三点式简化的太阳主光。

算子：`gen_celtic.generate`（编结 / 更新）、`gen_celtic.delete`、`gen_celtic.setup_scene`、
`gen_celtic.sync_from_object`（从对象上记录的参数回读面板）、`gen_celtic.toggle_source_wire`
（源网格在实体 / 线框之间来回切）。

## 面板参数

三档参数的生效方式不同，面板上也分开摆：

| 分组 | 参数 | 说明 |
|---|---|---|
| 输入 | 源网格 | 只能是网格物体；源不能是结自己。右边那个线框小按钮切「显示为：线框 / 实体」——源网格套在结外面时切成线框才能看穿它 |
| 几何（改完要重编） | 抬升 | 交叉处上下起伏的幅度，单位是**平均边长**（默认 0.35）。0 = 全贴在面上，绳管会互相穿插 |
| 几何节点（就地生效） | 管半径 | 绳管半径，单位是平均边长（默认 0.22：比抬升小，交叉处才分得开） |
| | 圆周分段 | 圆环截面的顶点数 3–32（默认 8 已经够圆，16 更圆但面数翻倍） |
| 外观 | 绳色 | 只改材质基色，几何一点不动（默认赭石 `OCHRE`） |
| 实时 | 实时更新 | 关掉就只在手动点「更新」时重编 |

抬升与管半径都是**比例**（乘源网格的平均边长），所以换尺度、换网格密度都不用重调参数；
面板另给一行折算后的实际值。带子网格里另存了平均边长与参数，换文件 / 换场景后
「回读参数」就能把面板还原成当初的样子。

面板底部的读数：交点 / 带数、带长区间（中位）、耗时、异常收尾数（只在网格有洞或非流形时
才不为 0）。

## 算法（`knot.py`，纯 numpy + 传进来的 BMesh）

遍历规则照搬参考实现（`visit_strands` / `next_face_loop` / `next_edge_loop` 三件套）：

1. **点**：每条边的中点 —— 结的每个转弯都落在这里，一条边一个点，也就是一条边一处交叉；
2. **扭转**：每条边标成同向扭转（`TWIST_CW`）。参考实现是 `random() < twist_prob` 掷骰，
   面板给 100% 时恒等于这个结果，这里直接恒给 —— 去掉随机数，同一张网格每次编出来一样；
3. **走带子**：从一条边的一个方向出发，「沿当前面转到下一条边 → 这条边扭转就跨到对侧的
   面」；跨边时方向要翻面（`next_edge_loop`，同一张面的绕向固定，两侧必然反向），走回
   自己用过的方向就收尾 —— 每个方向只准用一次（`exited` / `entered` 两张表），所以
   每根带子都是闭合的；
4. **上下**：同一条边的两侧必然一正一反（`get_offset` 只看扭转与 `forward`，参考实现
   连正负约定一起照搬），交叉处天然一上一下；抬起来的方向是**逐角法线**（相邻两角法线
   的平均），不是整张面的法线。

* **抬升**：点位置 = 边中点沿逐角法线抬起 `±抬升`；`knot.build` 把「抬升量」当世界单位
  收（比例 × 平均边长在 `weave.apply` 里算好），`0` 则整副结贴在表面上。
* **边界**：边界边（只挂一张面）不参与 —— 带子转到它上面就跳过，`link_loops` 为空的
  方向从来不出发。开放网格的带子因此都收在边界上，球 / 环这类闭合网格上全是闭合带。
* **异常收尾**：面被边界边围死、或网格非流形导致无路可走时，那根带子提前收尾并计一个数
  （参考实现这里直接 `assert` 失败；用户网格什么形状都有，崩掉不如记一笔）。

## 几何后端（`tube.py`）

带子网格只有边没有面，扫管全部交给一个自建的几何节点组（`Celtic Knot Tube`）：

```text
Group Input(Geometry, Radius, Resolution)
  → Mesh to Curve        （相连的边走成一条样条，闭合成环）
  → Curve Spline Type    （折线 → Bezier，自动手柄：阶梯走成圆滑的绳路）
  → Curve Set Handles    （AUTO）
  → Curve to Mesh        （圆环截面挤成管；Fill Caps：断头处封口）
  → Set Shade Smooth
  → Set Material         （绳管材质，见下）
  → Group Output
```

修改器的 `Radius` / `Resolution` 只走节点组接口，因此**改半径、改分段不碰带子网格**
（拖滑块是实时的），`lift` 改的是坐标，必须重编。

**Blender 5.2 上必读的三条**

* **材质必须写在节点组里**。带子网格只有边、没有面，对象材质槽传不到求值后的几何上：
  材质属性挂在没面的网格上是空转，渲染出来是**默认白**。所以在组内挂 `Set Material`，
  并在 `build_object` 里把材质写进去（`tube.set_geometry_material`）。
* `Set Material` 的材质在 5.x 是**输入插口**（`NodeSocketMaterial`），4.x 才是节点属性
  （`node.material`）——两条都写才能跨版本。
* 修改器输入是 `modifier.properties.inputs.<identifier>.value`，identifier 形如
  `Socket_8`，得回 `node_group.interface.items_tree` 按显示名查（`tube.set_mod_input`）；
  老的 `modifier[identifier]` 在 5.x 上直接抛 "id properties not supported"。
  接口插口本身也只认基础类型 + `subtype`（`NodeSocketFloat` 配 `subtype="DISTANCE"` 才是距离）。

## 实时更新（`live.py`）

两段式：`depsgraph_update_post` 处理器**只判断**要不要编（实时开关、源物体是不是网格、
结对象在不在、面数过不过上限），通过就往 timer 里排一次「立刻执行」；真正的编结在
timer 回调里跑，走 `weave.apply`（先比指纹，没变就什么都不做）。

**为什么不在处理器里直接编**（Blender 5.2 实测，代价是崩溃）：撤销 / 重做时 Blender 正在
换掉一批数据块，处理器如果这时候往生成对象里写网格（`write_strands` 开头就是
`mesh.clear_geometry()`），等于把数据从它脚下抽走；编辑模式里拖动点、按 Ctrl+Z 直接把
Blender 干掉了。挪进 timer 之后，写操作一定发生在求值 / 撤销恢复之后。顺带处理器本身也
不再有 O(面数) 的开销 —— 指纹现在只在 timer 里算。

其余细节：

* 对象模式走 numpy 快路径（`knot.mesh_signature`：`foreach_get("co")`），
  编辑模式只能走 BMesh（`knot.signature`）；两条路共用同一套 numpy 运算，
  同一个网格必须算出同一个值；
* **编辑模式里的坐标只有 `bmesh.from_edit_mesh(obj.data)` 拿得到**：`obj.data` 是进编辑
  模式前的旧坐标，求值网格在编辑模式下是空的，拖动中的点只活在编辑 BMesh 里。
  它是借来的（`weave.edit_bmesh`），用完不能 `free()`；
* 指纹没变直接返回，写生成对象引发的那次更新也落在这一条上，不会递归；
* 处理器按「模块名 + 函数名」认自己的处理器（不是函数对象），热重载留下旧实例也不会
  重复挂；「实时更新」重新打开时会立刻补一次（`live.request()`），不用等下次改网格。

`LIVE_FACE_LIMIT`（20000 面）是保护：小网格拖点很舒服，十几万面的网格每次拖点都重编
会把 Blender 拖死，超过就直接跳过（面板亮一条提示），手动点「更新」照常工作。

## 实测

源网格 → 结（`knot.build` 遍历，BMesh 已在内存里；扫管与修改器求值另算）：

| 源网格 | 面 / 边 | 交点 / 带 | 带长 | 遍历 |
|---|---|---|---|---|
| 圆环 32×16 | 512 / 1024 | 2,048 / 32 | 全是 64 | **7.7 ms** |
| 立方体 5×5（每面） | 150 / 300 | 600 / 20 | 全是 30 | **2.3 ms** |
| 网格 129×129 | 16,641 / 33,540 | 66,048 / 129 | 全是 512 | **327 ms** |

三张网格上「异常收尾」都是 0，每条边一个点、每根带子闭合；交点数是 2,048 / 600 /
66,048，正好等于**非边界方向**的个数。参考实现在同一批网格上的路径与本实现逐元素相同
（边序号、方向、坐标全部对到 0 误差）。

129×129 网格上的逐项开销（同上，跑在同一台机）：

| 动作 | 耗时 |
|---|---|
| 处理器本身（只判断 + 排 timer，不再算指纹） | **0.004 ms** |
| timer 里空转一次（对象模式，numpy 指纹） | **0.60 ms** |
| timer 里空转一次（编辑模式，BMesh 指纹） | **7.6 ms** |
| 拖点后重编（knot 遍历占绝大部分） | **327 ms** |

生成的开销几乎全在遍历（`knot.build`）；扫管与修改器求值在 66,048 点的规模上只占小头。
所以「能不能实时」取决于网格多大、而不是结多粗 —— 粗管只多一点点面数。

## 模块

```
knot.py   凯尔特结遍历：扭转标记 / 走带子 / 抬升 / 指纹（只 import numpy，规则照搬 celtic-knot）
tube.py   几何节点后端：节点组 / 修改器输入 / 材质 / 生成对象
weave.py  编结入口：指纹比对 → 遍历 → 写对象（算子与实时处理器走同一条路）
props.py  scene.gen_celtic 参数组 + 对象上回存的设计参数
live.py   实时更新：depsgraph_update_post 只判断，编结推迟到 timer 里跑
ops.py    编结 / 删除 / 回读参数 / 场景预设
ui.py     View3D > 侧栏 > Celtic
palette.py 项目色板副本（改色记得与 _shared/palette.py 同步）
```

`knot.py` 不 import bpy，只是 BMesh 从外面传进来，可以脱离界面单独跑算法：
需要一份带索引的 BMesh（`bm.verts.ensure_lookup_table()`）和抬升量，
`knot.build(bm, lift)` 返回 `Knot(verts, edges, stats)`。

## 局限与下一步

* **没有加捻**：绳管是圆截面的直筒，没有把带子扭一扭、也没有把绳端收尾，断头处只是平封口；
* **只按边中点取点**：结的细节密度就等于源网格的密度，想要更密的编织只能细分源网格
  （代价是遍历变慢），没有做"在面内细分一层"的二次加密；
* **卡在边界上就收尾**：面被边界边围死、或网格非流形（一条边挂三张面）时，那根带子会
  提前收尾并记进「异常收尾」；闭合流形网格上不会出现（实测量到 0）；
* **只做 Celtic 一种编织**：Lattice / Weave 两种没搬（它们只是在扭转标记上加随机）；
* 半径 / 抬升按**平均边长**缩放，网格边长很不均匀时（长条 + 小块混在一起）会偏；
* 实时更新是"整份重编"，没有做增量更新：拖动时每个事件循环最多编一次，源网格十几万面时
  每次仍要几百毫秒，请关掉实时、手动点「更新」。
