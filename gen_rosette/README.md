# 生成式玫瑰线（Gen Rosette）

星形玫瑰线（star rosette）生成器 + Blender 扩展（扩展 id `gen_rosette`，Blender 5.2.2
实测）：给一组花型参数（花瓣数 / 阶数 / 花型）与一个整数种子，得到一张**可复现的蕾丝
编织**——玫瑰线本身被当成一根丝带，在每一个自交处上下交替，压下的那一段切掉缺口、缺口
用一块沿对方边缘裁齐的补片贴平；丝带围出来的区域同时被填成色块。

几何来自 Manim 版 `.ref/rosette.py`（论文式"核 + 镜像 + 旋转"构造），编织与 Grease
Pencil 后端沿用 [`gen_zellij`](../gen_zellij/README.md) 里实测过的做法。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），在偏好设置里启用 **Gen Rosette**；
2. 3D 视图侧栏出现 **Rosette** 面板（F3 里也有 `gen_rosette.*` 算子）；
3. 点「生成」得到一朵玫瑰线；种子旁的按钮抽新种子（只换配色）；
4. 要直接出图点「场景预设」：2048×2048 正交相机、Standard 色彩、GP 抗锯齿 16、
   世界背景铺项目色板的 `BACKGROUND`，取景按生成对象的实际包围盒。

算子：`gen_rosette.generate`、`gen_rosette.random_seed`、`gen_rosette.delete`、
`gen_rosette.sync_from_object`、`gen_rosette.setup_scene`。

## 面板参数

| 分组 | 参数 | 说明 |
|---|---|---|
| 种子 | 种子 / 每次换种子 | 种子**只决定配色**（5 色色板 + 三色色带的次序）；花型由下面三项决定 |
| 花型 | 花瓣数 | `n ≥ 4`（`n = 3` 会让核退化成一条径向线）；上限 32 |
| | 花型 | 十种：`S` + `P / C / D` × `A / O / R`。首位是核的边往外走时的走势（P 平行 / C 汇聚 / D 发散），次位是收尾边的角度（A 锐角 / O 钝角 / R 直角）；`S` 是单段直核 |
| | 阶数 | 越高内部连接越复杂；每个 `(花瓣数, 花型)` 都有可实现上限，越界自动收回并提示 |
| 画布 | 画布 / 边距 | 世界单位；图案等比缩放、居中 |
| 图层 | 色块 / 编织 / 描边 / 辅助线 | 四个 GP 图层的显隐 |
| 编织 | 编织带宽 / 编织色 / 平头交叉 / 间隙 | 带宽是**几何参数**（缺口按它算） |
| | 描边倍数 / 描边色 | 描边半径 = 带宽 × 倍数（默认 1.5，每侧露出半个带宽）；也是几何参数 |
| 工具 | 场景预设 / 回读参数 / 删除 | 相机与色彩设置、从对象读回生成参数 |

**就地生效**（不重建几何）：四个图层的显隐（`layer.hide`）、辅助线宽（改 `radius`）。
**必须重新生成**：种子、花瓣数、花型、阶数、画布、边距，以及编织的带宽 / 描边倍数 /
间隙 / 平头交叉——缺口是几何，宽度或切法一变，缺口就不对了。

「阶数」的可行上限由 `rosette.realizable_level()` 现算，面板直接显示「该组合最高 N 阶」；
滑块越界时不报错，生成时收回到上限并在状态栏注明（「阶数收回到 2（请求 4）」）。

## 图层语义

| 图层 | 内容 | 默认 |
|---|---|---|
| `Faces` | 丝带围出来的封闭区域，按质心半径分三圈取色（颜色来自种子色板） | 显示 |
| `Rosette Case` | 丝带下面那条更粗的描边，露出来的一圈就是蕾丝边（默认墨玄） | 显示 |
| `Rosette` | 编织本体：交叉点上交替压上 / 压下，压下的那一段切掉缺口（默认绢白） | 显示 |
| `Guides` | 构造辅助线：第「阶数」阶的核 + **连续的**玫瑰线中心线（一条轨道一笔画到底） | 隐藏 |

`Rosette Case` 与 `Rosette` 是同一套带子：描边更宽、永远在最下面，所以单开描边只剩一圈
圈深色轮廓。`Guides` 不参与编织：它画的是跳步重排后**合并过**的中心线（
`rosette.merge_adjacent_petals()`），与带子的中心线严格重合，但一条轨道是**连续的一笔**
——条数为 `gcd(n, level + 1)`，默认参数下整朵花就是一笔，点序即绘制顺序。所以它可以
直接拿去驱动生长动画（GP 的 Build 修改器、按长度展开的几何节点都只认一条笔划的点序）；
早期"一片花瓣一条路径"的画法端点各自断开，做不出连贯的生长。想按片核对构造，用
`rosette.get_petals_by_kernel()` 自己拼。

`Faces` 与带子共用同一张平面化边网，边界与带子中心线严格重合——带子两侧各压掉半个带宽，
色块正好顶到带子边缘，不留白缝。

## 算法

### 1. 核 → 花瓣 → 曲线（`rosette.py`）

移植自 Manim 版，去掉 numpy，并用 `math` 直接算；三步：

1. `cal_kernels(n, level, star_type)`：第 0 / 1 阶由三角恒等式给出
   （`xk0 = cosθ + sinθ/tan2θ`、`xk1 = cos2θ + sin2θ/tanθ`，`θ = π/n`），第 2 阶按
   `star_type` 分叉（见下），更高阶把前一阶**旋转 θ** 再与 x 轴求交迭代；
2. `get_petals_by_kernel()`：核沿 x 轴镜像成一片花瓣（镜像时去掉与 x 轴重合的中间点），
   再旋转 `2π/n` 复制 `n` 份；
3. `sort_petals()` + `merge_adjacent_petals()`：按跳步 `level + 1` 重排，把首尾相接的
   花瓣并成连续曲线。

**为什么跳步**：相邻花瓣（差 1 步）只是共用一条半径边界，端点并不重合；差 `level + 1`
步的两片，前一片的末端正好落在后一片的起点上——连起来那条曲线就是玫瑰线本身的走势。
实测（`n = 4..24`、`level = 0..4`、10 种花型共 1668 组）：**合并结果永远是
`gcd(n, level + 1)` 条闭合环**，没有例外（`step` 与 `n` 互质时并成一条）。

### 1.1 十种核（第 2 阶）

第 2 阶的核是折线 `尖端 (x2, y2) → 中点 → 轴上一点`（`y2 = sin3θ`），各花型只差两件事：

| 首位 | 中点所在的高度 `side` | 中点 x |
|---|---|---|
| `C` 汇聚 | `y0 = sinθ`（比尖端低 ⇒ 边朝轴收） | `x2 + (y2 − side) / tanθ` |
| `P` 平行 | `y2`（与尖端同高 ⇒ 这段是水平线） | 沿平行链量：`xk0 + y2/tan2θ + y2/cosθ` |
| `D` 发散 | `2·y2 − y0`（比尖端高 ⇒ 边朝外散） | 同上公式，代入 D 的 `side` |

| 次位 | 收尾边（中点 → 轴上点） |
|---|---|
| `A` 锐角 | 从竖直向外偏 θ：`xk22 + side·tanθ` |
| `O` 钝角 | 从竖直向内偏 2θ：`xk22 − side·tan(2θ)` |
| `R` 直角 | 竖直落下：`xk22`（于是中点处的转角正好 90°） |

`S`（straight）是特例：整条核就是 `(level+1)θ` 处**圆的切线弦**，切点在单位圆上、方向垂直
于半径，`n` 份旋转复制后得到标准 `{n/(level+1)}` 星形多边形（顶点在单位圆上、边互相相切）。
它没有分叉，所以第 0 / 1 阶直接沿用上面那条单段核。

读法校验（`n = 10`，`θ = 18°`）：`PA` 在中点处的转角是 `90° − θ = 72°`（锐角）、`PR` 是
`90°`、`PO` 是 `90° + 2θ = 126°`（钝角）——字母与几何一致；渲染出来 `PR` 是方框、
`PO` 是长尖刺、`CR` 是环状菱形、`CO` 是锯齿星，与论文 Figure 8 的同名图逐一对得上。

四点说明（照论文记法补全时留下的判据与取舍）：

- **`CO`、`DA`、`DO`、`DR`、`S` 是后补的**（原有 `PA/PO/PR/CA/CR` 五个与论文一致）。
  `D` 的 `side` 取 `y0` 关于「过尖端的高度线」的镜像（`2·y2 − y0`），与 `C` 关于 `y2` 对称
  ——这是论文记法下唯一自洽的读法，但原文只给了分类与图，没给 `D` 的闭式，所以这一支属于
  **按记法补出**；两条可以直接改的旋钮见下面两条；
- `D` 的分支反过来朝上，所以「向内 / 向外」的视觉方向与 `P / C` 相反：`DO` 出来是
  **方框套星**、`DA` 是尖刺放射、`DR` 是细密日芒。若你手上的论文里 `D/A` 是方框、`D/O`
  是宽花瓣（即两支的收尾方向要互换），把 `rosette.cal_kernels()` 里 D 分支的
  `tip == "A"` 与 `tip == "O"` 两个算式对调即可（一行，其余不受影响）；
- `D` 的分支高度是「关于尖端镜像」，你要是想改成别的定值（例如 `sin5θ` 或 `1.0`），
  同样只动那一行 `side = 2.0 * y2 - y0`；
- `S` 在第 `level` 阶要求 `(level+1)θ < 90°`（切线还要能与正 x 轴相交）：`n = 10` 到 3 阶、
  `n = 8` 到 2 阶，越界由 `realizable_level()` 报出上限。

三个"数学上不存在"的情况显式报错，而不是产出 `inf` / `nan`：

- `n = 3`：`xk0 = 0`，核退化成径向线段 ⇒ `MIN_PETALS = 4`；
- 某些 `(n, star_type)` 的某一阶让旋转后的核线段与 x 轴**平行**，那一步没有交点
  （例：`n = 4` 的 `PO` 第 2 阶、`n = 6` 的 `PA` 第 4 阶）。`realizable_level()` 从第 0
  阶逐阶往上试，第一次失败就停，返回该组合的最高阶（面板与算子都用它）；
- `S` 的 `cos((level+1)θ) ≤ 0`（上一条）。

### 2. 色块（`faces.py`）

编织关心"带子怎么走"，填充关心"带子围出了哪些区域"，两者共用 `weave.edge_network()`
平面化后的同一张边网。取面是标准半边遍历：

1. 每个结点的出边按极角（逆时针）排序；
2. 沿半边 `u → v` 走，在 `v` 处取 `v → u` 在逆时针序里的**前一条**出边；
3. 面始终在左手边 ⇒ 内部面逆时针（有向面积为正）、最外圈边界顺时针。只保留正面积，
   背景天然被排除，不需要额外判断"哪块是背景"。

实测面数：`level 1` 是 `n + 1` 块上下，`level 2` 是 `2n + 1`（`n = 8 / 10 / 16 / 24` →
`17 / 21 / 33 / 49`），`level 3` 是 `3n + 1`；`level 0` 例外，那里是一整颗实心星（1 块面）。
最大的面只占包围盒面积 8% 左右（面积已经被带子切碎），所以填色是"彩色花窗"而不是色斑。

**配色**：按质心半径分三圈（`FACE_BANDS = 3`），从内到外依次取色板里的三个中间色；这三个
槽的使用次序由种子旋转（`face_slots`），所以换种子会换一套排列。按半径分圈是为了**保住
旋转对称**——逐块随机会把一朵花染成噪点。

### 3. 编织（`weave.py`）

整份实现来自 `gen_zellij/weave.py`，只把 `_edge_network` 公开成 `edge_network`（色块要
复用）。输入从"色块多边形"换成"玫瑰线闭合曲线"，算法不需要改动：曲线自交处本来就是
结点，平面化把它切成标准 X 交叉，配对"最接近直通"的两条边正好是同一条曲线的两段，
于是带子沿玫瑰线自己走。具体七步（平面化 → 顶点配对 → 追带子 → 认交叉 → 定上下 →
切缺口 → 端头平/圆 + 补片）见 `gen_zellij/README.md` §13，这里只记差异：

- **带子末端就是花尖**：花尖的两条边夹角很小（点积 > `PAIR_COS`），配不上对，带子在那里
  收尾、用圆头收边——观感上是丝带在尖端折了一个圆角；
- `level 0` 没有任何交叉（每片花瓣是独立的 V 形），所以**编不起来**，只有直带；
- 描边层整根不切（它永远最下面、深压深看不出来），切口只在本体那一套。

### 4. 装配（`scene.py`）

所有图层共用同一个等比变换（设计坐标 y 向下 → Blender y 向上、居中、留边），所以色块
边界、带子中心线、辅助线严格对齐。编织在**世界坐标**里做（带宽、缺口都是世界单位），
色块在**设计坐标**里切（原点就是花心，质心半径才有意义），再一起变换到画布。

## 已知行为与取舍

- **色块会盖掉一半带宽**：色块边界在带子中心线上，带子两侧各压掉半个带宽。想要更大的
  色块就调小带宽；想要纯线稿就把「色块」关掉。
- **带宽有上限**：`2 × 可见半宽` 要小于相邻两条带子的间距（`level 2`、`n = 16` 的格子宽
  约 `0.35`），否则描边环会真的叠在一起。默认 `0.025 × 1.5 = 0.0375` 离上限还有几倍余量。
- **花尖是圆头**：花尖处配对不上（夹角太小），带子在那里结束；两个圆头端点重合，看起来
  像丝带在尖端折了一下。这不是 bug，`weave.PAIR_COS` 的注释里解释了为什么不能硬配。
- **`level 0` 编不起来**：没有交叉，只有直带 + 一整块实心星。
- **退化配置仍能出图**：个别高阶核（如 `n = 4` 的 `CR` 第 3 阶）会把所有点并成同一点，
  这时平面化得到 0 条边，`scene._weave_shapes` 退回"直接把原始曲线画出来"，不会空手。
- **种子只影响配色**：花型是数学图形，随机化它只会得到"另一朵花"。想要随机花型自己拖
  花瓣数 / 花型 / 阶数——面板不拦，越界会自动收回到可实现的上限。
- **色块按半径分圈**：同一圈里的颜色相同，所以旋转对称被保住；这也是"三色调"的由来。
- **边距只保证曲线在框内**：带子有宽度，`边距 = 0` 时描边会溢出画布半个可见半宽。
- **相机取景按对象包围盒**：带子宽度变了，取景会自动跟着变（「场景预设」重新跑一次）。

## 性能

实测（AMD 平台、系统 CPython 3.13——这些模块不 import bpy，与插件里的解释器同版本、
每次生成取 5 次最小；画布 10 / 边距 0.5 / 带宽 0.025 / 描边 0.0375）：

| 配置 | 形状数（面 / 描边 / 带 / 辅助） | 分层耗时 |
|---|---|---|
| `n = 10` / `level 2` / `PA` | 84（21 / 1 / 60 / 2） | 11 ms |
| `n = 10` / `level 2` / `CO` | 123（21 / 20 / 80 / 2） | 10 ms |
| `n = 16` / `level 2` / `PA` | 163（33 / 16 / 112 / 2） | 15 ms |
| `n = 10` / `level 2` / `DR` | 103（21 / 10 / 70 / 2） | 27 ms |
| `n = 16` / `level 2` / `DR` | 659（177 / 32 / 448 / 2） | 85 ms |
| `n = 24` / `level 4` / `CA` | 435（97 / 24 / 312 / 2） | 24 ms |
| `n = 24` / `level 3` / `DR` | 1329（385 / 48 / 891 / 5） | 213 ms |

「辅助」= 1（核）+ `gcd(n, level + 1)`（连续中心线，见「图层语义」）。`D` / `S` 这两支的
第 2 阶核与轴相交得更散，同一 `n` 下曲线被切得更多，所以形状数与耗时都明显高于 `P / C`
（`DR` 在 `n = 16` 时已经是 659 个形状）。

**带宽是几何**：上表按默认带宽 0.025 测。面板改成 0.05 后，`n = 24` / `level 3` / `DR`
的带子会从 891 掉到 775（带子变粗，被回收的残段变多），其余几档不变。

全参数 sweep（`n = 4..24` × 各花型可实现的每一阶 × 10 种花型 = 1668 组）：无异常、无空结果，
`build_curves()` 整轮 22 ms（平均 13 µs，最慢一组 0.025 ms）；带 `realizable_level()` 试算的
完整一轮 31 ms。走完整算子还要加装配与 GP 写入——最重的 `n = 24` / `level 3` / `DR` 一档是
254 ms + 7 ms，默认配置 `n = 10` / `level 2` / `PA` 是 15 ms + 1 ms（Blender 5.2.2 内实测）。

## 调试建议

- **只看构造**：只开 `Guides`，能看到第 `level` 阶的核与**连续**的中心线——一整朵花通常是
  一笔（`gcd(n, level + 1)` 条），点序就是绘制顺序，可以直接拿去做生长动画；要按片核对
  构造就调 `rosette.get_petals_by_kernel()`；
- **检查闭合性**：`build_curves()` 的返回值应满足"条数 = `gcd(n, level+1)`、全部
  `closed=True`、首点不重复末点"；
- **检查面**：`interior_faces()` 的块数在 `P / C / S` 的低阶下通常等于 `level × n + 1`
  （`level 0` 一律 1 块），且每块有向面积为正（逆时针）；`D` 家族（以及 `CO / PO` 的高阶）
  核会多次穿过轴线，块数明显更多——`n = 16` / `level 2` / `DR` 是 177 而不是 33；
- **检查编织**：`build_weave()` 返回的 `Weave.cuts` 应与"压下"的通过段数一致
  （同一个交叉点被同一条曲线走过两次时会算两刀，所以 `cuts` 可能大于 `crossings`）；
  `pruned` 应为 0（默认参数下没有残段被回收）；
- **检查配准**：`Faces` 的每条边都应落在 `Rosette` 对应带子的中心线上——两者共用同一张
  平面化边网，对不上就说明坐标变换被改坏了；
- **看上下关系**：把 `Rosette Case` 关掉、只留本体，压下的那一段会明显断开；再打开描边，
  断开处应该被补片沿对方边缘贴平。
