# 3D 希尔伯特曲线弹簧质点（Sim Hilbert）

把 3D 希尔伯特曲线当**弹簧质点系统**扔下去：顶点是质点，弹簧铺在格子的 6 / 18 / 26 邻域上，
逐帧显式欧拉推进，实时画成一条 Grease Pencil 笔划（扩展 id `sim_hilbert`，Blender 5.2.2 实测）。

曲线本身就是一根连续的线：顶点编号 = 希尔伯特序号，`0..N-1` 依次相连，所以整个对象只有
**一个笔划**（3 阶 512 点 / 4 阶 4096 点）。落地的瞬间格子上半截还在往下掉、下半截已经被
地面钳住摊开，颜色按逐点速度（或应变）走项目色板 —— 一张会动的墨线图。

计算后端两档，同一套方程：

| 后端 | 依赖 | 3 阶（512 点 / 5068 弹簧） | 4 阶（4096 点 / 4.66 万弹簧） |
|---|---|---|---|
| **Taichi GPU**（默认「自动」时优先） | 需要在 Blender 的 Python 里 `import taichi` | **16 ms/帧**（150 子步） | **16 ms/帧** |
| **NumPy**（回退） | 只要 Blender 自带 numpy | 41 ms/帧 | 290~390 ms/帧 |

两个后端在同一拓扑上跑 1500 子步后位置差 **9.5e-7 m**（f32 舍入），也就是说选哪个只影响
速度、不影响结果。

## 快速开始

1. 仓库已注册为本地扩展仓库（见根目录 `README.md`），启用 **Sim Hilbert**；
2. 3D 视图侧栏出现 **Hilbert** 面板（F3 里也有 `sim_hilbert.*` 算子）；
3. 点「构建」——建曲线对象、求解器、地面纸面，画面停在悬空的初始格子；
4. 播放（或点「+1 帧」）：格子落下 → 撞地 → 摊成一堆，颜色由石青烧成朱砂再冷下去；
5. 出图点「场景预设」：1600×1000 正交相机（方位 38° / 俯角 20°）、Standard 色彩、
   世界背景铺项目色板的 `BACKGROUND`、地面铺一片 `SILK` 纸面。

算子：`sim_hilbert.build`、`sim_hilbert.reset`（回初始格子，不重建拓扑）、
`sim_hilbert.step`（时间轴 +1 帧）、`sim_hilbert.setup_scene`、
`sim_hilbert.fix_viewport`、`sim_hilbert.delete`。

颜色只写在 GP 的 `vertex_color` 属性里，而 Solid 视图默认的「着色颜色 = Material」读的是
材质单色 —— 这时线是**全黑**的，看不出速度色。所以「构建」「场景预设」会顺手把 Solid 视图
切成 **Attribute**；播放中要是又切回 Material，面板会亮一条红色提示，点
`sim_hilbert.fix_viewport` 即可；材质预览 / 渲染模式本来就看得到颜色，不动它们。

## 面板参数

三档参数的生效方式不同，面板上也分开摆：

| 分组 | 参数 | 说明 |
|---|---|---|
| 曲线 / 精度 | 阶数 | 1 = 2³ = 8 点 / 2 = 64 点 / 3 = 512 点（缺省）/ 4 = 4096 点。阶数变高时**曲线的实际跨度不变**，只是格子变密 |
| | 尺寸 | 包围盒边长（不是格距）：格距 = 尺寸 / (2^阶数 − 1)。缺省 4 m、3 阶 → 格距 0.57 m |
| | 落差 | 初始整体抬高的 z 偏移：格子底面在地面上方 `落差 − 尺寸/2` 处。缺省 3 m → 离地 1 m，约 15 帧落地 |
| | 邻域 | 6 / 18 / 26：弹簧怎么连，档位越高越硬。3 阶对应 1344 / 3696 / 5068 根 |
| | 后端 / 子步 | 「自动」= 有 taichi 就用 GPU，取不到回退 NumPy；子步是**唯一的播放速度旋钮**（物理时间/帧 = dt × 子步） |
| 物理 | 重力 | 9.81 / 1.62 / 0：只影响下落与冲击力度，不改弹簧 |
| | 刚度 / 阻尼 | 刚度 k 越小落地坍缩越明显（缺省 200）；阻尼 c 越大能量耗散越快 |
| | 质量 / 时间步 dt | 固有频率 ω ≈ √(k/m)；显式欧拉对 dt 敏感，画面开始抖/炸之前先减 dt |
| | 地面高度 / 弹性 / 摩擦 | 碰撞平面：法向速度乘 `−弹性`、切向速度乘 `1−摩擦`。勾「地面纸面」才画那块板 |
| 外观 | 配色 | 速度（石青 → 赭石 → 朱砂）/ 应变（冲击波在格子里走）/ 单色 |
| | 速度满标 / 应变满标 | 色带的满标，不做逐帧自归一化 —— 自归一化会让每帧整体变色，看不出能量在耗散 |
| | 线宽 | 笔划半径（世界单位，实际线宽是它的 2 倍） |

- **物理参数**：下一帧就生效，不重建；
- **外观参数**：当场重刷当前帧（不推进物理）；
- **曲线 / 后端**：进签名，下一帧由 handler 自动重建（也可以手动点「重建」）。

读数：当前帧、速度峰值、应变均值 / 峰值、后端名与回退原因、每帧耗时（指数滑动平均）、
上次构建耗时。

## 物理模型

顶点是质点、弹簧是阻尼弹簧、地面是碰撞平面（与参考实现 `ga2/common/mass_spring.py`
逐式一致）：

```
F_i = m·g + Σ_j [ −k·(|p_i − p_j| − L_ij) − c·(v_i − v_j)·n̂_ij ] · n̂_ij
v_i += (F_i / m)·dt
p_i += v_i·dt
p_i.z < z_ground  →  p_i.z = z_ground, v_i.z *= −e, v_i.xy *= (1 − μ)
```

- **弹簧网络是格子的，不是曲线的**：6 邻域只连轴向（最软，像一团绳结）、18 邻域再加 12 条
  面对角、26 邻域连上 8 条体对角（最硬，落下去像一块软胶体）。曲线的走向（顶点 0→N−1）
  只决定笔划怎么连，不参与弹簧拓扑；
- **弹簧原长 = 初始点距**，所以斜向弹簧天生比轴向长（26 邻域里体对角是轴向的 √3 倍）；
- **显式欧拉 + 半隐式积分**：每子步「算力 → 更新速度 → 更新位置 → 地面钳位」。地面钳位写在
  积分之后（与参考实现同顺序），穿地面的那一小段会被"推"回平面上，表现为一点软接触；
- **刚度与观感**：缺省 k=200 时整块格子落地后竖向从 4 m 压到约 2.1 m、横向从 4 m 摊到
  约 4.4 m（应变均值 3%）；k=100 会摊成 1 m 厚的一滩，k=3000 以上基本就是一块硬胶体在弹。
  沉降量 ∝ 1/k，所以调刚度就是在调"这堆格子有多软"；
- **稳定性**：ω ≈ √(k·n/m)（26 邻域 n≈26），缺省 k=200、m=1 时 ω≈72，显式欧拉的临界步长约
  2/ω ≈ 0.028 s —— 缺省 dt=2e-4 有 140 倍余量。网格爆炸的样子是"线瞬间糊成一团噪点"，
  这时先减 dt（不是减刚度）。

缺省一帧走 150 子步 × 2e-4 s = **0.03 s 物理时间**，24 fps 下就是 0.72 倍实时（慢放）。
想快点播就加「子步」，想更稳就减「dt」——两者都只影响这一帧走多少，不改物理。

## 数据接口

GP 对象（`Sim Hilbert`）的 drawing 上的属性，几何节点 / 着色器可以直接按名字取：

| 属性 | 类型 / 域 | 含义 |
|---|---|---|
| `position` | FLOAT_VECTOR / POINT | 世界坐标（顶点编号 = 希尔伯特序号） |
| `radius` | FLOAT / POINT | 笔划半径 |
| `vertex_color` | FLOAT_COLOR / POINT | 线性 RGBA（Solid 的 Attribute 着色与渲染共用） |
| `speed` | FLOAT / POINT | 逐点速度大小 [m/s] |
| `strain` | FLOAT / POINT | 逐点平均应变 `|L − L0| / L0`（按参与的弹簧数取平均） |

`speed` / `strain` 就是面板读数与配色用的那两个数组，额外存一份是为了让几何节点能直接用
（例如按 speed 挤出厚度、按 strain 上置换）。颜色不存第二份：配色直接写进 `vertex_color`。

## 模块

```
curve.py        希尔伯特映射 / 弹簧网络拓扑                    （不 import bpy）
solver.py       弹簧质点求解器（纯 NumPy）+ 后端工厂 create()  （不 import bpy）
taichi_solver.py 同一套方程的 Taichi GPU kernel（可选后端）
colour.py       速度 / 应变 → 逐点颜色（只用项目色板）         （不 import bpy）
gp.py           Grease Pencil v3 后端：图层 / 逐点位置 / 颜色 / 标量 / 逐帧重刷
sim.py          frame_change_pre handler：推进物理 → 写笔划
scene.py        世界底色 / 斜俯视正交相机 / 地面纸面 / 渲染设置
viewport.py     Solid 视图的着色颜色检查（Material 着色下线是全黑的）
props.py        scene.sim_hilbert 参数组
ops.py          构建、重置、步进、场景预设、视口修正、删除
ui.py           View3D > 侧栏 > Hilbert
```

`curve.py` / `solver.py` / `colour.py` 可以脱离 Blender 单独跑（系统 Python + numpy）：

```powershell
python -c "from sim_hilbert import curve, solver; n = curve.network(3); s = solver.NumPyMassSpring(n.positions, n.pairs, n.rest_lengths); s.step(1500); print(s.positions()[:,2].min())"
```

希尔伯特映射自带校验：相邻序号的格子**曼哈顿距离恒为 1**（1~4 阶、全部 8^order 个序号都验过），
所以曲线的连线不会斜穿格子。

## 取景

正交相机的 `ortho_scale` 作用在**长边**上：1600×1000 的竖向视野只有 `span / 1.6`。再加上
斜视时格子的进深会抬高它在屏幕上的竖直尺寸（`进深 × sin(俯角)`），所以取景按

```
screen = (落差 + 尺寸/2)·cos(俯角) + 1.4·尺寸·sin(俯角)
span   = max(1.8·尺寸, 1.08·screen·宽高比)
```

算 —— 只按竖向高度算的话，格子后面那半个会被切出画面。地面纸面开到 8 倍正交尺度：
正交视角下纸面一旦露出边，构图就毁了。

## 与参考实现的差别

参考实现是 `ga2/common/hilbert_curve.py` + `ga2/scripts/blender_hilbert_mass_spring.py`
（独立脚本：Taichi 求解器 + 网格 + `velocity_mag` 顶点属性）。物理与拓扑照搬，差别在工程结构：

| | 参考脚本 | 本扩展 |
|---|---|---|
| 组织方式 | 两个脚本（算法 / Blender 集成） | 扩展包：算法层与 Blender 层分开，可单独测试 |
| 后端 | 只有 Taichi | Taichi GPU 优先，**可回退 NumPy**（同方程，实测差 9.5e-7） |
| 结果落到场景 | 只有边的网格 + `velocity_mag` 属性 | GP 笔划（3D 深度遮挡）+ `speed` / `strain` 标量 + `vertex_color` |
| 视觉 | 只有网格 | 逐点颜色按速度 / 应变走色板，落地冲击一眼看得出来 |
| 弹簧刚度 | 10000（几乎不许变形） | 200（落地明显坍缩；面板可调 1~5000） |
| 场景 | 只改世界底色 | 世界底色 + 斜俯视正交相机 + 地面纸面 + 渲染预设 |

> 参考实现里刚度 10000 的格子落地只会弹、几乎不变形（应变 < 1%）。这个扩展到场景里要的是
> "曲线被压成一堆"，所以缺省刚度降到 200：同样的结构落地后竖向压掉一半、横向摊开 10%。

## 局限与下一步

- **没有烘焙**：动画靠 `frame_change_pre` 实时算，渲染动画时帧要按顺序走（Blender 默认如此），
  **回退会重置**整个模拟（`target < 当前帧` 就从初始格子重算）。跳到很远的帧会很慢 ——
  NumPy 后端 4 阶上每帧近 0.3 s，跳 100 帧就是一分钟；
- Taichi 后端每帧的耗时几乎与规模无关（3 阶和 4 阶都是 16 ms/帧）：瓶颈是**每子步一次
  kernel 调用**（150 子步 × ~65 µs），不是弹簧的数量。要再快就得把多子步塞进一个 kernel，
  那需要 kernel 内部的屏障（Taichi 没有暴露），暂不做；
- 只有**地面**碰撞，没有顶点之间的自碰撞：格子自己压自己的时候会穿过去，看起来还是"一团线"，
  这也正是线稿的好处（穿模不显眼）；
- 弹簧网络是线性的（胡克 + 轴向阻尼），没有弯曲约束和体积约束，所以 6 邻域档位会很"软塌"
  （长条会被拉成折线），26 邻域档位才是缺省的"胶体"观感；
- GP 笔划的深度遮挡是 3D 逐像素的，曲线自交处按真实深度切——靠前的一段会切掉靠后的一段，
  切口是笔划的圆头轮廓。要"实"的管状轮廓得把 GP 转成 mesh 再补几何。
